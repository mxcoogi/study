

Redis는 단순한 Key-Value 저장소지만 Value에 여러 종류의 자료구조를 사용할 수 있다.

```text
Key → Value

Value:
├── String
├── List
├── Hash
├── Set
├── Sorted Set
├── Bitmap
├── HyperLogLog
├── Geospatial
└── Stream
```

---

## 1. String

Redis에서 가장 기본적인 자료구조이다.

하나의 Key에 문자열, 숫자, 바이너리 데이터를 저장할 수 있다.

```text
Key            Value
──────────────────────
name           "Kim"
age            "25"
login_count    "100"
```

### 기본 명령어

```redis
SET name "Kim"
GET name

SET age 25
GET age

DEL name
```

### 숫자 연산

String에 숫자를 저장하면 증가/감소 연산을 수행할 수 있다.

```redis
SET count 10

INCR count
INCRBY count 10

DECR count
DECRBY count 5
```

### 여러 값 처리

```redis
MSET name "Kim" age 25
MGET name age
```

### 만료 시간

```redis
SET auth:code "123456" EX 300
```

300초 후 자동으로 삭제된다.

### 주요 사용 사례

- 캐시
    
- 세션
    
- 인증 코드
    
- JWT/토큰
    
- 카운터
    
- 간단한 상태값
    

---

# 2. List

문자열 값을 **순서대로 저장하는 자료구조**이다.

양쪽 끝에서 데이터를 추가하거나 제거할 수 있다.

```text
LEFT                         RIGHT
 ↓                             ↓
[A] ←→ [B] ←→ [C] ←→ [D]
```

### 데이터 추가

```redis
LPUSH queue A
LPUSH queue B

RPUSH queue C
```

### 데이터 조회

```redis
LRANGE queue 0 -1
```

### 데이터 제거

```redis
LPOP queue
RPOP queue
```

### 사용 예

Queue:

```redis
RPUSH queue job1
RPUSH queue job2

LPOP queue
```

Stack:

```redis
LPUSH stack A
LPUSH stack B

LPOP stack
```

### 주요 사용 사례

- Queue
    
- Stack
    
- 작업 목록
    
- 최근 데이터 목록
    

---

# 3. Hash

하나의 Key 안에 여러 **Field-Value**를 저장한다.

객체를 표현할 때 유용하다.

```text
user:1
 │
 ├── name  → Kim
 ├── age   → 25
 └── email → kim@example.com
```

### 저장

```redis
HSET user:1 name "Kim"
HSET user:1 age 25
HSET user:1 email "kim@example.com"
```

한 번에 저장:

```redis
HSET user:1 name "Kim" age 25 email "kim@example.com"
```

### 조회

```redis
HGET user:1 name
HGETALL user:1
HMGET user:1 name age
```

### 삭제

```redis
HDEL user:1 email
```

### 주요 사용 사례

- 사용자 정보
    
- 상품 정보
    
- 객체 캐싱
    
- 설정값
    

---

# 4. Set

**중복을 허용하지 않는 순서 없는 집합**이다.

```text
friends:1

{ A, B, C }
```

같은 데이터를 여러 번 추가해도 하나만 존재한다.

```redis
SADD tags java
SADD tags redis
SADD tags java
```

결과:

```text
java
redis
```

### 조회

```redis
SMEMBERS tags
```

### 존재 확인

```redis
SISMEMBER tags java
```

### 삭제

```redis
SREM tags java
```

### 집합 연산

교집합:

```redis
SINTER user:1:friends user:2:friends
```

합집합:

```redis
SUNION user:1:friends user:2:friends
```

차집합:

```redis
SDIFF user:1:friends user:2:friends
```

### 주요 사용 사례

- 태그
    
- 중복 제거
    
- 친구 목록
    
- 권한 목록
    
- 공통 관심사 계산
    

---

# 5. Sorted Set

Set처럼 **중복된 Member를 허용하지 않지만**, 각 Member에 `Score`를 부여한다.

Score를 기준으로 정렬된다.

```text
ranking

Score     Member
────────────────
1000      Kim
850       Lee
700       Park
```

### 저장

```redis
ZADD ranking 1000 Kim
ZADD ranking 850 Lee
ZADD ranking 700 Park
```

### 조회

```redis
ZRANGE ranking 0 -1
```

높은 점수부터:

```redis
ZREVRANGE ranking 0 -1 WITHSCORES
```

### 순위 조회

```redis
ZREVRANK ranking Kim
```

### Score 증가

```redis
ZINCRBY ranking 100 Kim
```

### 주요 사용 사례

- 게임 랭킹
    
- 인기 게시물
    
- 점수 기반 정렬
    
- 우선순위 데이터
    
- 시간 기반 정렬
    

---

# 6. Bitmap

Bitmap은 별도의 독립 자료형이라기보다는 **String의 비트를 조작하는 기능**이다.

각 bit를 `0` 또는 `1`로 표현한다.

```text
사용자 ID

0 1 2 3 4 5 6
─────────────
1 0 1 1 0 0 1
```

### Bit 설정

```redis
SETBIT login:2026-09-13 100 1
```

사용자 `100`이 로그인했다는 식으로 표현할 수 있다.

### Bit 조회

```redis
GETBIT login:2026-09-13 100
```

### 1인 Bit 개수

```redis
BITCOUNT login:2026-09-13
```

### 주요 사용 사례

- 출석 체크
    
- 로그인 여부
    
- 사용자 활성 상태
    
- Boolean 상태 대량 저장
    

대량의 `true/false` 데이터를 매우 적은 메모리로 관리할 수 있다는 장점이 있다.

# 7. HyperLogLog

**고유한 데이터의 개수(Cardinality)를 추정**하기 위한 확률적 자료구조이다.

예를 들어 웹사이트에 방문한 고유 사용자 수를 계산할 때 사용할 수 있다.

```text
접속 기록

User1
User2
User1
User3
User2

실제 고유 사용자 = 3
```

### 데이터 추가

```redis
PFADD visitors user1
PFADD visitors user2
PFADD visitors user1
PFADD visitors user3
```

### 개수 조회

```redis
PFCOUNT visitors
```

### 특징

정확한 값을 저장하는 대신 **매우 적은 메모리를 사용하면서 근사값을 계산**한다.

따라서 정확한 값이 반드시 필요한 상황에는 적합하지 않다.

### 주요 사용 사례

- 일일 방문자 수
    
- Unique Visitor
    
- 고유 IP 수
    
- 대규모 데이터의 Cardinality 추정

# 8. Geospatial

위도와 경도 정보를 저장하고 **위치 기반 검색**을 수행할 수 있다.

내부적으로는 Sorted Set을 기반으로 구현되어 있다.

### 위치 저장

```redis
GEOADD stores 127.0276 37.4979 gangnam
GEOADD stores 126.9780 37.5665 seoul
```

형식:

```text
GEOADD key longitude latitude member
```

주의할 점은 **경도(longitude)가 먼저**라는 것이다.

### 거리 계산

```redis
GEODIST stores gangnam seoul km
```

### 특정 위치 주변 검색

```redis
GEOSEARCH stores \
    FROMLONLAT 127.0276 37.4979 \
    BYRADIUS 5 km
```

### 주요 사용 사례

- 주변 매장 검색
    
- 주변 사용자 검색
    
- 배달 서비스
    
- 위치 기반 서비스

# 9. Stream

Redis에서 **이벤트/메시지 스트림을 저장하고 처리하기 위한 자료구조**이다.

단순 Pub/Sub과 다르게 메시지를 Redis에 저장할 수 있다.

```text
Producer
   │
   │ XADD
   ▼
┌───────────────┐
│ Redis Stream  │
│───────────────│
│ Event 1       │
│ Event 2       │
│ Event 3       │
└───────────────┘
   │
   │ XREAD
   ▼
Consumer
```

### 메시지 추가

```redis
XADD orders * userId 100 productId 200
```

`*`를 사용하면 Redis가 Stream ID를 생성한다.

예:

```text
1694598123456-0
```

### 메시지 조회

```redis
XRANGE orders - +
```

### 메시지 읽기

```redis
XREAD STREAMS orders 0
```

### Consumer Group

여러 Consumer가 메시지를 나누어 처리할 수도 있다.

```text
                Redis Stream
                     │
              Consumer Group
               /           \
              ↓             ↓
        Consumer A     Consumer B
```

관련 명령어:

```redis
XGROUP
XREADGROUP
XACK
```

### 주요 사용 사례

- 이벤트 처리
    
- 메시지 Queue
    
- 비동기 작업
    
- 로그 수집
    
- 이벤트 기반 시스템

# 자료구조 비교

|자료구조|특징|대표 사용 사례|
|---|---|---|
|String|단일 값|Cache, Token, Counter|
|List|순서가 있는 목록|Queue, Stack|
|Hash|Field-Value|객체, 사용자 정보|
|Set|중복 없는 집합|Tag, 친구, 중복 제거|
|Sorted Set|Score 기반 정렬|Ranking|
|Bitmap|Bit 단위 상태 저장|출석, 활성 사용자|
|HyperLogLog|고유 개수 추정|UV, 방문자 수|
|Geospatial|위치 정보|주변 검색|
|Stream|메시지/이벤트 저장|Queue, Event 처리|
