## 개요

**관계(Relationship)**는 엔터티의 인스턴스 사이의 **논리적인 연관성**이다.

존재의 형태나 행위로서 서로에게 영향을 주는 연결 상태를 의미하며, 실제 DB에서는 보통 **FK**와 **조인**으로 구현된다.

---

## 관계의 분류

| 분류 | 설명 | 예 |
| --- | --- | --- |
| **존재에 의한 관계** | 한쪽이 존재하는 것 자체로 관계가 성립 | 사원 — **소속** — 부서 |
| **행위에 의한 관계** | 어떤 행위(이벤트)가 일어나서 관계가 성립 | 고객 — **주문** — 주문 |

- ERD에서는 두 관계를 **구분하지 않고** 같은 선으로 표현한다.
- UML 클래스 다이어그램에서는 **연관 관계(실선)**와 **의존 관계(점선)**로 구분한다.

---

## 관계의 표기법

| 표기 요소 | 설명 |
| --- | --- |
| **관계명 (Membership)** | 관계의 이름. 양쪽 엔터티 관점에서 각각 기술 |
| **관계 차수 (Cardinality)** | 한 엔터티의 인스턴스가 상대 엔터티의 몇 개 인스턴스와 관계하는지 (1:1, 1:M, M:N) |
| **관계 선택사양 (Optionality)** | 관계가 **필수(Mandatory)**인지 **선택(Optional)**인지 |

```text
IE 표기법 (까마귀발)

부서 ──┼────────○<── 사원

  ┼  : 1 (필수)
  ○  : 선택 (0 가능)
  <  : 여러 개 (Many)

→ 한 부서에는 사원이 0명 이상 있을 수 있고,
  한 사원은 반드시 하나의 부서에 속한다.
```

### 관계명 규칙

- 애매한 동사는 피한다 (`관련이 있다`, `관계된다` X).
- **현재형**으로 표현한다 (`수강을 신청했다` X → `수강 신청한다` O).

---

## 관계 차수 (Cardinality)

| 차수 | 예 |
| --- | --- |
| **1 : 1** | 사원 — 사원상세 |
| **1 : M** | 부서 — 사원 |
| **M : N** | 학생 — 과목 → 실제 구현 시 **교차(관계) 엔터티**로 풀어 1:M, M:1로 만든다 |

```text
학생 ─< 수강신청 >─ 과목
```

---

## 관계 정의 시 체크사항

- 두 엔터티 사이에 관심 있는 **연관 규칙**이 존재하는가?
- 두 엔터티 사이에 **정보의 조합**이 발생하는가?
- 업무 기술서, 장표에 관계 연결에 대한 **규칙이 서술**되어 있는가?
- 업무 기술서, 장표에 관계 연결을 가능하게 하는 **동사(Verb)**가 있는가?

---

## 시험 포인트

- 관계 분류: **존재**에 의한 관계 / **행위**에 의한 관계 (ERD는 구분 X)
- 표기 3요소: **관계명, 관계 차수, 관계 선택사양**
- 관계명은 **현재형**, 애매한 동사 금지
- M:N은 교차 엔터티로 해소
- 식별 관계 / 비식별 관계는 → [[5. 식별자]]
