## 개요

**정규화(Normalization)**는 데이터의 **중복을 제거**하고 **이상 현상(Anomaly)**을 없애기 위해 하나의 엔터티를 여러 엔터티로 **분해**하는 과정이다.

정규화는 **논리적 모델링** 단계에서 수행하며, **함수적 종속성**을 근거로 단계적으로 진행한다.

---

## 이상 현상 (Anomaly)

정규화가 안 된 테이블에서는 데이터를 넣고, 바꾸고, 지울 때 문제가 생긴다.

```text
수강 테이블
학번 | 이름  | 과목코드 | 과목명    | 성적
1001 | 김철수 | C01     | DB       | A
1001 | 김철수 | C02     | 자료구조  | B
1002 | 이영희 | C01     | DB       | B
```

| 이상 | 설명 | 위 예시에서 |
| --- | --- | --- |
| **삽입 이상** | 불필요한 데이터까지 함께 넣어야 삽입 가능 | 수강생이 없으면 새 과목을 등록할 수 없다 |
| **갱신 이상** | 중복 데이터 중 일부만 수정되어 불일치 발생 | 김철수 이름을 한 행만 바꾸면 모순 |
| **삭제 이상** | 삭제 시 필요한 정보까지 함께 삭제 | 김철수의 자료구조 수강 행을 지우면 C02 과목 정보도 함께 사라진다 |

## 함수적 종속성 (Functional Dependency)

`X → Y` : X 값이 정해지면 Y 값이 **하나로** 결정된다. (X = 결정자, Y = 종속자)

```text
학번 → 이름          (학번을 알면 이름이 정해진다)
(학번, 과목코드) → 성적
과목코드 → 과목명
```

- **완전 함수 종속**: Y가 X **전체**에 종속
- **부분 함수 종속**: Y가 복합키 X의 **일부**에만 종속
- **이행 함수 종속**: X → Y, Y → Z 이면 X → Z

## 정규형 단계

| 정규형 | 조건 | 제거 대상 |
| --- | --- | --- |
| **1NF** | 모든 속성이 **원자값**을 가진다 | 반복 그룹, 다중값 속성 |
| **2NF** | 1NF + 모든 일반 속성이 PK에 **완전 함수 종속** | **부분 함수 종속** |
| **3NF** | 2NF + 일반 속성 간 종속이 없다 | **이행 함수 종속** |
| **BCNF** | 3NF + **모든 결정자가 후보키** | 후보키가 아닌 결정자 |
| 4NF | BCNF + 다치 종속 제거 | 다치 종속 |
| 5NF | 4NF + 조인 종속 제거 | 조인 종속 |

> 외우기: **도부이결다조** (도메인 원자값 → 부분 → 이행 → 결정자 → 다치 → 조인)

### 1NF 예시

```text
[위반] 고객번호 | 전화번호
       C01     | 010-1111, 010-2222     ← 한 칸에 값 2개

[1NF] 고객번호 | 전화번호
      C01     | 010-1111
      C01     | 010-2222
```

### 2NF 예시 (부분 함수 종속 제거)

```text
수강(학번, 과목코드, 이름, 성적)    PK = (학번, 과목코드)
  학번 → 이름                      ← PK 일부에만 종속 (부분 종속)

→ 학생(학번, 이름)
  수강(학번, 과목코드, 성적)
```

### 3NF 예시 (이행 함수 종속 제거)

```text
사원(사번, 부서코드, 부서명)
  사번 → 부서코드 → 부서명          ← 이행 종속

→ 사원(사번, 부서코드)
  부서(부서코드, 부서명)
```

### BCNF 예시

```text
수강(학번, 과목, 교수)    PK = (학번, 과목)
  교수 → 과목              ← 결정자 '교수'가 후보키가 아님

→ 수강(학번, 교수)
  담당(교수, 과목)
```

## 정규화와 성능

| 작업 | 영향 |
| --- | --- |
| 입력 / 수정 / 삭제 | 중복이 줄어 **성능 향상** |
| 조회 | 테이블이 나뉘어 **조인이 늘어나 성능 저하될 수 있음** |

- 조회 성능이 크게 떨어지면 의도적으로 중복을 허용하는 **반정규화**를 고려한다. 단, 정규화를 먼저 수행한 뒤 검토한다.

---

## 시험 포인트

- 정규화 목적: **중복 제거, 이상 현상(삽입·갱신·삭제) 제거**
- 1NF 원자값 / 2NF **부분** 종속 제거 / 3NF **이행** 종속 제거 / BCNF 결정자 = 후보키
- 정규화 → 입력·수정·삭제 성능 ↑, 조회는 조인 증가로 ↓ 가능 (항상 조회가 느려지는 것은 아님)
- 정규화는 **논리적 모델링** 단계
