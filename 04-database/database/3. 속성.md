## 개요

**속성(Attribute)**은 업무에서 필요로 하는, **의미상 더 이상 분리되지 않는 최소의 데이터 단위**이다.

엔터티를 설명하고 인스턴스를 구성하는 요소이며, 실제 DB에서는 테이블의 **컬럼**이 된다.

---

## 엔터티 · 인스턴스 · 속성 · 속성값의 관계

```text
한 엔터티   → 2개 이상의 인스턴스
한 인스턴스 → 2개 이상의 속성
한 속성     → 1개의 속성값
```

- 하나의 속성은 **하나의 값만** 가져야 한다. 여러 값을 가지면 별도 엔터티로 분리한다 (→ [[6. 정규화]] 1정규형).

---

## 속성의 분류

### 1. 특성에 따른 분류

| 분류 | 설명 | 예 |
| --- | --- | --- |
| **기본 속성** | 업무 분석을 통해 바로 정의한 속성 | 이름, 주소, 가격 |
| **설계 속성** | 업무상 필요한 데이터는 아니지만 모델링 과정에서 새로 만들거나 변형한 속성 | 코드, 일련번호 |
| **파생 속성** | 다른 속성으로부터 **계산·변형**되어 생성된 속성 | 합계, 평균, 총주문금액 |

> 파생 속성은 원본 데이터가 바뀔 때 함께 바뀌어야 하므로 **데이터 정합성**을 유지하기 어렵다. 가급적 적게 정의한다.

### 2. 엔터티 구성 방식에 따른 분류

| 분류 | 설명 |
| --- | --- |
| **PK (Primary Key) 속성** | 인스턴스를 식별할 수 있는 속성 |
| **FK (Foreign Key) 속성** | 다른 엔터티와의 관계에서 포함된 속성 |
| **일반 속성** | PK, FK에 포함되지 않은 속성 |

### 3. 분해 여부에 따른 분류

| 분류 | 설명 | 예 |
| --- | --- | --- |
| **단일 속성** | 하나의 의미로 구성 | 이름 |
| **복합 속성** | 여러 의미로 분해 가능 | 주소 (시, 구, 동) |
| **다중값 속성** | 여러 개의 값을 가질 수 있음 → **별도 엔터티로 분리** | 전화번호 여러 개 |

## 도메인 (Domain)

각 속성이 가질 수 있는 **값의 범위**를 도메인이라고 한다.

- 데이터 타입, 크기, 제약조건(NOT NULL, CHECK 등)을 포함한다.

```text
속성 : 학점
도메인 : 0.0 ~ 4.5 사이의 소수 (NUMBER(2,1))
```

---

## 속성 명명 규칙

- 해당 업무에서 사용하는 이름을 부여한다.
- **서술식 이름은 사용하지 않는다.**
- 약어 사용은 가급적 제한한다.
- 전체 데이터 모델에서 **유일**하게 만드는 것이 좋다.

---

## 시험 포인트

- 속성 = 의미상 **더 이상 분리되지 않는 최소 단위**
- 한 속성은 **한 개의 속성값**만 가진다
- 기본 / **설계**(코드, 일련번호) / **파생**(계산값, 정합성 주의)
- 다중값 속성은 별도 엔터티로 분리
- 도메인 = 속성이 가질 수 있는 **값의 범위**
