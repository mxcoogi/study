## 개요

**NULL**은 **아직 정해지지 않은 값, 알 수 없는 값**을 의미한다.

**0이나 공백 문자('')와는 다르다.** 값이 "없음"을 나타내는 특별한 표시이다.

```text
보너스 = 0      → 보너스가 0원으로 정해짐
보너스 = NULL   → 보너스가 얼마인지 아직 모름
```

---

## NULL의 연산

| 연산 | 결과 |
| --- | --- |
| NULL + 10, NULL * 0 | **NULL** (산술 연산 결과는 NULL) |
| NULL = NULL, NULL > 1 | **UNKNOWN** (비교 연산 결과는 참도 거짓도 아님) |
| WHERE 조건이 UNKNOWN | 해당 행은 **선택되지 않음** |

```sql
-- 잘못된 비교 (아무 행도 나오지 않음)
SELECT * FROM 사원 WHERE 보너스 = NULL;

-- 올바른 비교
SELECT * FROM 사원 WHERE 보너스 IS NULL;
SELECT * FROM 사원 WHERE 보너스 IS NOT NULL;
```

## 집계 함수와 NULL

집계 함수는 **NULL을 제외**하고 계산한다. 단, `COUNT(*)`는 NULL이 포함된 행도 센다.

```text
사원 | 보너스
A    | 100
B    | NULL
C    | 200
```

| 함수 | 결과 | 이유 |
| --- | --- | --- |
| `COUNT(*)` | **3** | 행 수 |
| `COUNT(보너스)` | **2** | NULL 제외 |
| `SUM(보너스)` | **300** | NULL 제외 |
| `AVG(보너스)` | **150** | 300 / **2** |
| `SUM(보너스) / COUNT(*)` | **100** | 300 / **3** |
| `AVG(NVL(보너스, 0))` | **100** | NULL을 0으로 바꾼 뒤 300 / 3 |

> AVG에서 NULL을 0으로 볼지 제외할지에 따라 결과가 달라진다. 시험 단골 문제.

---

## NULL 관련 함수

| 함수 | 설명 |
| --- | --- |
| `NVL(a, b)` (Oracle) / `ISNULL(a, b)` (SQL Server) | a가 NULL이면 b |
| `NULLIF(a, b)` | a = b 이면 NULL, 아니면 a |
| `COALESCE(a, b, c, ...)` | NULL이 아닌 **첫 번째** 값 |

## 정렬과 NULL

| DBMS | NULL 위치 |
| --- | --- |
| **Oracle** | NULL을 **가장 큰 값**으로 취급 → ASC 시 맨 뒤 |
| **SQL Server** | NULL을 **가장 작은 값**으로 취급 → ASC 시 맨 앞 |

## 모델링 관점의 NULL

- 속성마다 **NULL 허용 여부**를 정의하고 ERD에 표시한다.
- 주식별자(PK)는 **NULL 불가** (→ [[5. 식별자]] 존재성).
- NULL을 허용하는 속성이 너무 많으면 데이터의 의미가 모호해지고 SQL 작성 시 실수가 생기기 쉽다.

---

## 시험 포인트

- NULL ≠ 0 ≠ 공백
- NULL 산술 연산 → **NULL**, 비교 연산 → **UNKNOWN**
- `= NULL` X, **`IS NULL`** O
- 집계 함수는 NULL **제외**, `COUNT(*)`만 예외
- `AVG(col)` ≠ `SUM(col)/COUNT(*)` (NULL 있을 때)
- Oracle: NULL 최대값 / SQL Server: NULL 최소값
