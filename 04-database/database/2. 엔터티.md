## 개요

**엔터티(Entity)**는 업무에 필요하고 유용한 정보를 저장하고 관리하기 위한 집합적인 것이다.

엔터티는 **인스턴스의 집합**이며, 실제 DB에서는 보통 **테이블**로 구현된다.

```text
엔터티     : 사원
인스턴스   : 김철수, 이영희, 박민수 ...   (테이블의 행)
속성      : 사번, 이름, 입사일 ...       (테이블의 열)
```

---

## 엔터티의 특징

| 특징 | 설명 |
| --- | --- |
| **업무에서 필요한 정보** | 해당 업무에서 필요하고 관리하고자 하는 정보여야 한다 |
| **식별 가능** | 유일한 식별자에 의해 각 인스턴스를 구분할 수 있어야 한다 |
| **인스턴스의 집합** | 영속적으로 존재하는 인스턴스가 **2개 이상** 있어야 한다 |
| **업무 프로세스에 의해 이용** | 업무 프로세스가 그 엔터티를 사용(CRUD)해야 한다 |
| **속성 포함** | 반드시 속성을 가져야 한다 (식별자만 있는 경우는 의심) |
| **관계 존재** | 다른 엔터티와 **최소 1개 이상**의 관계가 있어야 한다 |

> 관계 예외: 통계성 엔터티, 코드성 엔터티, 시스템 내부 처리용 엔터티는 관계를 생략할 수 있다.

---

## 엔터티의 분류

### 1. 유무형에 따른 분류

| 분류 | 설명 | 예 |
| --- | --- | --- |
| **유형 엔터티** | 물리적인 형태가 있고 안정적, 지속적으로 활용 | 사원, 물품, 강사 |
| **개념 엔터티** | 물리적 형태는 없지만 관리할 개념적 정보 | 조직, 보험상품 |
| **사건 엔터티** | 업무를 수행하면서 발생, 발생량이 많고 통계에 자주 사용 | 주문, 청구, 미납 |

### 2. 발생 시점에 따른 분류

| 분류 | 설명 | 예 |
| --- | --- | --- |
| **기본(키) 엔터티** | 다른 엔터티와 관계없이 **독립적으로 생성**, 자신만의 주식별자를 가짐 | 사원, 부서, 고객, 상품 |
| **중심 엔터티** | 기본 엔터티로부터 발생, 업무의 **중심** 역할. 많은 데이터가 발생하고 행위 엔터티를 만들어냄 | 계약, 주문, 매출, 청구 |
| **행위 엔터티** | **2개 이상의 부모 엔터티**로부터 발생, 자주 변경되고 데이터가 계속 증가 | 주문목록, 사원변경이력 |

```text
기본 엔터티     고객, 상품
     │
     ▼
중심 엔터티     주문
     │
     ▼
행위 엔터티     주문상세 (주문 + 상품)
```

---

## 엔터티 명명 규칙

- 가능하면 **현업에서 사용하는 용어**를 사용한다.
- **약어는 사용하지 않는다.**
- **단수 명사**를 사용한다.
- 모든 엔터티 이름은 **유일**해야 한다.
- 엔터티가 생성되는 **의미대로** 이름을 붙인다.

---

## 시험 포인트

- 인스턴스는 **2개 이상**이어야 엔터티 (1개뿐이면 엔터티로 보기 어려움)
- 관계는 최소 1개 이상, 단 **통계성·코드성·내부 처리용**은 예외
- 유무형: **유형 / 개념 / 사건**
- 발생 시점: **기본(키) / 중심 / 행위**
- 기본 엔터티 = 독립적 생성, 자신의 주식별자 / 행위 엔터티 = 2개 이상 부모
- 이름은 **단수 명사**, 약어 X
