## 개요

CBT 모의고사에서 틀린 개념만 모아 정리한 페이지이다.

모든 예시는 아래 `EMP` 테이블을 기준으로 한다. (Oracle 기준)

```text
EMPNO | ENAME | MGR  | DEPTNO | JOB       | SAL
1     | KING  | NULL | 10     | PRESIDENT | 5000
2     | JONES | 1    | 20     | MANAGER   | 3000
3     | BLAKE | 1    | 30     | MANAGER   | 2800
4     | SCOTT | 2    | 20     | ANALYST   | 3000
5     | SMITH | 4    | 20     | CLERK     | 800
6     | ALLEN | 3    | 30     | SALESMAN  | 1600

조직도
KING
 ├── JONES
 │    └── SCOTT
 │         └── SMITH
 └── BLAKE
      └── ALLEN
```

## 1. PIVOT

> 관련 노트 → [[25. PIVOT 절과 UNPIVOT 절]]

### 개념

**PIVOT**은 **행으로 나열된 값을 열(컬럼)로 펼쳐서** 보여주는 기능이다. 엑셀의 피벗 테이블과 같다.

```text
[PIVOT 전]  JOB, DEPTNO 가 행으로 나열         [PIVOT 후]  DEPTNO 값이 컬럼이 됨
JOB      | DEPTNO | SAL                         JOB       | 10   | 20   | 30
MANAGER  | 20     | 3000                        MANAGER   | NULL | 3000 | 2800
MANAGER  | 30     | 2800          ───────▶      ANALYST   | NULL | 3000 | NULL
ANALYST  | 20     | 3000                        ...
...
```

---

### 문법 구조

```sql
SELECT *
  FROM (SELECT JOB, DEPTNO, SAL FROM EMP)        -- ① 원본 (보통 인라인 뷰)
 PIVOT (
        SUM(SAL)                                 -- ② 집계 함수: 칸에 들어갈 값
        FOR DEPTNO                               -- ③ FOR 컬럼: 열로 펼칠 기준
        IN (10, 20, 30)                          -- ④ IN 목록: 실제로 만들 열
       );
```

| 구성 요소 | 역할 | 위 예시 |
| --- | --- | --- |
| ① 원본 | PIVOT 할 데이터 | JOB, DEPTNO, SAL |
| ② **집계 함수** | 각 칸에 들어갈 값. **반드시 집계 함수**여야 한다 (SUM, COUNT, AVG, MAX ...) | `SUM(SAL)` |
| ③ **FOR 컬럼** | 이 컬럼의 **값**이 새로운 **열 이름**이 된다 | `DEPTNO` |
| ④ **IN 목록** | 만들 열을 **직접 나열**한다. 상수만 가능 (서브쿼리 X) | `10, 20, 30` |
| ⑤ **그룹 컬럼** | ②, ③에 쓰이지 않은 **나머지 컬럼 전부** → 자동 GROUP BY | `JOB` |

> 핵심: GROUP BY 를 **직접 쓰지 않는다.** ②③에 안 쓴 컬럼이 **자동으로** 그룹 기준이 된다.

---

### 동작 과정 따라가기

**Step 1. 원본 (인라인 뷰 결과)**

```text
JOB       | DEPTNO | SAL
PRESIDENT | 10     | 5000
MANAGER   | 20     | 3000
MANAGER   | 30     | 2800
ANALYST   | 20     | 3000
CLERK     | 20     | 800
SALESMAN  | 30     | 1600
```

**Step 2. 그룹 컬럼 결정**

- SAL → 집계 함수에 사용 / DEPTNO → FOR 에 사용
- 남은 컬럼 **JOB** → 그룹 기준 → JOB 값마다 **1행** (5개 직업 → 5행)

**Step 3. IN 목록 값마다 열 생성 후 집계**

- 각 JOB 행에서, DEPTNO = 10 인 SAL의 합 → `10` 열, 20 → `20` 열, 30 → `30` 열
- 해당하는 데이터가 없으면 **NULL**

```text
JOB       | 10   | 20   | 30
PRESIDENT | 5000 | NULL | NULL
MANAGER   | NULL | 3000 | 2800     ← MANAGER 중 20번 부서 3000, 30번 부서 2800
ANALYST   | NULL | 3000 | NULL
CLERK     | NULL | 800  | NULL
SALESMAN  | NULL | NULL | 1600
```

---

### 그룹 컬럼에 따라 결과가 달라진다 (최다 함정)

인라인 뷰에 **어떤 컬럼을 남기느냐**가 결과 행 수를 결정한다.

**(1) 그룹 컬럼이 없을 때 → 1행**

```sql
SELECT *
  FROM (SELECT DEPTNO, SAL FROM EMP)
 PIVOT (SUM(SAL) FOR DEPTNO IN (10, 20, 30));
```

```text
10   | 20   | 30
5000 | 6800 | 4400          ← 20: 3000+3000+800 / 30: 2800+1600
```

**(2) 그룹 컬럼 JOB → 5행** (위의 기본 예시)

**(3) 인라인 뷰 없이 EMP 를 바로 사용 → 6행 (집계가 안 됨)**

```sql
SELECT *
  FROM EMP
 PIVOT (SUM(SAL) FOR DEPTNO IN (10, 20, 30));
```

- 그룹 컬럼 = SAL, DEPTNO 를 뺀 **EMPNO, ENAME, MGR, JOB** 전부
- EMPNO 가 행마다 다르므로 그룹이 **원래 행 수(6개)** 그대로 나뉜다

```text
EMPNO | ENAME | MGR  | JOB       | 10   | 20   | 30
1     | KING  | NULL | PRESIDENT | 5000 | NULL | NULL
2     | JONES | 1    | MANAGER   | NULL | 3000 | NULL
3     | BLAKE | 1    | MANAGER   | NULL | NULL | 2800
...                                               (6행)
```

> 문제에서 "결과 행 수는?" 이 나오면 **집계·FOR 에 안 쓴 컬럼**이 뭔지부터 찾는다.

---

### IN 목록 규칙

| 상황 | 결과 |
| --- | --- |
| IN 에 **없는** 값의 데이터 | **버려진다** (결과에 안 나옴) |
| IN 에 **있지만** 데이터가 없는 값 | 열은 만들어지고 값은 **NULL** |
| IN 에 서브쿼리 사용 | **불가** (값을 직접 나열해야 함) |

```sql
-- IN (10, 20) 만 쓰면 30번 부서 데이터는 사라진다
SELECT * FROM (SELECT JOB, DEPTNO, SAL FROM EMP)
 PIVOT (SUM(SAL) FOR DEPTNO IN (10, 20));
→ SALESMAN 행: 10 = NULL, 20 = NULL  (30번 부서 1600은 버려짐)

-- IN (10, 20, 30, 40) → 40 열이 생기지만 모두 NULL
```

### 집계 함수에 따른 빈 칸 값

| 집계 함수 | 데이터 없는 칸 |
| --- | --- |
| `SUM`, `AVG`, `MAX`, `MIN` | **NULL** |
| `COUNT` | **0** |

---

### 결과 컬럼 이름 규칙

| 작성 | 결과 컬럼명 |
| --- | --- |
| `SUM(SAL) FOR DEPTNO IN (10, 20)` | `10`, `20` |
| `SUM(SAL) FOR DEPTNO IN (10 AS D10, 20 AS D20)` | `D10`, `D20` |
| `SUM(SAL) AS S FOR DEPTNO IN (10, 20)` | `10_S`, `20_S` |
| `SUM(SAL) AS S, COUNT(*) AS C FOR DEPTNO IN (10 AS D10, 20 AS D20)` | `D10_S`, `D10_C`, `D20_S`, `D20_C` |

- 규칙: **`IN 별칭` + `_` + `집계 별칭`**
- 별칭 없이 숫자 이름이 된 컬럼은 SELECT 할 때 **큰따옴표**가 필요하다.

```sql
SELECT JOB, "10", "20"        -- 10, 20 으로 쓰면 숫자 상수가 되어버림
  FROM (SELECT JOB, DEPTNO, SAL FROM EMP)
 PIVOT (SUM(SAL) FOR DEPTNO IN (10, 20, 30));
```

### 집계 함수 여러 개

```sql
SELECT *
  FROM (SELECT JOB, DEPTNO, SAL FROM EMP)
 PIVOT (SUM(SAL) AS S, COUNT(*) AS C
        FOR DEPTNO IN (20 AS D20, 30 AS D30));
```

```text
JOB       | D20_S | D20_C | D30_S | D30_C
PRESIDENT | NULL  | 0     | NULL  | 0
MANAGER   | 3000  | 1     | 2800  | 1
ANALYST   | 3000  | 1     | NULL  | 0
CLERK     | 800   | 1     | NULL  | 0
SALESMAN  | NULL  | 0     | 1600  | 1
```

### FOR 컬럼 여러 개

```sql
PIVOT (SUM(SAL) FOR (DEPTNO, JOB) IN ((20, 'MANAGER') AS D20_MGR,
                                      (30, 'MANAGER') AS D30_MGR))
```

- FOR 와 IN 을 **괄호로 묶어** 값 조합으로 열을 만든다.

---

### CASE + GROUP BY 로 같은 결과 만들기

PIVOT 은 아래 쿼리를 짧게 쓴 것과 같다. 시험에서 "같은 결과를 내는 SQL" 문제로 자주 나온다.

```sql
SELECT JOB,
       SUM(CASE WHEN DEPTNO = 10 THEN SAL END) AS "10",
       SUM(CASE WHEN DEPTNO = 20 THEN SAL END) AS "20",
       SUM(CASE WHEN DEPTNO = 30 THEN SAL END) AS "30"
  FROM EMP
 GROUP BY JOB;              -- PIVOT 의 '그룹 컬럼' 이 여기 들어간다

-- DECODE 로도 가능
SUM(DECODE(DEPTNO, 10, SAL)) AS "10"
```

```text
PIVOT                                 CASE 버전
그룹 컬럼(자동)               ↔        GROUP BY JOB
SUM(SAL)                      ↔        SUM(CASE ... THEN SAL END)
FOR DEPTNO IN (10, 20, 30)    ↔        WHEN DEPTNO = 10 / 20 / 30 각각 한 컬럼
```

---

### UNPIVOT

**열을 행으로** 되돌린다. PIVOT 의 반대이다.

```sql
SELECT *
  FROM P                                -- JOB, D10, D20, D30 컬럼을 가진 테이블
UNPIVOT (
         SAL                            -- 값이 들어갈 새 컬럼 이름
         FOR DEPTNO                     -- 열 이름이 들어갈 새 컬럼 이름
         IN (D10 AS 10, D20 AS 20, D30 AS 30)   -- 행으로 내릴 기존 열
        );
```

```text
[UNPIVOT 전] P                          [UNPIVOT 후]
JOB      | D10  | D20  | D30            JOB       | DEPTNO | SAL
MANAGER  | NULL | 3000 | 2800  ───▶     MANAGER   | 20     | 3000
                                        MANAGER   | 30     | 2800
                                        (D10 이 NULL 이라 행이 안 생김)
```

| 옵션 | 동작 | 위 P 전체(5행) 기준 결과 |
| --- | --- | --- |
| `EXCLUDE NULLS` (**기본값**) | NULL 인 값은 행으로 만들지 않는다 | NULL 아닌 칸 수 = **6행** |
| `INCLUDE NULLS` | NULL 도 행으로 만든다 | 5행 × 3열 = **15행** |

```sql
SELECT * FROM P
UNPIVOT INCLUDE NULLS (SAL FOR DEPTNO IN (D10 AS 10, D20 AS 20, D30 AS 30));
```

- `SAL`, `DEPTNO` 는 UNPIVOT 이 **새로 만드는 컬럼 이름**이다 (원래 테이블에 없어도 됨).
- IN 에 나열한 열들은 **데이터 타입이 같아야** 한다.
- UNPIVOT 은 PIVOT 을 **완벽히 되돌리지 못한다.** PIVOT 에서 SUM 으로 합쳐진 값은 원래 여러 행으로 쪼개지지 않는다.

---

### 시험 포인트

- PIVOT = 행 → 열 / UNPIVOT = 열 → 행
- PIVOT 은 **집계 함수 필수**
- **집계·FOR 에 안 쓴 컬럼 = 자동 GROUP BY** → 인라인 뷰로 컬럼을 줄여야 원하는 결과
- IN 목록에 없는 값은 버려짐, 데이터 없는 칸은 NULL (COUNT 는 0)
- IN 에는 **상수만** (서브쿼리 X)
- 컬럼명: `IN별칭_집계별칭`, 숫자 컬럼명은 `"10"` 처럼 큰따옴표
- UNPIVOT 기본은 **EXCLUDE NULLS**

## 2. 그룹 함수 (ROLLUP, CUBE, GROUPING SETS)

> 관련 노트 → [[21. 그룹 함수]]

| 함수 | 만들어지는 그룹 (A, B 기준) | 그룹 수 | 순서 영향 |
| --- | --- | --- | --- |
| `ROLLUP(A, B)` | (A, B), (A), **()** | N + 1 | **있음** |
| `CUBE(A, B)` | (A, B), (A), (B), **()** | 2^N | 없음 |
| `GROUPING SETS(A, B)` | (A), (B) | 나열한 것만 | 없음 |

- `()` = 전체 합계
- **GROUPING SETS에는 (A, B) 조합도, 전체 합계도 없다.** 필요하면 `GROUPING SETS((A, B), A, ())` 처럼 직접 적는다.
- `ROLLUP(A, B)` ≠ `ROLLUP(B, A)` → 소계 기준이 달라진다.

### 행 수 세기 (EMP 기준)

- DEPTNO, JOB 조합 6개 / DEPTNO 3개 / JOB 5개

| 쿼리 | 행 수 |
| --- | --- |
| `GROUP BY DEPTNO, JOB` | 6 |
| `GROUP BY ROLLUP(DEPTNO, JOB)` | 6 + 3 + 1 = **10** |
| `GROUP BY CUBE(DEPTNO, JOB)` | 6 + 3 + 5 + 1 = **15** |
| `GROUP BY GROUPING SETS(DEPTNO, JOB)` | 3 + 5 = **8** |
| `GROUP BY DEPTNO, ROLLUP(JOB)` | 6 + 3 = **9** (전체 합계 없음) |

### 응용 형태

```text
ROLLUP(A, (B, C))  → (A, B, C), (A), ()        (B, C)를 하나로 묶음
GROUP BY A, ROLLUP(B) → (A, B), (A)            A는 항상 고정, 전체 합계 X
```

### GROUPING 함수

- 해당 컬럼이 **집계되어 NULL로 표시된 행이면 1**, 아니면 0.
- 원래 데이터의 NULL과 소계 때문에 생긴 NULL을 구분할 때 쓴다.

```sql
SELECT CASE GROUPING(DEPTNO) WHEN 1 THEN '전체합계' ELSE TO_CHAR(DEPTNO) END AS DEPTNO,
       CASE GROUPING(JOB)    WHEN 1 THEN '소계'     ELSE JOB END            AS JOB,
       SUM(SAL)
  FROM EMP
 GROUP BY ROLLUP(DEPTNO, JOB);
```

```text
행 종류         GROUPING(DEPTNO) | GROUPING(JOB)
(DEPTNO, JOB)        0           |      0
부서 소계             0           |      1
전체 합계             1           |      1
```

## 3. 계층형 질의 (START WITH, 계층 탐색)

> 관련 노트 → [[24. 계층형 질의와 셀프 조인]]

```sql
SELECT LEVEL, LPAD(' ', 2 * (LEVEL - 1)) || ENAME AS ENAME
  FROM EMP
 START WITH MGR IS NULL           -- 시작(루트) 행
CONNECT BY PRIOR EMPNO = MGR      -- 탐색 방향
 ORDER SIBLINGS BY ENAME;         -- 형제끼리만 정렬
```

```text
LEVEL | ENAME
1     | KING
2     |   BLAKE
3     |     ALLEN
2     |   JONES
3     |     SCOTT
4     |       SMITH
```

### START WITH

- 계층 탐색을 **시작할 루트 행**을 지정한다.
- **START WITH로 선택된 행은 CONNECT BY 조건과 상관없이 항상 결과에 포함**된다. (함정)
- START WITH 를 생략하면 **모든 행**이 각각 루트가 되어 탐색한다.

### 탐색 방향: PRIOR 읽는 법

**PRIOR가 붙은 컬럼 = 이미 찾은 행(이전 행)의 값**이라고 읽는다.

| 조건 | 해석 | 방향 |
| --- | --- | --- |
| `PRIOR EMPNO = MGR` | 이전 행의 EMPNO를 MGR로 갖는 행 = **부하**를 찾음 | **순방향** (위 → 아래) |
| `PRIOR MGR = EMPNO` | 이전 행의 MGR을 EMPNO로 갖는 행 = **상사**를 찾음 | **역방향** (아래 → 위) |

> 외우기: PRIOR 가 **PK(EMPNO) 쪽에 붙으면 순방향**, **FK(MGR) 쪽에 붙으면 역방향**
> `MGR = PRIOR EMPNO` 처럼 좌우를 바꿔 써도 PRIOR가 어디 붙었는지만 보면 된다.

```sql
-- 역방향: SMITH부터 위로
SELECT LEVEL, ENAME
  FROM EMP
 START WITH ENAME = 'SMITH'
CONNECT BY PRIOR MGR = EMPNO;
```

```text
LEVEL | ENAME
1     | SMITH
2     | SCOTT
3     | JONES
4     | KING       ← 역방향이어도 시작 행이 LEVEL 1
```

### 가상 컬럼 · 함수

| 이름 | 설명 | 예 (SMITH 행) |
| --- | --- | --- |
| `LEVEL` | 루트 = 1, 한 단계 내려갈 때마다 +1 | 4 |
| `CONNECT_BY_ISLEAF` | 자식이 없는 리프면 1, 아니면 0 | 1 |
| `CONNECT_BY_ISCYCLE` | 순환이 발생한 행이면 1 (`NOCYCLE`과 함께 사용) | 0 |
| `SYS_CONNECT_BY_PATH(ENAME, '/')` | 루트부터 현재까지 경로 | `/KING/JONES/SCOTT/SMITH` |
| `CONNECT_BY_ROOT ENAME` | 현재 행의 루트 값 | `KING` |

### WHERE vs CONNECT BY 조건 (함정)

실행 순서: **START WITH → CONNECT BY → WHERE**

```sql
-- (1) WHERE 에서 제외: 그 행만 빠지고 자식은 남는다
... START WITH MGR IS NULL
   CONNECT BY PRIOR EMPNO = MGR
     WHERE ENAME <> 'JONES';
→ KING, BLAKE, ALLEN, SCOTT, SMITH

-- (2) CONNECT BY 에서 제외: 그 행부터 아래 가지 전체가 잘린다
... START WITH MGR IS NULL
   CONNECT BY PRIOR EMPNO = MGR AND ENAME <> 'JONES';
→ KING, BLAKE, ALLEN

-- (3) CONNECT BY 조건이어도 루트는 항상 포함
... START WITH MGR IS NULL
   CONNECT BY PRIOR EMPNO = MGR AND DEPTNO = 20;
→ KING(부서 10이지만 루트라 포함), JONES, SCOTT, SMITH
```

### 정렬

- `ORDER BY` → 계층 구조가 **깨지고** 전체가 정렬된다.
- `ORDER SIBLINGS BY` → 계층 구조를 **유지**하면서 같은 부모를 가진 형제끼리만 정렬한다.

### 순환 (NOCYCLE)

- 데이터가 순환(A → B → A)하면 에러가 난다. `CONNECT BY NOCYCLE PRIOR ...` 로 순환 지점에서 멈춘다.

## 4. SAVEPOINT

> 관련 노트 → [[28. TCL]]

트랜잭션 안에 **중간 저장점**을 만들어 그 지점까지만 롤백할 수 있게 한다.

| DBMS | 저장점 생성 | 저장점까지 롤백 |
| --- | --- | --- |
| Oracle | `SAVEPOINT SP1;` | `ROLLBACK TO SP1;` |
| SQL Server | `SAVE TRANSACTION SP1;` | `ROLLBACK TRANSACTION SP1;` |

### 추적 문제 풀기

```sql
INSERT INTO T VALUES (1);
SAVEPOINT A;
INSERT INTO T VALUES (2);
SAVEPOINT B;
INSERT INTO T VALUES (3);
ROLLBACK TO A;          -- (2), (3) 취소, (1)은 남음
INSERT INTO T VALUES (4);
COMMIT;
→ 결과: 1, 4
```

### 핵심 규칙

- `ROLLBACK TO SP` 는 **트랜잭션을 끝내지 않는다.** 이후 작업은 같은 트랜잭션으로 이어진다.
- `ROLLBACK TO A` 를 하면 **A 이후에 만든 저장점(B)도 사라진다.** → 그 뒤 `ROLLBACK TO B` 는 **에러**.
- 저장점 없이 `ROLLBACK` → 마지막 **COMMIT 이후 전체**가 취소된다.
- **같은 이름**으로 SAVEPOINT를 다시 만들면 **나중 것이 앞의 것을 덮어쓴다.**

```sql
INSERT (1); SAVEPOINT A;
INSERT (2); SAVEPOINT A;     -- A가 이 위치로 이동
INSERT (3);
ROLLBACK TO A;               -- (3)만 취소 → 1, 2 남음
```

### Oracle vs SQL Server

| 구분 | Oracle | SQL Server |
| --- | --- | --- |
| DML 기본 | 자동 커밋 X (직접 COMMIT) | **AUTO COMMIT** 기본 |
| DDL 실행 시 | **자동 커밋** (이전 DML도 함께 커밋, 저장점 사라짐) | 트랜잭션 안이면 롤백 가능 |

## 5. MERGE

> 관련 노트 → [[27. DML]]

**대상 테이블에 같은 키가 있으면 UPDATE, 없으면 INSERT** 를 한 문장으로 처리한다.

```sql
MERGE INTO 대상 T
USING 소스 S
   ON (T.ID = S.ID)                       -- Oracle은 괄호 필수
 WHEN MATCHED THEN
      UPDATE SET T.VAL = S.VAL
      DELETE WHERE T.VAL < 0              -- (선택) UPDATE 된 행 중 삭제
 WHEN NOT MATCHED THEN
      INSERT (ID, VAL) VALUES (S.ID, S.VAL);
```

### 결과 추적

```text
대상 T          소스 S
ID | VAL        ID | VAL
1  | 10         2  | 200
2  | 20         3  | 300

MERGE 후 T
ID | VAL
1  | 10     ← 소스에 없음: 아무 일도 안 일어남 (삭제 X)
2  | 200    ← MATCHED → UPDATE
3  | 300    ← NOT MATCHED → INSERT
```

### 핵심 규칙

- `WHEN MATCHED`, `WHEN NOT MATCHED` 는 **둘 중 하나만 써도 된다.**
- **ON 절에 쓴 컬럼은 UPDATE SET 할 수 없다.** (에러)
- **소스에만 없는 대상 행**은 그대로 남는다. MERGE가 대상 행을 지우는 건 `DELETE WHERE` 뿐이다.
- `DELETE WHERE` 는 **MATCHED 절 안에서만**, **UPDATE 된 행에 대해서만** (UPDATE 후 값으로) 평가된다.
- USING 에는 테이블, 뷰, **서브쿼리** 모두 가능하다.
- 소스에 같은 키가 여러 행이라 대상 한 행이 **여러 번 매칭되면 에러**가 난다.
- 각 WHEN 절의 UPDATE / INSERT 뒤에도 `WHERE` 조건을 붙일 수 있다.

## 6. 정규 표현식

> 관련 노트 → [[26. 정규 표현식]]

### 메타 문자

| 문자                       | 의미                             | 예                  |
| ------------------------ | ------------------------------ | ------------------ |
| `.`                      | 아무 문자 **1개**                   | `a.c` → abc, a1c   |
| `*`                      | 앞 문자 **0개 이상**                 | `ab*` → a, ab, abb |
| `+`                      | 앞 문자 **1개 이상**                 | `ab+` → ab, abb    |
| `?`                      | 앞 문자 **0개 또는 1개**              | `ab?` → a, ab      |
| `{m}` / `{m,}` / `{m,n}` | 정확히 m번 / m번 이상 / m~n번          | `\d{3}`            |
| `^`                      | 문자열 **시작**                     | `^A`               |
| `$`                      | 문자열 **끝**                      | `N$`               |
| `[abc]`                  | 괄호 안 문자 중 하나                   | `[0-9]`            |
| `[^abc]`                 | 괄호 안 문자 **제외** (괄호 안의 `^`는 부정) | `[^0-9]`           |
| `a\|b`                   | a 또는 b                         | `cat\|dog`         |
| `( )`                    | 그룹 (서브 표현식)                    | `(ab)+`            |
| `\1`                     | 첫 번째 그룹을 다시 참조 (역참조)           | `(ab)\1` → abab    |

| 축약 | 의미 | POSIX 클래스 |
| --- | --- | --- |
| `\d` / `\D` | 숫자 / 숫자 아님 | `[[:digit:]]` |
| `\w` / `\W` | 영문·숫자·`_` / 그 외 | `[[:alnum:]]` (+ `_`) |
| `\s` / `\S` | 공백 / 공백 아님 | `[[:space:]]` |
| | 영문자 | `[[:alpha:]]` |
| | 대문자 / 소문자 | `[[:upper:]]` / `[[:lower:]]` |

- **탐욕(greedy) vs 최소(non-greedy)**: `*`, `+` 는 최대한 길게 매칭. 뒤에 `?` 를 붙이면 (`*?`, `+?`) 최대한 짧게.

### 함수

| 함수 | 반환 | 못 찾으면 |
| --- | --- | --- |
| `REGEXP_LIKE(문자, 패턴)` | 조건 (WHERE 절에서 사용) | FALSE |
| `REGEXP_SUBSTR(문자, 패턴, 시작, 몇번째)` | 매칭된 **문자열** | **NULL** |
| `REGEXP_INSTR(문자, 패턴, 시작, 몇번째)` | 매칭된 **위치** | **0** |
| `REGEXP_REPLACE(문자, 패턴, 바꿀값, 시작, 몇번째)` | 치환된 문자열 | 원본 그대로 |
| `REGEXP_COUNT(문자, 패턴)` | 매칭 **횟수** | 0 |

- 시작 위치, 몇 번째 기본값은 **1**. 단 `REGEXP_REPLACE` 의 몇 번째 기본값은 **0 = 전부 치환**.
- 마지막 인자 match 옵션: `'i'` 대소문자 무시, `'c'` 대소문자 구분(기본), `'n'` `.`이 줄바꿈도 매칭, `'m'` 여러 줄 모드.

### 예제

```sql
REGEXP_SUBSTR('abc123def456', '\d+')            → '123'
REGEXP_SUBSTR('abc123def456', '\d+', 1, 2)      → '456'
REGEXP_SUBSTR('aaab', 'a*')                      → 'aaa'   (탐욕)
REGEXP_SUBSTR('aaab', 'a+?')                     → 'a'     (최소)
REGEXP_SUBSTR('http://www.test.com/page', '[^/]+', 1, 2)  → 'www.test.com'
                                    -- 1번째 'http:', 2번째 'www.test.com', 3번째 'page'
REGEXP_INSTR('abc123', '\d')                     → 4
REGEXP_REPLACE('a1b2c3', '[0-9]')                → 'abc'   (바꿀값 생략 = 삭제)
REGEXP_REPLACE('a1b2c3', '[0-9]', '*', 1, 2)     → 'a1b*c3' (2번째만)
REGEXP_COUNT('a1b2c3', '\d')                     → 3

-- 서브 표현식: 여는 괄호 순서대로 1, 2, 3, 4번
REGEXP_SUBSTR('1234567890', '(123)(4(56)(78))', 1, 1, 'i', 4)  → '78'
--  1: (123)  2: (4(56)(78)) = 45678  3: (56)  4: (78)

SELECT ENAME FROM EMP WHERE REGEXP_LIKE(ENAME, '^[A-C]');   -- A~C로 시작
→ BLAKE, ALLEN
```

## 7. 집합 연산자

> 관련 노트 → [[20. 집합 연산자]]

| 연산자 | 의미 | 중복 |
| --- | --- | --- |
| `UNION` | 합집합 | **제거** |
| `UNION ALL` | 합집합 | **유지** (정렬·중복 제거 없음 → 가장 빠름) |
| `INTERSECT` | 교집합 | 제거 |
| `MINUS` (Oracle) / `EXCEPT` (SQL Server) | 차집합 | 제거 |

### 결과 추적

```text
A = {1, 1, 2, 3}      B = {2, 3, 3, 4}

A UNION B       → 1, 2, 3, 4              (4행)
A UNION ALL B   → 1, 1, 2, 3, 2, 3, 3, 4  (8행)
A INTERSECT B   → 2, 3                    (2행)
A MINUS B       → 1                       (1행, 중복 제거되어 1개)
B MINUS A       → 4                       (1행)
```

### 핵심 규칙

- 각 SELECT 의 **컬럼 수가 같고**, 데이터 타입이 **호환**되어야 한다.
- 결과 **컬럼명(별칭)은 첫 번째 SELECT** 기준이다.
- `ORDER BY` 는 **맨 마지막에 한 번만** 쓸 수 있고, 첫 번째 SELECT 의 컬럼명·별칭 또는 위치 번호를 쓴다.
- 집합 연산에서 **NULL끼리는 같은 값**으로 본다 (UNION 시 NULL 중복도 제거).
- `MINUS` 는 **순서가 중요**하다 (A − B ≠ B − A).
- 우선순위: Oracle 은 모든 집합 연산자가 **같은 우선순위로 위에서부터** 처리. (표준·SQL Server 는 INTERSECT 가 먼저) → 헷갈리면 괄호로 명시.

```text
(A UNION ALL B) UNION C   → 마지막 UNION 이 앞의 중복까지 전부 제거
(A UNION B) UNION ALL C   → C 와의 중복은 남는다
```

- UNION 의 결과가 정렬되어 나온다고 **보장되지 않는다.** 정렬이 필요하면 ORDER BY 를 쓴다.

## 8. 트랜잭션 격리 수준 (Isolation Level)

> 관련 노트 → [[37. Lock과 트랜잭션 동시성 제어]], [[8. 모델이 표현하는 트랜잭션의 이해]]

### 동시성 문제 3가지

| 문제 | 설명 | 원인 |
| --- | --- | --- |
| **Dirty Read** | 다른 트랜잭션이 **아직 커밋하지 않은** 데이터를 읽음 | 상대가 나중에 롤백하면 없는 값을 읽은 셈 |
| **Non-Repeatable Read** | 같은 행을 두 번 읽었는데 **값이 다름** | 사이에 다른 트랜잭션이 **UPDATE / DELETE** 후 커밋 |
| **Phantom Read** | 같은 조건으로 두 번 조회했는데 **없던 행이 생김** | 사이에 다른 트랜잭션이 **INSERT** 후 커밋 |

```text
Non-Repeatable Read                     Phantom Read
T1: SELECT SAL WHERE EMPNO=1 → 5000     T1: SELECT COUNT(*) WHERE DEPTNO=20 → 3
T2: UPDATE SAL=6000; COMMIT;            T2: INSERT (DEPTNO=20); COMMIT;
T1: SELECT SAL WHERE EMPNO=1 → 6000     T1: SELECT COUNT(*) WHERE DEPTNO=20 → 4
```

### 격리 수준별 발생 여부

| 격리 수준 | Dirty Read | Non-Repeatable Read | Phantom Read |
| --- | --- | --- | --- |
| **READ UNCOMMITTED** | O | O | O |
| **READ COMMITTED** | X | O | O |
| **REPEATABLE READ** | X | X | O |
| **SERIALIZABLE** | X | X | X |

- 아래로 갈수록 **일관성 ↑, 동시성(성능) ↓**
- 외우기: 레벨이 하나 올라갈 때마다 **Dirty → Non-Repeatable → Phantom** 순서로 하나씩 막힌다.
- 기본값: **Oracle, SQL Server = READ COMMITTED** / MySQL(InnoDB) = REPEATABLE READ
- Oracle 은 READ COMMITTED 와 SERIALIZABLE 만 지원한다.

## 시험 직전 체크

- [ ] PIVOT: 안 쓰인 컬럼이 자동 GROUP BY → 인라인 뷰로 컬럼 줄이기
- [ ] ROLLUP N+1 / CUBE 2^N / GROUPING SETS 는 나열한 것만 (전체합계 X)
- [ ] GROUPING = 소계 행이면 1
- [ ] START WITH 행은 CONNECT BY 조건과 무관하게 항상 포함
- [ ] PRIOR 붙은 쪽 = 이전 행 / PRIOR EMPNO = MGR → 순방향
- [ ] WHERE 는 그 행만 제외, CONNECT BY 조건은 가지째 제외
- [ ] ROLLBACK TO A → A 이후 저장점 삭제, 트랜잭션은 계속
- [ ] MERGE: ON 컬럼 UPDATE 불가, 매칭 안 된 대상 행은 그대로
- [ ] REGEXP_SUBSTR 없으면 NULL / INSTR 없으면 0 / REPLACE 기본 전부 치환
- [ ] 집합 연산자: 컬럼명은 첫 SELECT, ORDER BY 는 마지막 한 번
- [ ] 격리 수준 표 (Dirty → Non-Repeatable → Phantom 순으로 막힘)
