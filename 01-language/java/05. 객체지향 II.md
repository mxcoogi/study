## 개요

[[04. 객체지향 I]] 에서 클래스, 객체, 변수, 메서드를 봤다면, 여기서는 클래스끼리 **관계**를 맺고 코드를 **유연하게** 만드는 방법을 정리한다.

| 주제 | 핵심 |
| --- | --- |
| **상속** | 기존 클래스를 재사용해 새 클래스를 만든다 |
| **오버라이딩** | 물려받은 메서드를 자식에 맞게 다시 정의한다 |
| **package, import** | 클래스를 묶고 가져다 쓴다 |
| **제어자** | `static`, `final`, `abstract`, 접근 제어자로 클래스·멤버의 성질을 정한다 |
| **다형성** | 조상 타입 참조 변수로 자손 객체를 다룬다 |
| **추상 클래스** | 미완성 설계도. 공통 부분만 정의하고 나머지는 자손에게 맡긴다 |
| **인터페이스** | 구현 없는 규칙의 모음. 다중 구현, 결합도 낮추기 |
| **내부 클래스** | 클래스 안에 선언한 클래스 |

# 1. 상속 (Inheritance)

## 상속이란?

**기존 클래스를 재사용해서 새로운 클래스를 작성**하는 것이다. `extends` 키워드를 쓴다.

```java
class Parent { int age; }
class Child extends Parent { }   // Child 는 Parent 의 age 를 물려받는다
```

| 용어 | 다른 이름 |
| --- | --- |
| 조상 클래스 | 부모(parent) 클래스, 상위(super) 클래스, 기반(base) 클래스 |
| 자손 클래스 | 자식(child) 클래스, 하위(sub) 클래스, 파생(derived) 클래스 |

### 상속의 규칙

- 자손은 조상의 **모든 멤버를 상속**받는다.
- **생성자와 초기화 블록은 상속되지 않는다.**
- `private` 멤버도 상속은 되지만 자손에서 **직접 접근할 수는 없다.** (getter 등으로 접근)
- 자손의 멤버 개수는 조상보다 **항상 같거나 많다.** (상속 = 확장, extends)
- 조상이 바뀌면 자손에 영향을 주지만, 자손이 바뀌어도 조상에는 영향이 없다.

```java
class Tv {
    boolean power;
    int channel;
    void power()       { power = !power; }
    void channelUp()   { ++channel; }
    void channelDown() { --channel; }
}

class SmartTv extends Tv {      // Tv 의 모든 멤버 + 새 멤버
    boolean caption;            // 자막 on/off
    void displayCaption(String text) {
        if (caption) System.out.println(text);
    }
}

SmartTv stv = new SmartTv();
stv.channel = 10;               // 조상에게 물려받은 멤버
stv.channelUp();
stv.caption = true;             // 자신의 멤버
```

- 자손 인스턴스를 만들면 **조상의 멤버와 자손의 멤버가 합쳐진 하나의 인스턴스**가 생긴다. 조상 인스턴스가 따로 생기는 것이 아니다.

---

## 클래스 간의 관계: 상속 vs 포함

### 포함 (Composition)

한 클래스의 **멤버 변수로 다른 클래스 타입의 참조 변수**를 선언하는 것이다.

```java
class Point  { int x, y; }

// 상속
class Circle extends Point { int r; }

// 포함
class Circle {
    Point c = new Point();   // 원점
    int r;                   // 반지름
}
```

### 클래스 간 관계 결정하기

| 관계 | 판단 문장 | 선택 | 예 |
| --- | --- | --- | --- |
| **is-a** | ~은 ~**이다** | **상속** | SportsCar 는 Car 이다 |
| **has-a** | ~은 ~를 **가지고 있다** | **포함** | Circle 은 Point(원점)를 가지고 있다 |

- 대부분의 관계는 **has-a(포함)**이다. 상속은 is-a 가 확실할 때만 쓴다.
- 실무에서는 "**상속보다 포함(composition over inheritance)**"을 권장한다. 상속은 조상과 자손이 강하게 묶여 조상을 바꾸기 어려워진다.

---

## 단일 상속

자바는 **하나의 조상만** 상속받을 수 있다. (C++ 는 다중 상속 허용)

```java
class TvDVD extends Tv, DVD { }   // 에러: 다중 상속 불가
```

- 이유: 두 조상에 **같은 이름의 멤버**가 있으면 어느 것을 물려받을지 모호해진다 (다이아몬드 문제).
- 다른 클래스의 기능이 필요하면 **포함**으로 해결하거나 **인터페이스**를 여러 개 구현한다.

```java
class TvDVD extends Tv {
    DVD dvd = new DVD();             // 포함

    void play() { dvd.play(); }      // DVD 의 기능을 감싸서 제공
}
```

---

## Object 클래스: 모든 클래스의 조상

- 조상을 지정하지 않은 클래스는 컴파일러가 자동으로 **`extends Object`** 를 붙인다.
- 따라서 모든 클래스는 상속 계층의 맨 위에 **Object** 를 둔다.
- 모든 클래스는 Object 의 멤버(`toString()`, `equals()`, `hashCode()` 등)를 쓸 수 있다. (→ java.lang 패키지에서 자세히)

```java
class Tv { }                  // 컴파일 후
class Tv extends Object { }   // 이렇게 된다
```

![All classes are descendants of Object](https://docs.oracle.com/javase/tutorial/figures/java/classes-object.gif)

*자바의 모든 클래스는 Object 의 자손이다 (출처: Oracle, The Java Tutorials, Inheritance)*

# 2. 오버라이딩 (Overriding)

## 오버라이딩이란?

조상에게 물려받은 메서드의 **내용을 자손에 맞게 다시 정의**하는 것이다.

```java
class Point {
    int x, y;
    String getLocation() { return "x : " + x + ", y : " + y; }
}

class Point3D extends Point {
    int z;

    @Override                                  // 오버라이딩임을 컴파일러에게 알림
    String getLocation() {                     // 선언부는 그대로, 내용만 바꿈
        return "x : " + x + ", y : " + y + ", z : " + z;
    }
}
```

- `@Override` 를 붙이면 이름 오타 등으로 오버라이딩이 안 됐을 때 **컴파일 에러**로 알려 준다. 항상 붙이는 것이 좋다.

## 오버라이딩의 조건

| 조건 | 설명 |
| --- | --- |
| **선언부 일치** | 이름, 매개변수, 반환 타입이 조상과 **같아야** 한다 (반환 타입은 자손 타입으로 좁히는 것 가능 = 공변 반환 타입) |
| **접근 제어자** | 조상보다 **좁게 바꿀 수 없다** (조상이 `protected` 면 자손은 `protected` 나 `public` 만) |
| **예외** | 조상보다 **많은(넓은) 예외를 선언할 수 없다** |
| **static** | 인스턴스 메서드 ↔ static 메서드로 바꿀 수 없다 |

```java
class Parent {
    protected void method() throws IOException { }
}

class Child extends Parent {
    void method() { }                       // 에러: protected → default 로 좁힘
    public void method() throws Exception { }  // 에러: Exception 은 IOException 보다 넓다
    public void method() { }                // OK: 접근 범위 넓힘, 예외 없음
}
```

> 조상의 **static 메서드**를 자손에 같은 이름으로 정의하면 오버라이딩이 아니라 **숨김(hiding)**이다. 각 클래스에 별개로 존재한다.

## 오버로딩 vs 오버라이딩

| 구분 | 오버로딩 (Overloading) | 오버라이딩 (Overriding) |
| --- | --- | --- |
| 의미 | 기존에 없는 **새 메서드를 정의** (new) | 상속받은 메서드의 **내용을 변경** (change, modify) |
| 위치 | 같은 클래스 (또는 상속 관계) | **상속 관계** |
| 이름 | 같다 | 같다 |
| 매개변수 | **달라야** 한다 (개수 또는 타입) | **같아야** 한다 |
| 반환 타입 | 상관없다 | 같아야 한다 (공변 반환 가능) |

```java
class Parent {
    void parentMethod() { }
}

class Child extends Parent {
    void parentMethod() { }          // 오버라이딩
    void parentMethod(int i) { }     // 오버로딩

    void childMethod() { }
    void childMethod(int i) { }      // 오버로딩
    void childMethod() { }           // 에러: 중복 정의
}
```

## super

**자손 클래스에서 조상 클래스로부터 상속받은 멤버를 가리키는** 참조 변수이다.

- 멤버 변수와 지역 변수 이름이 같을 때 `this` 로 구분하듯, 상속받은 멤버와 자신의 멤버 이름이 같을 때 **`super`** 로 구분한다.
- `this` 처럼 **static 메서드에서는 사용할 수 없다.**

```java
class Parent { int x = 10; }

class Child extends Parent {
    int x = 20;

    void method() {
        System.out.println(x);        // 20 (자신의 x)
        System.out.println(this.x);   // 20
        System.out.println(super.x);  // 10 (조상의 x)
    }
}
```

### 조상 메서드를 확장할 때

```java
class Point3D extends Point {
    @Override
    String getLocation() {
        return super.getLocation() + ", z : " + z;   // 조상 메서드를 호출하고 내용을 덧붙임
    }
}
```

## super(): 조상 클래스의 생성자

자손 생성자에서 **조상의 생성자를 호출**할 때 쓴다.

- 생성자는 상속되지 않으므로, 조상 멤버의 초기화는 **조상의 생성자**가 해야 한다.
- **모든 생성자의 첫 줄**에는 `this()` 또는 `super()` 가 있어야 한다. 없으면 컴파일러가 **`super();`** 를 자동으로 넣는다.

```java
class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
}

class Point3D extends Point {
    int z;

    Point3D(int x, int y, int z) {
        super(x, y);     // 조상 생성자 Point(int, int) 호출 → 반드시 첫 줄
        this.z = z;
    }
}
```

### 자주 나는 에러

```java
class Point {
    int x, y;
    Point(int x, int y) { ... }      // 매개변수 있는 생성자만 있음 → 기본 생성자 없음
}

class Point3D extends Point {
    Point3D(int x, int y, int z) {
        // 컴파일러가 super(); 를 자동으로 넣음
        // → Point() 가 없으므로 컴파일 에러
        this.z = z;
    }
}
```

- 해결: `super(x, y)` 를 직접 호출하거나, 조상에 기본 생성자 `Point() {}` 를 추가한다.

### 생성자 호출 순서

```text
new Point3D(1, 2, 3)
   → Point3D() 첫 줄: super(1, 2)
       → Point() 첫 줄: super()
           → Object()
       ← Point 초기화
   ← Point3D 초기화
```

- **조상 → 자손 순서**로 초기화된다. 맨 위에는 항상 Object 의 생성자가 있다.

# 3. package 와 import

## 패키지 (package)

**서로 관련된 클래스의 묶음**이다. 클래스를 그룹 단위로 관리하고, **같은 이름의 클래스 충돌**을 막는다.

- 클래스의 실제 이름(Full Name)은 **패키지명을 포함**한다. 예: `java.lang.String`
- 패키지는 **물리적으로 디렉터리**이다. `java.lang.String` → `java/lang/String.class`
- 패키지 안에 다른 패키지를 둘 수 있다 (`.` 으로 구분).

## 패키지의 선언

```java
package com.example.shop.order;   // 소스 파일의 맨 첫 줄 (주석, 공백 제외), 파일당 하나

public class Order { }
```

- 패키지명은 **소문자**로 쓰는 것이 관례이다. 보통 **회사 도메인을 거꾸로** 쓴다 (`com.example...`).
- 패키지를 선언하지 않으면 **이름 없는 패키지(unnamed package)**에 속한다. 연습용 외에는 쓰지 않는다.

## import 문

다른 패키지의 클래스를 쓸 때 **패키지명을 생략**할 수 있게 해 준다.

```java
// import 없이
java.util.Date today = new java.util.Date();

// import 사용
import java.util.Date;
Date today = new Date();
```

## import 문의 선언

```java
package com.example;      // 1. package 문

import java.util.Date;    // 2. import 문 (여러 개 가능)
import java.util.*;       //    패키지의 모든 클래스

public class Main { }     // 3. 클래스 선언
```

| 규칙 | 설명 |
| --- | --- |
| 위치 | package 문 **다음**, 클래스 선언 **전** |
| `*` 의 범위 | 그 패키지의 클래스만. **하위 패키지는 포함하지 않는다** (`import java.*;` 로 `java.util` 을 가져올 수 없다) |
| 성능 | `*` 를 써도 실행 성능 차이는 없다. 컴파일 시간만 약간 차이 |
| 자동 import | **`java.lang`** 패키지는 import 없이 쓸 수 있다 (`String`, `System`, `Math` ...) |
| 이름 충돌 | 두 패키지에 같은 이름의 클래스가 있으면 패키지명을 붙여 구분한다 |

## static import 문

**static 멤버**를 쓸 때 **클래스 이름까지 생략**할 수 있게 해 준다.

```java
import static java.lang.Math.random;
import static java.lang.Math.*;
import static java.lang.System.out;

out.println(random());   // System.out.println(Math.random()) 과 같다
```

- 테스트 코드에서 `import static org.assertj.core.api.Assertions.*;` 처럼 자주 쓴다.

# 4. 제어자 (Modifier)

## 제어자란?

클래스, 변수, 메서드의 선언부에 붙어 **부가적인 의미**를 더한다.

| 종류 | 제어자 |
| --- | --- |
| **접근 제어자** | `public`, `protected`, (default), `private` → **하나만** 사용 가능 |
| **그 외** | `static`, `final`, `abstract`, `native`, `transient`, `synchronized`, `volatile`, `strictfp` |

- 하나의 대상에 여러 제어자를 조합할 수 있다. 순서는 상관없지만 보통 **접근 제어자를 맨 앞**에 쓴다.

---

## static: 클래스의, 공통적인

**인스턴스가 아니라 클래스에 속한다.** 모든 인스턴스가 공유한다.

| 대상 | 의미 |
| --- | --- |
| 멤버 변수 | 모든 인스턴스가 공유하는 **클래스 변수**. 인스턴스 없이 사용 가능. 클래스가 메모리에 올라갈 때 생성 |
| 메서드 | 인스턴스 없이 호출 가능한 **클래스 메서드**. 메서드 안에서 인스턴스 멤버를 직접 쓸 수 없다 |
| 초기화 블록 | `static { }` 클래스가 로딩될 때 **한 번** 실행 |

> 자세히 → [[04. 객체지향 I]] 클래스 변수, 클래스 메서드

---

## final: 마지막의, 변경될 수 없는

| 대상 | 의미 | 예 |
| --- | --- | --- |
| **클래스** | 상속할 수 없다 (자손을 만들 수 없다) | `String`, `Math` |
| **메서드** | 오버라이딩할 수 없다 | |
| **변수** | 값을 바꿀 수 없는 **상수** | `final int MAX = 10;` |

```java
final class FinalTest {               // 조상이 될 수 없는 클래스
    final int MAX_SIZE = 10;          // 값을 바꿀 수 없는 멤버 변수

    final void getMaxSize() {         // 오버라이딩할 수 없는 메서드
        final int LV = MAX_SIZE;      // 값을 바꿀 수 없는 지역 변수
    }
}
```

### 생성자로 final 멤버 변수 초기화

- final 인스턴스 변수는 선언할 때 초기화하지 않고 **생성자에서 한 번** 초기화할 수 있다.
- 인스턴스마다 다른 값을 가지는 상수를 만들 수 있다.

```java
class Card {
    final int NUMBER;          // 상수지만 선언 때 초기화하지 않음
    final String KIND;

    Card(String kind, int num) {
        KIND = kind;           // 생성자에서 한 번만 초기화
        NUMBER = num;
    }
}

Card c = new Card("HEART", 10);
c.NUMBER = 5;                  // 에러: final 변수는 바꿀 수 없다
```

> 참조형 변수에 `final` 을 붙이면 **다른 객체를 가리키도록 바꿀 수 없을 뿐**, 객체 안의 값은 바꿀 수 있다. (`final int[] arr = {1}; arr[0] = 2;` 는 OK)

---

## abstract: 추상의, 미완성의

| 대상 | 의미 |
| --- | --- |
| 클래스 | 클래스 안에 **추상 메서드가 선언되어 있음**을 의미. 인스턴스를 만들 수 없다 |
| 메서드 | 선언부만 있고 **구현부가 없는** 메서드 |

> 자세히 → 아래 6. 추상 클래스

## 접근 제어자 (Access Modifier)

멤버 또는 클래스를 **외부에서 접근하지 못하도록 제한**한다.

| 제어자 | 같은 클래스 | 같은 패키지 | 자손 클래스 (다른 패키지) | 전체 |
| --- | --- | --- | --- | --- |
| `public` | O | O | O | O |
| `protected` | O | O | O | X |
| (default) | O | O | X | X |
| `private` | O | X | X | X |

```text
접근 범위 넓음 ◀──────────────────────────────▶ 좁음
   public  >  protected  >  (default)  >  private
```

![Classes and packages used to illustrate access levels](https://docs.oracle.com/javase/tutorial/figures/java/classes-access.gif)

*Alpha 의 멤버에 누가 접근할 수 있는가 (출처: Oracle, The Java Tutorials, Controlling Access to Members of a Class)*

| Alpha 멤버의 제어자 | Alpha | Beta (같은 패키지) | AlphaSub (다른 패키지, 자손) | Gamma (다른 패키지) |
| --- | --- | --- | --- | --- |
| `public` | O | O | O | O |
| `protected` | O | O | O | X |
| (default) | O | O | X | X |
| `private` | O | X | X | X |

| 대상 | 사용 가능한 접근 제어자 |
| --- | --- |
| 클래스 | `public`, (default) |
| 메서드, 멤버 변수 | 네 가지 모두 |
| 지역 변수 | 없음 |

### 접근 제어자를 쓰는 이유: 캡슐화

- 외부에서 데이터를 **함부로 바꾸지 못하게** 보호한다.
- 외부에 보일 필요가 없는 **내부 구현을 숨긴다.**

```java
public class Time {
    private int hour;                         // 외부에서 직접 접근 불가

    public int getHour() { return hour; }     // getter: 읽기
    public void setHour(int hour) {           // setter: 검증 후 쓰기
        if (hour < 0 || hour > 23) return;
        this.hour = hour;
    }
}
```

### 생성자의 접근 제어자

- 생성자를 `private` 으로 하면 **외부에서 인스턴스를 만들 수 없다.**
- 대신 클래스 안에서 인스턴스를 만들어 `public static` 메서드로 제공한다 → **싱글톤 패턴**.
- 생성자가 private 이면 자손 생성자가 `super()` 를 호출할 수 없으므로 상속도 불가능하다 (클래스에 `final` 을 함께 붙이는 것이 좋다).

```java
final class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() { }
    public static Singleton getInstance() { return INSTANCE; }
}
```

---

## 제어자의 조합

| 대상 | 사용 가능한 제어자 |
| --- | --- |
| 클래스 | `public`, (default), `final`, `abstract` |
| 메서드 | 모든 접근 제어자, `final`, `abstract`, `static` |
| 멤버 변수 | 모든 접근 제어자, `final`, `static` |
| 지역 변수 | `final` |

### 함께 쓸 수 없는 조합

| 조합 | 이유 |
| --- | --- |
| `abstract` + `static` 메서드 | static 메서드는 구현부가 있어야 한다 |
| `abstract` + `final` 클래스 | final 은 확장 불가, abstract 는 확장해서 완성해야 함 → 모순 |
| `abstract` + `private` 메서드 | abstract 는 자손이 구현해야 하는데 private 은 자손이 접근 불가 |
| `private` + `final` 메서드 | 오류는 아니지만 의미 중복. private 메서드는 이미 오버라이딩 불가 |

# 5. 다형성 (Polymorphism)

## 다형성이란?

**여러 가지 형태를 가질 수 있는 능력**. 자바에서는 **조상 타입의 참조 변수로 자손 타입의 객체를 다룰 수 있는 것**을 말한다.

```java
class Tv { boolean power; int channel; void power() {} void channelUp() {} void channelDown() {} }
class SmartTv extends Tv { String text; void caption() {} }

SmartTv s = new SmartTv();   // 타입 일치
Tv      t = new SmartTv();   // 조상 타입 참조 변수로 자손 객체 → OK (다형성)
SmartTv x = new Tv();        // 에러: 자손 타입 참조 변수로 조상 객체 불가
```

```text
Tv t = new SmartTv();

 t ──▶ ┌─────────────────────────┐
       │ power, channel           │  ← t 로 쓸 수 있는 부분 (Tv 의 멤버)
       │ power(), channelUp() ... │
       ├─────────────────────────┤
       │ text, caption()          │  ← 객체에는 있지만 t 로는 쓸 수 없음
       └─────────────────────────┘
```

- **참조 변수의 타입**이 사용할 수 있는 **멤버의 개수**를 결정한다.
- 자손 타입 참조 변수가 조상 객체를 가리키면, 존재하지 않는 멤버를 쓰려 할 수 있어 **허용하지 않는다.**

---

## 참조 변수의 형변환

**상속 관계**에 있는 클래스끼리만 참조 변수를 형변환할 수 있다.

| 방향 | 이름 | 형변환 연산자 |
| --- | --- | --- |
| 자손 → 조상 | **업캐스팅 (Up-casting)** | **생략 가능** |
| 조상 → 자손 | **다운캐스팅 (Down-casting)** | **생략 불가** |

```java
SmartTv s = new SmartTv();
Tv t = s;                    // 업캐스팅: (Tv) 생략 가능
SmartTv s2 = (SmartTv) t;    // 다운캐스팅: (SmartTv) 필수

Tv t2 = new Tv();
SmartTv s3 = (SmartTv) t2;   // 컴파일 OK, 실행 시 ClassCastException
```

- 형변환은 **참조 변수의 타입만 바꾸는 것**이다. 인스턴스는 바뀌지 않는다.
- 다운캐스팅은 **실제 인스턴스가 그 타입(또는 자손)일 때만** 성공한다. 아니면 **ClassCastException**.
- 그래서 다운캐스팅 전에는 **`instanceof`** 로 확인한다.

---

## instanceof 연산자

참조 변수가 가리키는 **실제 인스턴스의 타입**을 확인한다.

```java
void doWork(Tv t) {
    if (t instanceof SmartTv) {           // true 면 SmartTv 로 형변환 가능
        SmartTv s = (SmartTv) t;
        s.caption();
    }
}
```

- `참조변수 instanceof 타입` 이 **true** 면 그 타입으로 **형변환이 가능**하다는 뜻이다.
- 조상 타입에 대해서도 true 다: `new SmartTv() instanceof Tv` → true, `instanceof Object` → true.
- `null instanceof 아무타입` → false.

### 패턴 매칭 instanceof (Java 16+)

```java
if (t instanceof SmartTv s) {   // 검사 + 형변환 + 변수 선언을 한 번에
    s.caption();
}
```

---

## 참조 변수와 인스턴스의 연결

조상과 자손에 **같은 이름의 멤버**가 있을 때, 참조 변수의 타입에 따라 결과가 다르다.

| 멤버 | 무엇을 기준으로 결정 |
| --- | --- |
| **멤버 변수** | **참조 변수의 타입** |
| **인스턴스 메서드** (오버라이딩) | **실제 인스턴스의 타입** |

```java
class Parent {
    int x = 100;
    void method() { System.out.println("Parent Method"); }
}

class Child extends Parent {
    int x = 200;
    @Override
    void method() { System.out.println("Child Method"); }
}

Parent p = new Child();
Child  c = new Child();

p.x          // 100  ← 참조 변수 타입(Parent)의 x
c.x          // 200
p.method()   // Child Method  ← 실제 인스턴스(Child)의 메서드
c.method()   // Child Method
```

- 메서드는 오버라이딩되면 **항상 실제 인스턴스의 메서드**가 호출된다 (동적 바인딩).
- 변수는 그렇지 않으므로, 멤버 변수는 `private` 으로 두고 메서드로 접근하는 것이 좋다.
- static 메서드도 참조 변수 타입을 따른다 (그래서 `클래스명.메서드()` 로 호출하는 것이 권장된다).

---

## 매개변수의 다형성

메서드의 매개변수를 **조상 타입**으로 선언하면 모든 자손 객체를 받을 수 있다.

```java
class Product { int price; int bonusPoint; }
class Tv       extends Product { }
class Computer extends Product { }
class Audio    extends Product { }

class Buyer {
    int money = 1000;
    int bonusPoint = 0;

    // 제품마다 buy(Tv), buy(Computer), buy(Audio) 를 만들 필요가 없다
    void buy(Product p) {
        money -= p.price;
        bonusPoint += p.bonusPoint;
    }
}

Buyer b = new Buyer();
b.buy(new Tv());
b.buy(new Computer());
```

- 새 제품 클래스가 추가돼도 Buyer 를 **고치지 않아도 된다.**

---

## 여러 종류의 객체를 배열로 다루기

조상 타입의 배열에 **여러 자손 객체**를 함께 담을 수 있다.

```java
Product[] cart = new Product[10];
cart[0] = new Tv();
cart[1] = new Computer();
cart[2] = new Audio();

int sum = 0;
for (Product p : cart) {
    if (p == null) break;
    sum += p.price;
}
```

- 실무에서는 길이가 고정된 배열 대신 **`List<Product>`** 를 쓴다 (→ 컬렉션 프레임워크).

# 6. 추상 클래스 (Abstract Class)

## 추상 클래스란?

**미완성 설계도**. 미완성 메서드(추상 메서드)를 포함한 클래스이다.

- **인스턴스를 생성할 수 없다.** 상속을 통해 자손이 완성해야 한다.
- 생성자, 멤버 변수, 일반 메서드를 **가질 수 있다.** (일반 클래스 + 추상 메서드)
- 추상 메서드가 없어도 `abstract` 를 붙여 인스턴스 생성을 막을 수 있다.

```java
abstract class Player {
    boolean pause;
    int currentPos;

    Player() { currentPos = 0; }            // 생성자 가능

    abstract void play(int pos);            // 추상 메서드
    abstract void stop();

    void pause() { pause = !pause; }        // 일반 메서드 가능
}

Player p = new Player();   // 에러: 추상 클래스는 인스턴스 생성 불가
```

## 추상 메서드

**선언부만 있고 구현부가 없는** 메서드이다. 꼭 필요하지만 **자손마다 다르게 구현될 것**으로 예상될 때 쓴다.

```java
abstract 반환타입 메서드이름();   // { } 대신 ; 로 끝남
```

- 자손은 조상의 추상 메서드를 **모두 구현**해야 한다. 하나라도 구현하지 않으면 자손도 **abstract** 를 붙여야 한다.

```java
class AudioPlayer extends Player {
    @Override void play(int pos) { /* 구현 */ }
    @Override void stop()        { /* 구현 */ }
}

abstract class AbstractPlayer extends Player {
    @Override void play(int pos) { /* 구현 */ }
    // stop() 미구현 → abstract 필수
}
```

## 추상 클래스의 작성

여러 클래스에 공통으로 쓰이는 부분을 **뽑아서** 추상 클래스로 만든다 (추상화).

```java
// 공통 부분이 중복된 클래스들
class Marine   { int x, y; void move(int x, int y) { } void stop() { } void stimPack() { } }
class Tank     { int x, y; void move(int x, int y) { } void stop() { } void changeMode() { } }
class Dropship { int x, y; void move(int x, int y) { } void stop() { } void load() { } }

// 공통 부분을 추상 클래스로 추출
abstract class Unit {
    int x, y;
    abstract void move(int x, int y);   // 이동 방식은 유닛마다 다름 → 추상 메서드
    void stop() { /* 공통 구현 */ }
}

class Marine   extends Unit { void move(int x, int y) { /* 걷기 */ } void stimPack() { } }
class Tank     extends Unit { void move(int x, int y) { /* 바퀴 */ } void changeMode() { } }
class Dropship extends Unit { void move(int x, int y) { /* 비행 */ } void load() { } }

Unit[] group = { new Marine(), new Tank(), new Dropship() };
for (Unit u : group) u.move(100, 200);   // 다형성: 각자의 move() 가 호출됨
```

![Classes Rectangle, Line, Bezier, and Circle Inherit from GraphicObject](https://docs.oracle.com/javase/tutorial/figures/java/classes-graphicObject.gif)

*추상 클래스 예: 공통 상태(위치)와 공통 동작(moveTo)은 GraphicObject 에, 그리는 방법(draw)은 각 도형이 구현 (출처: Oracle, The Java Tutorials, Abstract Methods and Classes)*

# 7. 인터페이스 (Interface)

## 인터페이스란?

**추상 메서드의 집합**. 구현된 것이 없는 **기본 설계도**이며, 클래스가 **지켜야 할 규칙(약속)**을 정한다.

| 구분 | 추상 클래스 | 인터페이스 |
| --- | --- | --- |
| 비유 | 미완성 설계도 | 기본 설계도 (규칙) |
| 멤버 변수 | 가질 수 있다 | **상수만** (`public static final`) |
| 생성자 | 있다 | **없다** |
| 일반 메서드 | 있다 | default, static, private 메서드만 (Java 8/9+) |
| 상속 | `extends` 하나만 | `implements` **여러 개** 가능 |
| 관계 | is-a (~이다) | can-do (~할 수 있다) |

## 인터페이스의 작성

```java
interface 인터페이스이름 {
    public static final 타입 상수이름 = 값;
    public abstract 메서드이름(매개변수);
}
```

- 모든 멤버 변수는 **`public static final`**, 생략 가능.
- 모든 추상 메서드는 **`public abstract`**, 생략 가능. (default, static, private 메서드는 예외)
- 생략하면 **컴파일러가 자동으로 추가**한다.

```java
interface PlayingCard {
    int SPADE = 4;                      // public static final int SPADE = 4;
    String getCardKind();               // public abstract String getCardKind();
}
```

## 인터페이스의 상속

- 인터페이스는 **인터페이스로부터만** 상속받을 수 있다.
- 클래스와 달리 **다중 상속**이 가능하다. (구현이 없어 충돌 문제가 없다)
- Object 같은 최고 조상이 없다.

```java
interface Movable   { void move(int x, int y); }
interface Attackable { void attack(Unit u); }
interface Fightable extends Movable, Attackable { }   // 두 인터페이스의 멤버를 모두 상속
```

## 인터페이스의 구현

```java
class Fighter implements Fightable {
    public void move(int x, int y) { /* 구현 */ }   // public 필수
    public void attack(Unit u)     { /* 구현 */ }
}

// 상속과 구현을 동시에
class Fighter extends Unit implements Fightable { ... }

// 일부만 구현하면 abstract 클래스로
abstract class Fighter implements Fightable {
    public void move(int x, int y) { }
}
```

- 구현하는 메서드는 반드시 **`public`** 이어야 한다. 인터페이스 메서드가 public 이므로 더 좁게 바꿀 수 없다 (오버라이딩 규칙).

## 인터페이스를 이용한 다중 상속

- 자바는 클래스 다중 상속은 안 되지만, **인터페이스는 여러 개 구현**할 수 있다.
- 두 클래스의 기능이 모두 필요하면, 하나는 **상속**하고 하나는 **포함 + 인터페이스**로 해결한다.

```java
class Tv  { void power() { } void channelUp() { } }
interface IVCR { void play(); void stop(); }
class VCR implements IVCR { public void play() { } public void stop() { } }

class TVCR extends Tv implements IVCR {
    VCR vcr = new VCR();                  // 포함
    public void play() { vcr.play(); }    // 구현은 VCR 에 맡김
    public void stop() { vcr.stop(); }
}
```

## 인터페이스를 이용한 다형성

- 인터페이스 타입의 참조 변수로 **그 인터페이스를 구현한 클래스의 객체**를 가리킬 수 있다.
- 인터페이스를 **매개변수 타입**이나 **반환 타입**으로 쓸 수 있다.

```java
Fightable f = new Fighter();          // 인터페이스 타입 참조 변수

void attack(Fightable f) { ... }      // Fightable 을 구현한 객체만 받음

Fightable method() {                  // Fightable 을 구현한 객체를 반환
    return new Fighter();
}
```

> **반환 타입이 인터페이스**라는 것은 "그 인터페이스를 구현한 클래스의 인스턴스를 반환한다"는 뜻이다.

## 인터페이스의 장점

| 장점 | 설명 |
| --- | --- |
| **개발 시간 단축** | 선언부만 정해지면 사용하는 쪽과 구현하는 쪽이 **동시에** 개발할 수 있다 |
| **표준화** | 기본 틀을 정해 일관된 프로그램을 만든다 (JDBC 가 대표 예) |
| **관계없는 클래스 연결** | 공통 조상이 없는 클래스들을 같은 인터페이스로 묶을 수 있다 |
| **독립적인 프로그래밍** | 선언과 구현이 분리되어, 구현을 바꿔도 사용하는 쪽은 **고치지 않아도 된다** |

### 관계없는 클래스 묶기 예

```java
interface Repairable { }

class Tank     extends GroundUnit implements Repairable { }
class Dropship extends AirUnit    implements Repairable { }
class Marine   extends GroundUnit { }          // 수리 불가

void repair(Repairable r) { ... }               // Tank, Dropship 만 받을 수 있다
```

## 인터페이스의 이해

핵심은 두 가지다.

1. 클래스를 **사용하는 쪽(User)**과 **제공하는 쪽(Provider)**이 있다.
2. 사용하는 쪽은 **선언부(인터페이스)만 알면** 된다. 실제 구현 클래스는 몰라도 된다.

```java
// 직접 의존: B 가 C 로 바뀌면 A 도 고쳐야 한다
class A {
    void methodA(B b) { b.methodB(); }
}

// 인터페이스에 의존: B 가 C 로 바뀌어도 A 는 그대로
interface I { void methodB(); }
class B implements I { public void methodB() { } }
class C implements I { public void methodB() { } }

class A {
    void methodA(I i) { i.methodB(); }
}
```

```text
직접 관계                 간접 관계
A ──▶ B                  A ──▶ I ◀── B
                                 ◀── C
                         (A 는 I 만 안다 → 결합도 낮음)
```

> 스프링의 **DI(의존성 주입)**가 바로 이 원리다. `OrderService` 가 `PaymentRepository` 인터페이스에만 의존하고, 실제 구현체는 스프링이 넣어 준다.

## default 메서드, static 메서드, private 메서드

| 종류 | 도입 | 특징 |
| --- | --- | --- |
| **default 메서드** | Java 8 | 구현부가 있는 메서드. 인터페이스에 새 메서드를 추가해도 **기존 구현 클래스가 깨지지 않는다** |
| **static 메서드** | Java 8 | 인스턴스와 무관. `인터페이스명.메서드()` 로 호출 |
| **private 메서드** | Java 9 | default · static 메서드 안의 **중복 코드를 묶는** 용도. 외부에 공개되지 않음 |

```java
interface MyInterface {
    void method();                                      // 추상 메서드

    default void newMethod() {                          // default 메서드
        log("newMethod");
    }

    static void staticMethod() {                        // static 메서드
        System.out.println("static");
    }

    private void log(String msg) {                      // private 메서드
        System.out.println("[LOG] " + msg);
    }
}
```

### default 메서드 충돌 규칙

| 상황 | 해결 |
| --- | --- |
| 여러 인터페이스의 default 메서드 이름이 같을 때 | 구현 클래스에서 **반드시 오버라이딩** |
| 조상 클래스 메서드와 default 메서드 이름이 같을 때 | **조상 클래스 메서드가 우선** (default 는 무시) |

```java
interface A { default void hello() { System.out.println("A"); } }
interface B { default void hello() { System.out.println("B"); } }

class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();      // 특정 인터페이스의 default 메서드 호출
    }
}
```

# 8. 내부 클래스 (Inner Class)

## 내부 클래스란?

**클래스 안에 선언된 클래스**이다. 두 클래스가 **서로 긴밀한 관계**일 때 쓴다.

```java
class A {          // 외부 클래스
    class B { }    // 내부 클래스: A 에서만 주로 쓰임
}
```

| 장점 | 설명 |
| --- | --- |
| 멤버 접근 | 내부 클래스에서 외부 클래스의 멤버에 **쉽게 접근** (private 포함) |
| 캡슐화 | 외부에 불필요한 클래스를 감춰 **코드 복잡성을 줄인다** |

## 내부 클래스의 종류와 특징

선언 위치에 따라 나뉘며, **변수의 선언 위치와 같은 규칙**을 따른다.

| 종류 | 선언 위치 | 대응하는 변수 | 특징 |
| --- | --- | --- | --- |
| **인스턴스 클래스** | 외부 클래스의 멤버 변수 자리 | 인스턴스 변수 | 외부 클래스의 **인스턴스 멤버**처럼 다룬다 |
| **스태틱 클래스** | 멤버 변수 자리 + `static` | 클래스 변수 | 외부 클래스의 **static 멤버**처럼 다룬다 |
| **지역 클래스** | 메서드, 초기화 블록 안 | 지역 변수 | 선언된 영역 안에서만 사용 |
| **익명 클래스** | 객체 생성과 동시에 | - | 이름 없는 일회용 클래스 |

## 내부 클래스의 선언

```java
class Outer {
    class InstanceInner { }           // 인스턴스 클래스
    static class StaticInner { }      // 스태틱 클래스

    void myMethod() {
        class LocalInner { }          // 지역 클래스
    }
}
```

### 외부에서 생성하기

```java
Outer outer = new Outer();
Outer.InstanceInner ii = outer.new InstanceInner();   // 외부 인스턴스가 먼저 있어야 함

Outer.StaticInner si = new Outer.StaticInner();        // 외부 인스턴스 없이 가능
```

## 내부 클래스의 제어자와 접근성

- 인스턴스 · 스태틱 클래스는 **멤버**이므로 `private`, `protected` 등 **모든 접근 제어자**를 쓸 수 있다.

### 접근 규칙

| 내부 클래스 | 외부 클래스의 인스턴스 멤버 | 외부 클래스의 static 멤버 |
| --- | --- | --- |
| 인스턴스 클래스 | **O** | O |
| 스태틱 클래스 | **X** (인스턴스 없이 존재하므로) | O |
| 지역 클래스 | O (인스턴스 메서드 안이면) | O |

- static 메서드에서 static 이 아닌 멤버를 못 쓰는 것과 같은 원리다.

### 지역 클래스와 지역 변수

- 지역 클래스는 메서드의 지역 변수 중 **final 이거나 사실상 final(effectively final)**인 것만 쓸 수 있다.
- 이유: 메서드가 끝나 지역 변수가 사라진 뒤에도 지역 클래스의 객체는 남아 있을 수 있기 때문이다 (값을 복사해서 쓴다).

```java
void myMethod() {
    int lv = 0;            // 한 번도 바꾸지 않으면 effectively final
    class LocalInner {
        int v = lv;        // OK
    }
    // lv = 1;             // 이 줄이 있으면 위의 lv 사용이 에러
}
```

### 이름이 같을 때: `외부클래스.this`

```java
class Outer {
    int value = 10;
    class Inner {
        int value = 20;
        void method() {
            int value = 30;
            System.out.println(value);              // 30 (지역 변수)
            System.out.println(this.value);         // 20 (Inner 의 멤버)
            System.out.println(Outer.this.value);   // 10 (Outer 의 멤버)
        }
    }
}
```

## 익명 클래스 (Anonymous Class)

**이름이 없는 일회용 클래스**. 클래스 선언과 객체 생성을 **동시에** 한다.

```java
new 조상클래스이름() { /* 멤버 선언 */ }
new 구현인터페이스이름() { /* 멤버 선언 */ }
```

- 이름이 없으니 **생성자를 가질 수 없다.**
- 하나의 클래스를 상속하거나 **하나의 인터페이스만** 구현할 수 있다.

```java
// 익명 클래스: 인터페이스를 구현하면서 바로 객체 생성
Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("익명 클래스");
    }
};

// Java 8+ 람다: 추상 메서드가 하나뿐인 인터페이스는 더 짧게
Runnable r2 = () -> System.out.println("람다");
```

> 추상 메서드가 하나인 인터페이스(함수형 인터페이스)를 익명 클래스로 구현하는 코드는 대부분 **람다**로 바뀌었다. (→ 람다와 스트림)

# 핵심 정리

- 상속은 **is-a**, 포함은 **has-a**. 자바는 **단일 상속**, 모든 클래스의 조상은 **Object**.
- 생성자는 상속되지 않는다. 모든 생성자 첫 줄은 `this()` 또는 `super()`, 없으면 `super()` 자동 추가.
- 오버라이딩: 선언부 같게, 접근 제어자는 **좁게 X**, 예외는 **많게 X**. 오버로딩: 이름 같고 **매개변수 다르게**.
- 접근 범위: `public` > `protected` > (default) > `private`.
- `final` 클래스는 상속 X, 메서드는 오버라이딩 X, 변수는 변경 X. `abstract` + `final`, `abstract` + `static`, `abstract` + `private` 불가.
- 다형성: 조상 타입 참조 변수로 자손 객체. 업캐스팅 생략 가능, 다운캐스팅은 `instanceof` 확인 후.
- 같은 이름 멤버: 변수는 **참조 변수 타입**, 오버라이딩된 메서드는 **실제 인스턴스 타입**을 따른다.
- 추상 클래스: 인스턴스 생성 X, 생성자·변수·일반 메서드 O. 인터페이스: 상수 + 추상 메서드 (+ default/static/private), **다중 구현 가능**.
- 인터페이스에 의존하면 구현을 바꿔도 사용하는 쪽은 그대로 → 스프링 DI 의 원리.
- 내부 클래스는 변수처럼 4종류. 지역·익명 클래스는 **effectively final** 지역 변수만 사용. 익명 클래스는 대부분 람다로 대체.
