## 개요

자바 프로그램의 **기본이 되는 클래스**들이 모인 `java.lang` 패키지와, 실무에서 자주 쓰는 `java.util`, `java.math` 의 유용한 클래스들을 정리한다.

| 패키지 | 클래스 | 한 줄 요약 |
| --- | --- | --- |
| `java.lang` | **Object** | 모든 클래스의 조상. `equals`, `hashCode`, `toString` |
| | **String** | 변경할 수 없는(immutable) 문자열 |
| | **StringBuilder / StringBuffer** | 변경할 수 있는 문자열 |
| | **Math** | 수학 계산 static 메서드 모음 |
| | **래퍼 클래스** | 기본형을 객체로 감싼 클래스 (`Integer`, `Double` ...) |
| `java.util` | **Objects** | null 안전한 Object 보조 메서드 |
| | **Random** | 난수 생성 |
| | **regex** (`Pattern`, `Matcher`) | 정규식 |
| | **Scanner** | 입력 읽기 |
| | **StringTokenizer** | 문자열을 구분자로 자르기 (레거시) |
| `java.math` | **BigInteger** | 아주 큰 정수 |
| | **BigDecimal** | 오차 없는 실수 (**돈 계산**) |

# 1. java.lang 패키지

- 자바 프로그래밍에 **가장 기본이 되는 클래스**들을 포함한다.
- **import 없이** 사용할 수 있다. 컴파일러가 `import java.lang.*;` 를 자동으로 넣는다. (→ [[5. 객체지향 II]] import)
- 예: `Object`, `String`, `StringBuilder`, `Math`, `Integer`, `System`, `Thread`, `Exception` ...

## Object 클래스

모든 클래스의 **최고 조상**이다. 그래서 Object 의 메서드는 **모든 객체**에서 쓸 수 있다. 멤버 변수는 없고 메서드만 11개 있다.

| 메서드 | 설명 |
| --- | --- |
| `boolean equals(Object obj)` | 같은 객체인지 비교 |
| `int hashCode()` | 객체의 해시코드 |
| `String toString()` | 객체 정보를 문자열로 |
| `Class<?> getClass()` | 객체의 클래스 정보(Class 객체) |
| `Object clone()` | 객체 복사 |
| `void finalize()` | GC 직전 호출 (**Java 9 에서 deprecated**, 쓰지 않음) |
| `notify()`, `notifyAll()`, `wait()` | 쓰레드 동기화용 (→ 쓰레드) |

### equals()

```java
public boolean equals(Object obj) {
    return (this == obj);       // Object 의 기본 구현: 주소 비교
}
```

- 기본 구현은 `==` 와 같다. **같은 객체(같은 주소)인지**만 본다.
- **값이 같으면 같다고 판단**하려면 **오버라이딩**해야 한다. String, Integer 등은 이미 오버라이딩되어 있다.

```java
class Person {
    long id;

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Person p)) return false;   // 타입 확인 + 형변환 (Java 16+)
        return this.id == p.id;                          // id 가 같으면 같은 사람
    }
}
```

### hashCode()

- 객체를 **해시 기반 컬렉션**(`HashMap`, `HashSet`)에 저장할 때 위치를 찾는 데 쓰는 정수값이다.
- Object 의 기본 구현은 객체마다 다른 값을 돌려준다 (보통 주소 기반).

#### equals 와 hashCode 의 약속 (가장 중요)

| 규칙 | 내용 |
| --- | --- |
| 1 | `equals()` 가 **true** 인 두 객체는 **hashCode() 가 같아야** 한다 |
| 2 | hashCode() 가 같다고 equals() 가 true 일 필요는 없다 (해시 충돌) |

> **equals 를 오버라이딩하면 hashCode 도 반드시 오버라이딩한다.**

```java
Person p1 = new Person(1L);
Person p2 = new Person(1L);

Set<Person> set = new HashSet<>();
set.add(p1);
set.add(p2);
set.size();     // equals 만 오버라이딩하면 2 (같은 사람이 두 번 들어감)
                // hashCode 도 오버라이딩하면 1

@Override
public int hashCode() {
    return Objects.hash(id);     // java.util.Objects 로 간단히
}
```

```text
HashSet 이 중복을 확인하는 순서
1. hashCode() 로 저장 위치(버킷)를 찾는다   ← hashCode 가 다르면 다른 버킷 → 중복 검사 자체를 안 함
2. 같은 버킷 안에서 equals() 로 비교한다
```

### toString()

```java
public String toString() {
    return getClass().getName() + "@" + Integer.toHexString(hashCode());   // 기본: Person@1b6d3586
}
```

- `System.out.println(obj)`, `"" + obj` 처럼 문자열이 필요하면 **자동으로 호출**된다.
- 디버깅·로그용으로 **오버라이딩**해서 의미 있는 정보를 보여 준다.

```java
@Override
public String toString() {
    return "Person{id=" + id + "}";
}
```

### getClass()

- 객체의 **Class 객체**(클래스 정보)를 반환한다. 클래스 이름, 필드, 메서드 정보를 얻을 수 있다 → **리플렉션**의 시작점.
- `Person.class` 로도 Class 객체를 얻는다.

### clone()

- 객체를 복사한다. 쓰려면 `Cloneable` 을 구현하고 오버라이딩해야 하며, 기본은 **얕은 복사**(참조형 멤버는 주소만 복사)다.
- 사용법이 복잡하고 실수가 많아서 **실무에서는 거의 쓰지 않는다.** 대신 **복사 생성자**나 **정적 팩토리**를 쓴다.

```java
Person(Person other) { this.id = other.id; }   // 복사 생성자
```

### 실무 포인트

- `equals`/`hashCode`/`toString` 을 손으로 쓰면 실수하기 쉽다. **IDE 자동 생성**, **Lombok**(`@EqualsAndHashCode`, `@ToString`), **record**(Java 16+, 자동 생성)를 쓴다.

```java
record Point(int x, int y) { }   // equals, hashCode, toString, getter 자동 생성
```

- JPA 엔티티는 지연 로딩 프록시 때문에 equals/hashCode 를 함부로 Lombok 으로 만들면 문제가 생긴다. **id 기반**으로 직접 작성한다. (→ JPA 에서 다시)

## String 클래스

### 변경 불가능한(immutable) 클래스

- String 은 문자열을 내부 배열(`byte[]`, Java 9+)에 저장하고, **한 번 만들어진 문자열은 바뀌지 않는다.**
- 문자열을 바꾸는 것처럼 보이는 연산은 모두 **새 String 객체**를 만든다.

```java
String a = "a";
String b = "b";
a = a + b;      // "a" 가 "ab" 로 바뀌는 게 아니라, 새 객체 "ab" 를 만들고 a 가 그것을 가리킴
```

```text
a ──X──▶ "a"          ("a" 는 그대로, 참조가 끊김)
  └────▶ "ab"         (새로 생성)
b ─────▶ "b"
```

- 불변이라서 **여러 곳에서 공유해도 안전**하다 (쓰레드 안전, HashMap 키로 안전).
- 대신 문자열을 **자주 바꾸면** 객체가 계속 생겨 느려진다 → **StringBuilder** 사용.

### 문자열 리터럴 vs new String()

```java
String str1 = "abc";              // 문자열 상수 풀(String Pool)에 있는 것을 재사용
String str2 = "abc";
String str3 = new String("abc");  // 힙에 항상 새 객체 생성
String str4 = new String("abc");
```

```text
              Heap
            ┌─────────────────────────────────┐
str1 ──┐    │  String Pool                    │
       ├───▶│   ┌───────┐                     │
str2 ──┘    │   │ "abc" │                     │
            │   └───────┘                     │
str3 ──────▶│  ┌───────┐                      │
str4 ──────▶│  ┌───────┐   (서로 다른 객체)     │
            └─────────────────────────────────┘
```

| 비교 | 결과 | 이유 |
| --- | --- | --- |
| `str1 == str2` | **true** | 풀의 같은 객체 |
| `str3 == str4` | **false** | 서로 다른 객체 |
| `str1 == str3` | **false** | 풀 vs 힙 |
| `str3.equals(str4)` | **true** | 내용 비교 |

> 문자열은 **항상 `equals()`** 로 비교한다. (→ [[3. 기초 문법]] `==` vs `equals`)

### 빈 문자열과 null

- `""` 는 길이가 0인 **문자열 객체**, `null` 은 **객체가 없음**.
- 문자열 변수는 null 보다 `""` 로 초기화하는 것이 안전하다.

```java
String s = "";
s.length();         // 0
String n = null;
n.length();         // NullPointerException
```

![Use the charAt method to get a character at a particular index](https://docs.oracle.com/javase/tutorial/figures/java/objects-charAt.gif)

![Use the substring method to get part of a string](https://docs.oracle.com/javase/tutorial/figures/java/objects-substring.gif)

*`"Niagara. O roar again!"` 에서 charAt(), substring(11, 15) → "roar" (끝 인덱스 15 는 포함하지 않음) (출처: Oracle, The Java Tutorials, Manipulating Characters in a String)*

| 메서드 | 예 | 결과 |
| --- | --- | --- |

| `charAt(int)` | `"Hello".charAt(1)` | 'e' |
| `substring(begin, end)` | `"Hello".substring(1, 3)` | "el" (**end 미포함**) |

| `contains(str)` | `"Hello".contains("ell")` | true |

| `repeat(n)` | `"ab".repeat(3)` | "ababab" (Java 11+) |
| `String.valueOf(x)` | `String.valueOf(10)` | "10" |
| `String.format(...)` / `formatted(...)` | `"%d원".formatted(1000)` | "1000원" (formatted 는 Java 15+) |

### 텍스트 블록 (Java 15+)

```java
String json = """
        {
          "name": "kim",
          "age": 20
        }
        """;
```

- 여러 줄 문자열을 `\n` 과 `+` 없이 쓴다. SQL, JSON 을 코드에 넣을 때 편하다.

### 실무 포인트

```java
// 1. null 안전한 비교: 상수를 앞에
if ("ADMIN".equals(role)) { }     // role 이 null 이어도 false
if (role.equals("ADMIN")) { }     // role 이 null 이면 NPE

// 2. split 은 정규식을 받는다
"a.b.c".split(".");               // [] (빈 배열!)  "." 은 정규식에서 '아무 문자'
"a.b.c".split("\\.");             // ["a", "b", "c"]
"a|b".split("\\|");               // | 도 이스케이프 필요

// 3. 반복문 안에서 + 로 이어 붙이지 않는다
String result = "";
for (String s : list) result += s;          // 매번 새 객체 → 느림
StringBuilder sb = new StringBuilder();
for (String s : list) sb.append(s);         // 하나의 객체에 이어 붙임
```

- 한 줄 안의 `"a" + b + "c"` 는 컴파일러가 최적화하므로 그냥 `+` 를 써도 된다. **반복문 안에서 누적할 때만** StringBuilder 를 쓴다.

## StringBuffer, StringBuilder

### 변경 가능한(mutable) 문자열

- 내부에 **버퍼(char 배열)**를 두고 그 안에서 문자열을 **직접 수정**한다. 새 객체를 만들지 않는다.
- 생성할 때 버퍼 크기를 지정할 수 있다. 지정하지 않으면 **16**. 공간이 부족하면 자동으로 늘어난다(새 배열에 복사 → 비용이 든다).

![A string builder's length and capacity](https://docs.oracle.com/javase/tutorial/figures/java/objects-stringBuffer.gif)

*`length()` = 실제 문자 수(9), `capacity()` = 버퍼 크기(16) (출처: Oracle, The Java Tutorials, The StringBuilder Class)*

```java
StringBuilder sb = new StringBuilder("abc");
sb.append("123")          // abc123
  .insert(0, "X")         // Xabc123
  .delete(1, 3)           // Xc123
  .reverse();             // 321cX
String result = sb.toString();
```

| 메서드 | 설명 |
| --- | --- |
| `append(x)` | 끝에 추가. **자기 자신을 반환**해서 연속 호출(메서드 체이닝) 가능 |
| `insert(pos, x)` | 위치에 삽입 |
| `delete(start, end)` / `deleteCharAt(i)` | 삭제 |
| `replace(start, end, str)` | 구간 치환 |
| `reverse()` | 뒤집기 |
| `setLength(n)` | 길이 변경 (`setLength(0)` 으로 비우기) |
| `toString()` | String 으로 변환 |

### StringBuffer vs StringBuilder

| 구분 | StringBuffer | StringBuilder |
| --- | --- | --- |
| 동기화 | **O** (멀티쓰레드 안전) | X |
| 성능 | 상대적으로 느림 | **빠름** |
| 도입 | Java 1.0 | Java 5 |
| 사용 | 여러 쓰레드가 **같은 객체**를 공유할 때 | **대부분의 경우** (지역 변수) |

> 메서드 안의 지역 변수는 쓰레드마다 따로라 동기화가 필요 없다. 그래서 거의 항상 **StringBuilder** 를 쓴다.

### 주의: equals() 가 오버라이딩되어 있지 않다

```java
StringBuilder sb1 = new StringBuilder("abc");
StringBuilder sb2 = new StringBuilder("abc");

sb1.equals(sb2);                                  // false (주소 비교)
sb1.toString().equals(sb2.toString());            // true
sb1.compareTo(sb2) == 0;                          // true (Java 11+)
```

## Math 클래스

수학 계산에 필요한 메서드를 모은 클래스. 생성자가 `private` 이라 인스턴스를 만들 수 없고, **모든 메서드가 static** 이다.

| 메서드 | 예 | 결과 |
| --- | --- | --- |
| `abs(x)` | `Math.abs(-10)` | 10 |
| `max(a, b)` / `min(a, b)` | `Math.max(3, 7)` | 7 |
| `ceil(x)` | `Math.ceil(1.1)` | 2.0 (올림) |
| `floor(x)` | `Math.floor(1.9)` | 1.0 (내림) |
| `round(x)` | `Math.round(1.5)` | 2 (반올림, **long** 반환) |
| `rint(x)` | `Math.rint(2.5)` | 2.0 (가장 가까운 정수, .5 면 **짝수** 쪽) |
| `pow(a, b)` | `Math.pow(2, 10)` | 1024.0 |
| `sqrt(x)` | `Math.sqrt(16)` | 4.0 |
| `random()` | `Math.random()` | 0.0 이상 1.0 **미만** |

### 반올림의 함정

```java
Math.round(1.5);    //  2
Math.round(-1.5);   // -1   (음수는 +쪽으로: floor(x + 0.5))
Math.round(2.5);    //  3
Math.rint(2.5);     //  2.0 (짝수 쪽)

// 소수점 둘째 자리에서 반올림
Math.round(3.14159 * 100) / 100.0;   // 3.14
```

### 오버플로우 감지: Exact 메서드 (Java 8+)

```java
int a = Integer.MAX_VALUE;
int b = a + 1;                  // -2147483648 (조용히 넘어감)
int c = Math.addExact(a, 1);    // ArithmeticException 발생 → 오버플로우를 알 수 있다
```

- `addExact`, `subtractExact`, `multiplyExact`, `toIntExact` 등.

### 실무 포인트

- **돈 계산에 double 을 쓰지 않는다.** `0.1 + 0.2 = 0.30000000000000004`. 반올림해도 오차가 쌓인다 → **BigDecimal** 사용.

## 래퍼(Wrapper) 클래스

**기본형 값을 객체로** 다뤄야 할 때 쓰는 클래스. 기본형마다 하나씩 있다.

| 기본형 | 래퍼 클래스 |
| --- | --- |
| `boolean` | `Boolean` |
| `char` | **`Character`** |
| `byte` | `Byte` |
| `short` | `Short` |
| `int` | **`Integer`** |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |

### 왜 필요한가

- **컬렉션**은 객체만 저장한다: `List<int>` X, `List<Integer>` O.
- 제네릭 타입 인자는 기본형을 쓸 수 없다.
- **null** 을 표현해야 할 때 (값이 없음).

### Number 클래스

숫자를 다루는 래퍼 클래스들의 **추상 조상**. `intValue()`, `longValue()`, `doubleValue()` 등으로 다른 기본형 값을 꺼낼 수 있다.

![The class hierarchy of Number](https://docs.oracle.com/javase/tutorial/figures/java/objects-numberHierarchy.gif)

*Number 의 자손: Byte, Short, Integer, Long, Float, Double (BigInteger, BigDecimal 도 Number 의 자손) (출처: Oracle, The Java Tutorials, The Numbers Classes)*

### 문자열 ↔ 숫자 변환

| 메서드 | 반환 | 예 |
| --- | --- | --- |
| `Integer.parseInt("100")` | **기본형** `int` | 100 |
| `Integer.valueOf("100")` | **래퍼** `Integer` | 100 |
| `Integer.toString(100)` / `String.valueOf(100)` | `String` | "100" |
| `Integer.parseInt("FF", 16)` | 진법 지정 | 255 |

- 숫자로 바꿀 수 없는 문자열이면 **NumberFormatException**.

### 오토박싱 & 언박싱 (Java 5+)

컴파일러가 기본형 ↔ 래퍼 클래스 변환을 **자동으로** 해 준다.

```java
Integer boxed = 10;               // 오토박싱: Integer.valueOf(10)
int     prim  = boxed;            // 언박싱:   boxed.intValue()

List<Integer> list = new ArrayList<>();
list.add(10);                     // 오토박싱
int n = list.get(0);              // 언박싱
```

### 실무 함정 1: `==` 비교와 Integer 캐시

```java
Integer a = 127, b = 127;
a == b;            // true   ← -128 ~ 127 은 미리 만들어 둔 객체를 재사용(캐시)
Integer c = 128, d = 128;
c == d;            // false  ← 캐시 범위 밖은 서로 다른 객체
c.equals(d);       // true
```

> 테스트 데이터가 작은 숫자일 때는 통과하다가 운영에서 큰 숫자로 터지는 대표적인 버그. **래퍼 클래스는 항상 `equals()`** 로 비교한다.

### 실무 함정 2: null 언박싱 → NPE

```java
Map<String, Integer> stock = new HashMap<>();
int count = stock.get("apple");          // 키가 없으면 null → 언박싱하다 NullPointerException

int count = stock.getOrDefault("apple", 0);   // 안전
```

- DB 에서 NULL 이 올 수 있는 컬럼(JPA 엔티티 필드, DTO)은 **래퍼 타입**으로 받는다. 기본형으로 받으면 null 을 담을 수 없다.

# 2. java.util 의 유용한 클래스

## java.util.Objects

Object 를 다룰 때 쓰는 **null 안전한 static 메서드** 모음 (Java 7+).

| 메서드 | 설명 |
| --- | --- |
| `Objects.equals(a, b)` | 둘 다 null 이면 true, 하나만 null 이면 false. NPE 없음 |
| `Objects.hash(a, b, ...)` | 여러 값으로 hashCode 생성 |
| `Objects.isNull(o)` / `nonNull(o)` | null 검사 (스트림 필터에 편함) |
| `Objects.requireNonNull(o, "msg")` | null 이면 **즉시 NPE**, 아니면 o 반환 |
| `Objects.requireNonNullElse(o, 기본값)` | null 이면 기본값 (Java 9+) |
| `Objects.toString(o, "기본값")` | null 이면 기본값 문자열 |
| `Objects.compare(a, b, comparator)` | Comparator 로 비교 |

### 실무 포인트

```java
// 1. 생성자·메서드 입구에서 null 막기 (문제를 늦게 발견하지 않도록)
public Order(Member member) {
    this.member = Objects.requireNonNull(member, "member 는 null 일 수 없습니다");
}

// 2. equals / hashCode 구현
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Point p)) return false;
    return x == p.x && Objects.equals(name, p.name);   // name 이 null 이어도 안전
}

@Override
public int hashCode() { return Objects.hash(x, name); }

// 3. 스트림에서 null 제거
list.stream().filter(Objects::nonNull).toList();
```

## java.util.Random

난수를 만드는 클래스. `Math.random()` 도 내부적으로 Random 을 쓴다.

```java
Random rand = new Random();
rand.nextInt(10);        // 0 ~ 9
rand.nextInt(1, 7);      // 1 ~ 6 주사위 (Java 17+)
rand.nextBoolean();
rand.nextDouble();       // 0.0 ~ 1.0 미만

// Math.random() 으로 1 ~ 6
int dice = (int) (Math.random() * 6) + 1;
```

### 종자값(seed)

```java
Random r1 = new Random(1);
Random r2 = new Random(1);
r1.nextInt() == r2.nextInt();   // true: 같은 seed 면 항상 같은 순서의 난수
```

- 테스트에서 **재현 가능한 난수**가 필요할 때 seed 를 고정한다.

### 실무 포인트: 용도에 맞는 난수

| 클래스 | 용도 |
| --- | --- |
| `Random` | 일반 용도, 테스트 데이터 |
| `ThreadLocalRandom.current()` | **멀티쓰레드** 환경 (Random 을 여러 쓰레드가 공유하면 경쟁으로 느려짐) |
| `SecureRandom` | **보안** 용도: 인증번호, 토큰, 비밀번호 생성 (예측 불가능) |

> Random 은 seed 를 알면 다음 값을 **예측할 수 있다.** 인증번호·토큰에는 반드시 `SecureRandom`.

## java.util.regex: 정규식

**정규식(Regular Expression)**: 텍스트에서 원하는 **패턴**을 찾거나 검증하는 규칙.

```java
import java.util.regex.*;

Pattern p = Pattern.compile("c[a-z]*");          // 1. 패턴 컴파일
Matcher m = p.matcher("cat");                     // 2. 대상 문자열과 매칭
boolean ok = m.matches();                         // 3. 전체가 패턴과 일치하는가 → true
```

### 자주 쓰는 패턴

| 패턴 | 의미 |
| --- | --- |
| `.` | 아무 문자 1개 |
| `*` / `+` / `?` | 0개 이상 / 1개 이상 / 0 또는 1개 |
| `{n}` / `{n,m}` | n번 / n~m번 |
| `[abc]` / `[^abc]` / `[a-z]` | a,b,c 중 하나 / 제외 / 범위 |
| `\d` / `\w` / `\s` | 숫자 / 영문·숫자·_ / 공백 |
| `^` / `$` | 시작 / 끝 |
| `( )` | 그룹 (나중에 `group(n)` 으로 꺼냄) |
| `a\|b` | a 또는 b |

> 자바 문자열 안에서는 `\` 를 두 번 쓴다: `"\\d+"`

### matches() vs find() 와 그룹

```java
// matches(): 문자열 전체가 일치해야 true
"010-1234-5678".matches("\\d{3}-\\d{4}-\\d{4}");   // true

// find() + group(): 문자열 안에서 일치하는 부분을 하나씩 찾기
Pattern p = Pattern.compile("(0\\d{1,2})-(\\d{3,4})-(\\d{4})");
Matcher m = p.matcher("집: 02-123-4567, 휴대폰: 010-1234-5678");

while (m.find()) {
    System.out.println(m.group());    // 02-123-4567 / 010-1234-5678
    System.out.println(m.group(1));   // 02 / 010  (첫 번째 괄호)
}
```

### String 의 정규식 메서드

| 메서드 | 예 |
| --- | --- |
| `matches(regex)` | `"abc123".matches("[a-z]+\\d+")` → true |
| `replaceAll(regex, 치환)` | `"a1b2".replaceAll("\\d", "")` → "ab" |
| `split(regex)` | `"a1b22c".split("\\d+")` → ["a", "b", "c"] |

### 실무 포인트

- `String.matches()`, `replaceAll()` 은 호출할 때마다 **패턴을 새로 컴파일**한다. 자주 쓰는 패턴은 **`static final Pattern`** 으로 한 번만 컴파일해 둔다.

```java
private static final Pattern PHONE = Pattern.compile("^01[016789]-\\d{3,4}-\\d{4}$");

boolean isValid(String phone) {
    return PHONE.matcher(phone).matches();
}
```

- 입력값 검증은 스프링에서 `@Pattern(regexp = "...")` (Bean Validation) 으로도 한다.

## java.util.Scanner

화면(콘솔), 파일, 문자열에서 **입력을 읽고 원하는 타입으로 변환**한다.

```java
Scanner sc = new Scanner(System.in);
int age = sc.nextInt();          // 정수
String name = sc.next();         // 공백 전까지 단어
String line = sc.nextLine();     // 줄 전체

Scanner s2 = new Scanner("1 2 3");   // 문자열에서 읽기
while (s2.hasNextInt()) {
    System.out.println(s2.nextInt());
}
```

### 함정: nextInt() 다음 nextLine()

```java
int n = sc.nextInt();        // "10\n" 에서 10 만 읽고 줄바꿈(\n)은 남김
String s = sc.nextLine();    // 남아 있던 \n 을 읽어서 빈 문자열 ""
```

- 해결: `nextInt()` 뒤에 `sc.nextLine();` 을 한 번 호출해 줄바꿈을 버리거나, 모두 `nextLine()` 으로 읽고 `Integer.parseInt()` 로 변환한다.

### 실무 포인트 (코딩 테스트)

- Scanner 는 편하지만 **느리다.** 입력이 많은 문제는 `BufferedReader` 를 쓴다.

```java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
int n = Integer.parseInt(br.readLine());
```

## java.util.StringTokenizer

문자열을 **구분자(delimiter)** 기준으로 여러 토큰으로 자른다.

```java
StringTokenizer st = new StringTokenizer("100,200,300", ",");
while (st.hasMoreTokens()) {
    System.out.println(st.nextToken());   // 100 / 200 / 300
}

// 구분자를 여러 개 지정: 각 문자가 하나의 구분자
new StringTokenizer("x=100*(200+300)", "+-*/=()");
```

### split() vs StringTokenizer

| 구분 | `String.split()` | `StringTokenizer` |
| --- | --- | --- |
| 구분자 | **정규식** | 문자 (여러 문자 = 각각 구분자) |
| 빈 토큰 | **포함**: `"a,,b".split(",")` → ["a", "", "b"] | **무시**: a, b |
| 결과 | 배열 | 하나씩 꺼냄 |
| 상태 | 일반적으로 권장 | **레거시** (호환성 때문에 남아 있음) |

- 실무 코드는 `split()` 을 쓴다. 코딩 테스트에서는 `BufferedReader` + `StringTokenizer` 조합이 빨라서 자주 쓴다.

```java
StringTokenizer st = new StringTokenizer(br.readLine());   // 공백 기준
int a = Integer.parseInt(st.nextToken());
int b = Integer.parseInt(st.nextToken());
```

# 3. java.math

## BigInteger

`long` 범위(약 ±922경, 19자리)를 넘는 **아주 큰 정수**를 다룬다.

```java
BigInteger a = new BigInteger("123456789012345678901234567890");   // 문자열로 생성
BigInteger b = BigInteger.valueOf(Long.MAX_VALUE);                  // long 으로 생성

BigInteger sum = a.add(b);           // 덧셈
a.subtract(b);  a.multiply(b);  a.divide(b);  a.remainder(b);
a.pow(10);
a.compareTo(b);                      // -1, 0, 1
```

- **불변(immutable)**이다. 연산 결과는 **새 객체**로 반환되므로 반드시 받아야 한다.

```java
a.add(b);           // 결과를 버림 → a 는 그대로
a = a.add(b);       // OK
```

- `+`, `-`, `*` 연산자는 쓸 수 없고 **메서드**로만 계산한다.
- 상수: `BigInteger.ZERO`, `ONE`, `TEN`.
- 쓰임: 큰 수의 팩토리얼, 암호(RSA), 코딩 테스트의 큰 수 문제.

## BigDecimal

**오차 없이** 실수를 계산한다. 정수(BigInteger) + **소수점 위치(scale)** 로 값을 표현해서 2진수 변환 오차가 없다.

### 왜 필요한가

```java
System.out.println(0.1 + 0.2);                 // 0.30000000000000004 (double 은 2진수로 근사)

BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
System.out.println(a.add(b));                  // 0.3
```

> **돈, 이자율, 수량 계산은 반드시 BigDecimal.** DB 의 `DECIMAL`/`NUMERIC` 컬럼도 자바에서는 BigDecimal 로 매핑한다.

### 함정 1: 생성할 때 double 을 넣지 않는다

```java
new BigDecimal(0.1);           // 0.1000000000000000055511151231257827... (double 의 오차가 그대로 들어감)
new BigDecimal("0.1");         // 0.1  ✔
BigDecimal.valueOf(0.1);       // 0.1  ✔ (내부적으로 Double.toString 사용)
```

### 함정 2: 나눗셈은 반올림 방식을 지정한다

```java
BigDecimal ten   = new BigDecimal("10");
BigDecimal three = new BigDecimal("3");

ten.divide(three);                                 // ArithmeticException: 3.333... 무한소수
ten.divide(three, 2, RoundingMode.HALF_UP);        // 3.33 (소수점 2자리, 반올림)
```

### 함정 3: equals() 는 scale 까지 비교한다

```java
new BigDecimal("2.0").equals(new BigDecimal("2.00"));       // false (scale 1 vs 2)
new BigDecimal("2.0").compareTo(new BigDecimal("2.00"));    // 0 (값이 같음)
```

> 값 비교는 **`compareTo() == 0`** 으로 한다.

### 반올림 · 자릿수

```java
BigDecimal price = new BigDecimal("1234.5678");
price.setScale(2, RoundingMode.HALF_UP);     // 1234.57
price.setScale(0, RoundingMode.DOWN);        // 1234
price.stripTrailingZeros();                  // 끝의 0 제거 (1.500 → 1.5)
price.toPlainString();                       // 지수 표기(1E+3) 없이 문자열
```

| RoundingMode | 의미 | 2.5 → | -2.5 → |
| --- | --- | --- | --- |
| `UP` | 0 에서 멀어지는 쪽 (올림) | 3 | -3 |
| `DOWN` | 0 쪽 (버림) | 2 | -2 |
| `CEILING` | +∞ 쪽 | 3 | -2 |
| `FLOOR` | -∞ 쪽 | 2 | -3 |
| **`HALF_UP`** | 반올림 (일반적인 사사오입) | 3 | -3 |
| `HALF_DOWN` | .5 는 버림 | 2 | -2 |
| **`HALF_EVEN`** | .5 면 짝수 쪽 (은행가 반올림, 오차 누적 최소) | 2 | -2 |

### 실무 예: 할인가 계산

```java
BigDecimal price    = new BigDecimal("19900");
BigDecimal discount = new BigDecimal("0.15");        // 15%

BigDecimal discounted = price
        .multiply(BigDecimal.ONE.subtract(discount))  // 19900 * 0.85 = 16915.00
        .setScale(0, RoundingMode.DOWN);              // 원 단위 절사 → 16915
```

- BigInteger 처럼 **불변**이라 결과를 꼭 받는다.
- 반올림 방식은 **회사·도메인 정책**으로 정한다 (원 단위 절사, 은행가 반올림 등). 코드 곳곳에서 다르게 쓰지 않도록 한 곳에 모은다.

# 핵심 정리

- `java.lang` 은 import 없이 사용. 모든 클래스의 조상은 **Object**.
- **equals 를 오버라이딩하면 hashCode 도** 함께. 안 하면 HashSet/HashMap 에서 중복이 생긴다. 실무에선 IDE·Lombok·record 로 생성.
- String 은 **불변**. 리터럴은 String Pool 에서 재사용, 비교는 항상 `equals()`, null 안전하게 `"상수".equals(변수)`.
- `split()`, `replaceAll()`, `matches()` 는 **정규식**을 받는다 (`.`, `|` 이스케이프).
- 반복문에서 문자열 누적은 **StringBuilder**. StringBuffer 는 동기화 버전. 둘 다 equals 미오버라이딩.
- `Math.round()` 는 long 반환, 음수 -1.5 → -1. 오버플로우 감지는 `addExact`.
- 래퍼 클래스: `==` 는 -128~127 캐시 때문에 **함정**, 항상 equals. null 언박싱은 **NPE**.
- `Objects.requireNonNull` 로 입구에서 null 차단, `Objects.equals`/`hash` 로 equals·hashCode 구현.
- 보안용 난수는 **SecureRandom**, 멀티쓰레드는 **ThreadLocalRandom**.
- 자주 쓰는 정규식은 `static final Pattern` 으로 한 번만 컴파일.
- Scanner `nextInt()` 뒤 `nextLine()` 함정. 코딩 테스트는 BufferedReader + StringTokenizer.
- 돈 계산은 **BigDecimal**: 생성은 문자열 또는 `valueOf`, 나눗셈은 RoundingMode 지정, 비교는 `compareTo`.
