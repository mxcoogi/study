

Java는 **Sun Microsystems에서 개발하여 1996년 공식 발표한 프로그래밍 언어**이다. 초기에는 객체지향 프로그래밍 언어로 설계되었으며, Java 8부터 람다 표현식과 Stream API 등이 도입되면서 함수형 프로그래밍 방식도 지원하게 되었다.

Java의 대표적인 특징은 **플랫폼 독립성(Platform Independence)**이다.

Java로 작성한 소스 코드는 특정 운영체제에서 직접 실행되는 기계어로 컴파일되는 것이 아니라 **바이트코드(Bytecode)**로 컴파일된다. 이 바이트코드는 JVM(Java Virtual Machine) 위에서 실행되기 때문에 JVM이 존재하는 환경이라면 동일한 Java 프로그램을 실행할 수 있다.

> **Write Once, Run Anywhere (WORA)**  
> 한 번 작성하면 여러 플랫폼에서 실행할 수 있다는 Java의 철학을 나타낸다.

이러한 특징 덕분에 Java는 기업용 서버 애플리케이션을 비롯하여 웹 백엔드, 모바일, 빅데이터, 분산 시스템 등 다양한 분야에서 사용되어 왔다.

Java 플랫폼은 대표적으로 **Java SE, Jakarta EE(과거 Java EE), Java ME** 등으로 구분할 수 있으며, 일반적으로 Java의 기본적인 언어와 표준 API를 이야기할 때는 **Java SE(Java Platform, Standard Edition)**를 의미한다.

# Java의 특징

## 1. 운영체제에 독립적이다

일반적인 네이티브 프로그램은 운영체제와 CPU 아키텍처에 맞는 기계어로 컴파일되기 때문에 실행 환경에 영향을 받는다.

Java는 소스 코드를 **JVM이 이해할 수 있는 바이트코드**로 컴파일한다.

```text
Java Source Code (.java)
        │
        │ javac
        ▼
Java Bytecode (.class)
        │
        ▼
       JVM
        │
        ├── Windows JVM
        ├── Linux JVM
        └── macOS JVM
        │
        ▼
 Operating System / Hardware
```

따라서 **Java 프로그램 자체는 특정 운영체제에 종속되지 않는다.**

반면 JVM은 실제 운영체제 및 하드웨어와 상호작용해야 하기 때문에 플랫폼에 종속적이다.

그래서 Windows, Linux, macOS 등 각각의 환경에 맞는 JVM 구현이 제공된다.

즉,

> Java 프로그램의 플랫폼 차이를 JVM이 중간에서 처리한다.

이 구조 덕분에 동일한 Java 바이트코드를 여러 운영체제에서 실행할 수 있다.

---

## 2. 객체지향 언어이면서 함수형 프로그래밍을 지원한다

Java는 대표적인 **객체지향 프로그래밍(Object-Oriented Programming, OOP) 언어**이다.

객체지향의 주요 특징인 다음 개념들을 지원한다.

- 캡슐화(Encapsulation)
    
- 상속(Inheritance)
    
- 다형성(Polymorphism)
    
- 추상화(Abstraction)
    

Java 8부터는 **람다 표현식(Lambda Expression)**, **함수형 인터페이스(Functional Interface)**, **Stream API** 등이 추가되면서 함수형 스타일의 프로그래밍도 적극적으로 활용할 수 있게 되었다.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

numbers.stream()
        .filter(n -> n % 2 == 0)
        .forEach(System.out::println);
```

따라서 현대 Java에서는 객체지향 프로그래밍을 기본으로 하면서 필요한 경우 함수형 프로그래밍의 장점을 함께 활용할 수 있다.

---

## 3. 비교적 배우기 쉬운 언어를 목표로 설계되었다

Java의 문법은 C/C++의 영향을 많이 받았기 때문에 C 계열 언어를 경험했다면 비교적 익숙하게 느낄 수 있다.

또한 C++의 복잡한 기능 중 일부를 제거하거나 단순화했다.

대표적으로 개발자가 직접 메모리를 해제하는 방식 대신 **Garbage Collector를 통한 자동 메모리 관리**를 제공한다.

Java는 이러한 설계를 통해 개발자가 복잡한 저수준 메모리 관리보다 애플리케이션의 비즈니스 로직과 객체 설계에 집중할 수 있도록 한다.

---

## 4. 자동 메모리 관리를 지원한다

Java 프로그램은 JVM 위에서 실행되며, JVM은 **Garbage Collector(GC)**를 이용하여 메모리를 관리한다.

프로그램에서 객체를 생성하면 일반적으로 Heap 영역에 객체가 할당된다.

```java
User user = new User();
```

이후 해당 객체가 더 이상 사용되지 않고 접근할 수 없는 상태가 되면 Garbage Collector가 이를 판단하여 메모리 회수 대상으로 처리한다.

```text
Application
     │
     ▼
    JVM
     │
     ▼
    Heap
 ┌───────────┐
 │ Object A  │ ← 사용 중
 │ Object B  │ ← 사용 중
 │ Object C  │ ← 접근 불가능
 └───────────┘
                  │
                  ▼
           Garbage Collector
                  │
                  ▼
            메모리 회수
```

따라서 C/C++처럼 개발자가 `free()`나 `delete`를 사용하여 객체의 메모리를 직접 해제할 필요가 없다.

다만 **Java에서 메모리 관리를 전혀 신경 쓰지 않아도 된다는 의미는 아니다.**

불필요한 객체를 계속 참조하고 있다면 GC가 해당 객체를 회수할 수 없기 때문에 Java에서도 메모리 누수와 같은 문제가 발생할 수 있다.

---

## 5. 네트워크 및 분산 환경을 위한 다양한 기능을 제공한다

Java는 초기부터 네트워크 환경을 고려하여 설계되었으며 네트워크 프로그래밍을 위한 다양한 표준 API를 제공한다.

예를 들어 다음과 같은 기능을 사용할 수 있다.

```text
java.net
 ├── Socket
 ├── ServerSocket
 ├── URI
 ├── URL
 └── HttpClient
```

이를 활용하면 TCP/IP 통신, HTTP 통신 등의 네트워크 프로그램을 구현할 수 있다.

현대의 Java 서버 개발에서는 이러한 기반 위에서 Spring과 같은 프레임워크를 사용하여 웹 애플리케이션과 분산 시스템을 구축하는 경우가 많다.

---

## 6. 멀티스레드 프로그래밍을 지원한다

Java는 언어와 표준 라이브러리 차원에서 **멀티스레드(Multi-threading)** 프로그래밍을 지원한다.

기본적인 `Thread`뿐만 아니라 다양한 동시성 관련 API를 제공한다.

```java
Thread thread = new Thread(() -> {
    System.out.println("Hello Thread");
});

thread.start();
```

또한 `java.util.concurrent` 패키지를 통해 보다 높은 수준의 동시성 프로그래밍을 지원한다.

```text
java.util.concurrent
 ├── ExecutorService
 ├── CompletableFuture
 ├── ConcurrentHashMap
 ├── BlockingQueue
 └── Semaphore
```

Java 코드에서는 운영체제별 스레드 구현 방식을 직접 처리할 필요 없이 JVM과 Java API를 통해 멀티스레드 프로그램을 작성할 수 있다.

다만 실제 스레드 스케줄링은 JVM뿐만 아니라 **운영체제의 스케줄러와 JVM 구현의 영향을 함께 받는다.**

---

## 7. 동적 로딩을 지원한다

Java 애플리케이션은 일반적으로 여러 개의 클래스로 구성된다.

```text
Application
 ├── User.class
 ├── Order.class
 ├── Payment.class
 └── Product.class
```

JVM은 **Class Loader**를 이용하여 필요한 클래스를 런타임에 JVM으로 로딩한다.

```text
.class
  │
  ▼
Class Loader
  │
  ▼
 JVM Memory
  │
  ▼
Execution
```

모든 클래스를 프로그램 시작과 동시에 무조건 로딩하는 것이 아니라 필요한 시점에 클래스를 로딩할 수 있다.

Java의 이러한 동적 클래스 로딩 기능은 프레임워크, 라이브러리, 플러그인 구조 등에서도 활용된다.

Spring Framework 역시 클래스 로딩, 리플렉션(Reflection) 등의 Java 기능을 적극적으로 활용한다.

# 정리

Java의 주요 특징을 정리하면 다음과 같다.

|특징|설명|
|---|---|
|플랫폼 독립성|바이트코드와 JVM을 통해 다양한 운영체제에서 실행할 수 있다.|
|객체지향|캡슐화, 상속, 다형성, 추상화를 지원한다.|
|함수형 프로그래밍|Java 8부터 Lambda, Stream API 등을 지원한다.|
|자동 메모리 관리|Garbage Collector가 사용하지 않는 객체의 메모리를 관리한다.|
|네트워크 지원|네트워크 프로그래밍을 위한 다양한 표준 API를 제공한다.|
|멀티스레드|Thread 및 `java.util.concurrent` 등의 동시성 API를 제공한다.|
|동적 로딩|Class Loader를 통해 런타임에 클래스를 로딩할 수 있다.|

Java의 핵심적인 실행 구조는 다음과 같이 요약할 수 있다.

```text
.java
 │
 │ javac
 ▼
.class (Bytecode)
 │
 ▼
JVM
 │
 ├── Class Loader
 ├── Runtime Memory
 ├── Execution Engine
 └── Garbage Collector
 │
 ▼
OS / Hardware
```

결국 Java를 제대로 이해하려면 단순히 문법만 공부하는 것보다 **`Java Source → Bytecode → JVM → OS`로 이어지는 실행 구조를 이해하는 것이 중요하다.**
