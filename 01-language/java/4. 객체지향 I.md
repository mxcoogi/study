## 개요

**객체지향 언어**는 "실제 세계는 **사물(객체)**로 이루어져 있고, 모든 사건은 사물 간의 **상호작용**이다"라는 생각에서 출발한다.

실제 사물의 **속성**과 **기능**을 분석해 **데이터(변수)**와 **함수(메서드)**로 정의하고, 실제 세계를 컴퓨터 속 가상 세계로 옮겨 놓는다.

- 객체지향 언어는 완전히 새로운 언어가 아니다. 기존 프로그래밍 언어에 **몇 가지 규칙을 추가한 발전된 형태**이다.
- 이 규칙들로 코드 간에 관계를 맺어 주어 프로그램을 **유기적으로** 구성할 수 있다.

---

## 객체지향 언어의 특징

| 특징 | 설명 |
| --- | --- |
| **코드의 재사용성이 높다** | 새 코드를 작성할 때 기존 코드를 이용해 쉽게 작성할 수 있다 (상속) |
| **코드의 관리가 쉽다** | 코드 간의 관계를 이용해 적은 노력으로 쉽게 변경할 수 있다 |
| **신뢰성이 높다** | 제어자와 메서드로 데이터를 보호하고 올바른 값을 유지한다 (캡슐화). 중복 코드를 줄여 불일치로 인한 오류를 막는다 |

### 객체지향의 4대 특징

| 개념 | 한 줄 설명 | 자세히 |
| --- | --- | --- |
| **캡슐화** | 데이터를 숨기고 메서드를 통해서만 접근하게 한다 | 객체지향 II · 제어자 |
| **상속** | 기존 클래스를 재사용해 새 클래스를 만든다 | 객체지향 II · 상속 |
| **추상화** | 공통 속성과 기능만 뽑아 정의한다 | 객체지향 II · 추상클래스, 인터페이스 |
| **다형성** | 하나의 참조 변수로 여러 타입의 객체를 다룬다 | 객체지향 II · 다형성 |

![A hierarchy of bicycle classes](https://docs.oracle.com/javase/tutorial/figures/java/concepts-bikeHierarchy.gif)

*상속 예: Bicycle 의 공통 속성·기능을 MountainBike, RoadBike, TandemBike 가 물려받고 각자 필요한 것만 추가한다 (출처: Oracle, The Java Tutorials, What Is Inheritance?)*

## 클래스와 객체

| 구분 | 정의 | 용도 | 비유 |
| --- | --- | --- | --- |
| **클래스** | 객체를 **정의해 놓은 것** | 객체를 **생성**하는 데 사용 | 제품 설계도 (TV 설계도) |
| **객체** | **실제로 존재하는 것** (사물 또는 개념) | 가지고 있는 속성과 기능에 따라 다름 | 제품 (실제 TV) |

- **유형의 객체**: 책상, 의자, 자동차, TV
- **무형의 객체**: 수학 공식, 프로그램 에러 같은 논리적인 개념

### 객체와 인스턴스

- 클래스로부터 객체를 만드는 과정을 **인스턴스화(instantiate)**라고 한다.
- 어떤 클래스로부터 만들어진 객체를 그 클래스의 **인스턴스(instance)**라고 한다.

```text
         인스턴스화
클래스  ────────────▶  인스턴스(객체)
(Tv)                  (실제 Tv 하나)
```

> 객체와 인스턴스는 거의 같은 뜻이다. "객체"는 넓은 의미, "인스턴스"는 **어떤 클래스로부터 만들어졌는지**를 강조할 때 쓴다. ("책상은 객체다" / "책상은 책상 클래스의 인스턴스다")

### 객체의 구성요소: 속성과 기능

객체가 가진 속성과 기능을 **멤버(member)**라고 한다.

| 구성요소 | 다른 이름 | 클래스에서는 | Tv 예 |
| --- | --- | --- | --- |
| **속성** (property) | 멤버 변수, 필드, 상태 | **변수** | 색상, 전원 상태, 채널 |
| **기능** (function) | 메서드, 행위 | **메서드** | 전원 켜기/끄기, 채널 올리기/내리기 |

| 일반적인 객체 | 자전거 객체 |
| --- | --- |
| ![A software object](https://docs.oracle.com/javase/tutorial/figures/java/concepts-object.gif) | ![A bicycle modeled as a software object](https://docs.oracle.com/javase/tutorial/figures/java/concepts-bicycleObject.gif) |
| 안쪽 = 상태(**필드**), 바깥 = 행동(**메서드**) | 상태: 속도 18mph, 페달 90rpm, 5단 기어 / 행동: 기어 변경, 브레이크, 페달 속도 변경 |

*출처: Oracle, The Java Tutorials, What Is an Object?*

- 필드가 안쪽에 있고 메서드가 바깥을 감싸는 모양 = 필드는 숨기고 **메서드를 통해서만** 상태를 바꾼다 (**캡슐화**).

```java
class Tv {
    // 속성 (멤버 변수)
    String  color;      // 색상
    boolean power;      // 전원 상태 (on/off)
    int     channel;    // 채널

    // 기능 (메서드)
    void power()       { power = !power; }   // 전원 on/off 전환
    void channelUp()   { ++channel; }
    void channelDown() { --channel; }
}
```

## 인스턴스의 생성과 사용

```java
클래스명 변수명;            // 클래스의 객체를 참조하기 위한 참조 변수 선언
변수명 = new 클래스명();    // 클래스의 객체를 생성하고, 그 주소를 참조 변수에 저장

Tv t = new Tv();          // 한 줄로
```

### 메모리에서 일어나는 일

```text
① Tv t;
   Tv 클래스 타입의 참조 변수 t 를 위한 공간이 생긴다.
   아직 인스턴스가 없으므로 t 로는 아무것도 할 수 없다.

   t ┌──────┐
     │ null │
     └──────┘

② t = new Tv();
   new 연산자가 메모리 빈 공간에 Tv 인스턴스를 만든다 (주소 0x100 이라고 가정).
   멤버 변수는 타입별 기본값으로 초기화된다.
   대입 연산자(=)가 인스턴스의 주소를 t 에 저장한다.

   t ┌───────┐        0x100 ┌──────────────────┐
     │ 0x100 │ ─────────▶   │ color   = null    │  (참조형 → null)
     └───────┘              │ power   = false   │  (boolean → false)
                            │ channel = 0       │  (int → 0)
                            └──────────────────┘

③ t.channel = 7;
   t 가 가리키는 인스턴스의 channel 에 7 을 저장한다.

④ t.channelDown();
   t 가 가리키는 인스턴스의 channelDown() 을 호출 → channel 은 6
```

![originOne now points to a Point object](https://docs.oracle.com/javase/tutorial/figures/java/objects-oneRef.gif)

*`Point originOne = new Point(23, 94);` 실행 후: 참조 변수 originOne 이 힙의 Point 객체를 가리킨다 (출처: Oracle, The Java Tutorials, Creating Objects)*

- **인스턴스는 참조 변수를 통해서만 다룰 수 있다.**
- 참조 변수의 타입은 인스턴스의 타입과 일치해야 한다. (단, 다형성에서는 **조상 타입**의 참조 변수도 가능 → 객체지향 II)

### 참조 변수가 둘일 때

```java
Tv t1 = new Tv();
Tv t2 = new Tv();
t2 = t1;            // t2 가 t1 과 같은 인스턴스를 가리킨다
t1.channel = 7;
System.out.println(t2.channel);   // 7
```

- 원래 t2 가 가리키던 인스턴스는 더 이상 참조하는 변수가 없어 **가비지 컬렉터(GC)**가 메모리에서 제거한다.
- 하나의 인스턴스를 **여러 참조 변수가 가리킬 수는 있지만**, 하나의 참조 변수가 여러 인스턴스를 동시에 가리킬 수는 없다.

![Multiple references to the same Point object](https://docs.oracle.com/javase/tutorial/figures/java/objects-multipleRefs.gif)

*참조 변수 originOne 과 Rectangle 객체 안의 참조 변수 origin 이 **같은 Point 객체**를 가리킨다. 한쪽에서 x 를 바꾸면 다른 쪽에서도 바뀐 값이 보인다 (출처: Oracle, The Java Tutorials, Creating Objects)*

## 객체 배열

많은 객체를 다룰 때는 배열로 묶는다.

- 객체 배열 안에는 객체가 아니라 **객체의 주소**가 저장된다.
- 즉, 객체 배열은 **참조 변수들을 하나로 묶은 참조 변수 배열**이다.

```java
Tv tv1, tv2, tv3;            // 참조 변수 3개
Tv[] tvArr = new Tv[3];      // 참조 변수 3개를 배열로 묶음
```

```text
tvArr ──▶ ┌──────┬──────┬──────┐
          │ null │ null │ null │     ← 배열만 만든 상태: 요소는 참조형 기본값 null
          └──────┴──────┴──────┘
```

- **배열만 생성했다고 객체가 생기지 않는다.** 각 요소에 객체를 따로 생성해서 저장해야 한다.

```java
tvArr[0] = new Tv();
tvArr[1] = new Tv();
tvArr[2] = new Tv();

// 또는
Tv[] tvArr = { new Tv(), new Tv(), new Tv() };

// 객체가 많으면 for 문으로
for (int i = 0; i < tvArr.length; i++) {
    tvArr[i] = new Tv();
}
```

> 객체를 넣지 않고 `tvArr[0].channelUp()` 을 호출하면 **NullPointerException**.

## 클래스의 또 다른 정의

### 1. 클래스 = 데이터와 함수의 결합

```text
변수      하나의 데이터를 저장하는 공간
배열      같은 종류의 여러 데이터를 하나로 저장하는 공간
구조체    서로 관련된 여러 데이터를 종류에 관계없이 하나로 저장하는 공간
클래스    데이터와 함수의 결합 (구조체 + 함수)
```

### 2. 클래스 = 사용자 정의 타입

프로그래밍 언어가 제공하는 기본형 외에, 프로그래머가 **서로 관련된 변수들을 묶어 하나의 타입으로 새로 추가**하는 것을 **사용자 정의 타입**이라고 한다. 자바에서는 **클래스**가 사용자 정의 타입이다.

```java
// 시간 3개를 클래스 없이 표현하면: 시, 분, 초가 따로 놀아서 관리가 어렵다
int   hour1, hour2, hour3;
int   minute1, minute2, minute3;
float second1, second2, second3;

// Time 클래스로 묶으면
Time t1 = new Time();
Time[] times = new Time[3];
```

#### 제약 조건까지 넣기 (캡슐화의 시작)

```java
class Time {
    private int   hour;      // private: 외부에서 직접 변경 불가
    private int   minute;
    private float second;

    public void setHour(int h) {
        if (h < 0 || h > 23) return;   // 잘못된 값이면 저장하지 않고 종료
        hour = h;
    }

    public int getHour() { return hour; }
    // minute, second 도 같은 방식
}
```

- 변수를 `private` 으로 막고, **메서드로만** 값을 바꾸게 하면 `hour = 25` 같은 잘못된 값이 들어가지 않는다.

## 선언 위치에 따른 변수의 종류

```java
class MyClass {
    int iv;            // 인스턴스 변수
    static int cv;     // 클래스 변수 (static 변수, 공유 변수)

    void method() {
        int lv = 0;    // 지역 변수
    }
}
```

| 변수 | 선언 위치 | 생성 시기 | 메모리 | 특징 |
| --- | --- | --- | --- | --- |
| **클래스 변수** (cv) | 클래스 영역 + `static` | 클래스가 메모리에 올라갈 때 | Method Area | **모든 인스턴스가 공유**. 인스턴스 없이 `클래스명.변수` 로 사용 |
| **인스턴스 변수** (iv) | 클래스 영역 | 인스턴스가 생성될 때 | Heap | 인스턴스마다 **독립된 저장 공간**, 서로 다른 값 |
| **지역 변수** (lv) | 메서드, 생성자, 블록 안 | 변수 선언문이 실행될 때 | Call Stack | 메서드가 끝나면 **소멸**. 사용 전 직접 초기화 필수 |

### 클래스 변수 vs 인스턴스 변수

```java
class Card {
    String kind;          // 무늬: 카드마다 다름   → 인스턴스 변수
    int    number;        // 숫자: 카드마다 다름   → 인스턴스 변수
    static int width  = 100;   // 폭: 모든 카드가 같음 → 클래스 변수
    static int height = 250;   // 높이: 모든 카드가 같음 → 클래스 변수
}

Card c1 = new Card();
Card c2 = new Card();
c1.width = 50;                  // 공유 변수라 c2.width 도 50 이 된다
Card.width = 50;                // 클래스 변수는 이렇게 클래스명으로 쓰는 것이 권장
```

```text
Method Area                  Heap
┌─────────────────┐         c1 ──▶ ┌─────────────┐
│ Card.width  = 50│◀─ 공유 ─┐      │ kind, number│
│ Card.height=250 │         │      └─────────────┘
└─────────────────┘         │  c2 ──▶ ┌─────────────┐
                            └──────── │ kind, number│
                                      └─────────────┘
```

- 모든 인스턴스가 **공통된 값을 유지**해야 하는 속성 → 클래스 변수
- 인스턴스마다 **다른 값**을 가져야 하는 속성 → 인스턴스 변수

## 메서드

**메서드(method)**는 특정 작업을 수행하는 문장들을 하나로 묶은 것이다.

### 메서드를 사용하는 이유

| 이유 | 설명 |
| --- | --- |
| **높은 재사용성** | 한 번 만든 메서드는 여러 곳에서 호출할 수 있다 |
| **중복 코드 제거** | 반복되는 코드를 메서드로 묶어 한 곳만 고치면 된다 |
| **프로그램 구조화** | 큰 작업을 작은 메서드로 나눠 흐름을 한눈에 볼 수 있다 |

### 선언부와 구현부

```java
//  반환타입  메서드이름  (매개변수 선언)       ← 선언부 (메서드 헤더)
    int      add       (int a, int b) {
        int result = a + b;                   ← 구현부 (메서드 몸통)
        return result;
    }
```

- 반환값이 없으면 반환 타입에 **`void`**.
- 매개변수는 타입이 같아도 **각각 타입을 적어야** 한다. (`int a, b` X → `int a, int b` O)
- 메서드 안에서 선언한 변수(매개변수 포함)는 **지역 변수**다.

### 메서드 호출

```java
int result = add(3, 5);   // 인자(argument) 3, 5 가 매개변수(parameter) a, b 에 복사된다
```

- 인자의 **개수와 타입**이 매개변수와 일치해야 한다. (자동 형변환이 가능한 타입은 허용)
- 같은 클래스의 메서드끼리는 참조 변수 없이 이름으로 바로 호출한다.
- 다른 클래스의 메서드는 인스턴스를 만든 뒤 `참조변수.메서드()` 로 호출한다.

## return 문

`return` 은 현재 실행 중인 메서드를 **종료하고 호출한 메서드로 돌아간다.**

- 원칙적으로 **모든 메서드에는 return 문이 있어야** 한다.
- 반환 타입이 `void` 면 생략할 수 있다. **컴파일러가 메서드 끝에 `return;` 을 자동으로 추가**해 준다.
- 반환 타입이 `void` 가 아니면 **반드시 `return 값;`** 이 있어야 하고, 값의 타입은 반환 타입과 일치(또는 자동 형변환 가능)해야 한다.

```java
int max(int a, int b) {
    if (a > b)
        return a;
    // 에러: a <= b 일 때 return 문이 없다
}

int max(int a, int b) {
    if (a > b) return a;
    else       return b;      // 모든 경우에 return 이 있어야 한다
}
```

### 매개변수의 유효성 검사

메서드 구현부에서 가장 먼저 할 일은 **매개변수 값이 적절한지 확인**하는 것이다.

```java
float divide(int x, int y) {
    if (y == 0) {
        System.out.println("0으로 나눌 수 없습니다.");
        return 0;               // 작업을 하지 않고 메서드를 끝낸다
    }
    return x / (float) y;
}
```

## 메서드와 메모리

> JVM 메모리 구조와 호출 스택의 동작은 → [[2. JVM]]

- 메서드를 호출하면 **호출 스택(Call Stack)**에 그 메서드의 작업 공간이 생기고, 지역 변수와 매개변수가 여기에 저장된다.
- 메서드가 끝나면 작업 공간이 사라지므로 **지역 변수도 함께 소멸**한다.
- 아래의 매개변수 전달, 재귀 호출은 모두 이 동작을 바탕으로 한다.

## 기본형 매개변수 vs 참조형 매개변수

자바는 메서드를 호출할 때 **인자의 값을 복사**해서 넘긴다. 무엇이 복사되는지가 다르다.

| 매개변수 타입 | 복사되는 것 | 메서드 안에서 |
| --- | --- | --- |
| **기본형** | 실제 **값** | 값을 **읽기만** 할 수 있다 (read only) |
| **참조형** | 인스턴스의 **주소** | 같은 인스턴스를 가리키므로 값을 **읽고 바꿀 수 있다** (read & write) |

```java
class Data { int x; }

static void change(int x)  { x = 1000; }          // 기본형
static void change(Data d) { d.x = 1000; }        // 참조형

int  x = 10;
Data d = new Data();
d.x = 10;

change(x);   // x 는 여전히 10   (복사본만 바뀜)
change(d);   // d.x 는 1000      (같은 인스턴스를 바꿈)
```

```text
기본형                                참조형
main:   x = 10                       main:   d ──┐
change: x = 10 → 1000 (복사본)        change: d ──┴──▶ [ x = 10 → 1000 ]
→ main 의 x 는 그대로                  → 같은 인스턴스라 main 에서도 1000
```

---

## 참조형 반환 타입

반환 타입이 참조형이면 **인스턴스의 주소**를 반환한다.

```java
static Data copy(Data d) {
    Data tmp = new Data();     // 새 인스턴스 생성
    tmp.x = d.x;               // 값 복사
    return tmp;                // 새 인스턴스의 주소를 반환
}

Data d2 = copy(d);             // d 와 d2 는 서로 다른 인스턴스
```

## 재귀 호출 (Recursive Call)

메서드 안에서 **자기 자신을 다시 호출**하는 것이다. 반드시 **종료 조건**이 있어야 한다.

```java
static int factorial(int n) {
    if (n == 1) return 1;            // 종료 조건
    return n * factorial(n - 1);     // 자기 자신 호출
}

factorial(4);   // 4 * 3 * 2 * 1 = 24
```

- 종료 조건이 없으면 호출 스택이 계속 쌓여 **StackOverflowError** 가 난다.
- 반복문보다 느리고 메모리를 더 쓰지만, 코드가 간결해지는 경우(트리 탐색 등)에 사용한다.

## 클래스 메서드 vs 인스턴스 메서드

| 구분 | 선언 | 호출 | 사용하는 것 |
| --- | --- | --- | --- |
| **인스턴스 메서드** | `void method()` | 인스턴스 생성 후 `참조변수.메서드()` | **인스턴스 변수**를 사용하는 작업 |
| **클래스 메서드** (static) | `static void method()` | 인스턴스 없이 `클래스명.메서드()` | 인스턴스 변수를 쓰지 않는 작업 |

```java
class MyMath {
    long a, b;                                   // 인스턴스 변수

    long add()                   { return a + b; }   // 인스턴스 변수 사용 → 인스턴스 메서드
    static long add(long a, long b) { return a + b; } // 매개변수만 사용   → 클래스 메서드
}

MyMath.add(200L, 100L);      // 클래스 메서드: 객체 생성 없이 호출

MyMath mm = new MyMath();
mm.a = 200L; mm.b = 100L;
mm.add();                    // 인스턴스 메서드: 객체 생성 후 호출
```

### static 을 언제 붙이나

- 메서드가 **인스턴스 변수를 사용하지 않으면** `static` 을 붙이는 것을 고려한다. (호출이 더 빠르고 객체 생성이 필요 없다)
- 모든 인스턴스가 공통으로 써야 하는 변수에는 `static` 을 붙인다.
- 예: `Math.max()`, `Math.random()` 은 인스턴스 변수가 필요 없어 모두 static 이다.

### 멤버 간 참조와 호출 규칙

```java
class TestClass {
    int iv;
    static int cv;

    void instanceMethod() {
        System.out.println(iv);   // OK
        System.out.println(cv);   // OK
        staticMethod();           // OK
    }

    static void staticMethod() {
        System.out.println(cv);   // OK
        System.out.println(iv);   // 에러: 인스턴스 변수 사용 불가
        instanceMethod();         // 에러: 인스턴스 메서드 호출 불가
    }
}
```

- **static 메서드에서는 인스턴스 멤버를 바로 쓸 수 없다.**
- 이유: static 멤버는 **인스턴스가 없어도** 존재하지만, 인스턴스 멤버는 **인스턴스가 생성된 뒤에야** 존재하기 때문이다.
- static 메서드에서 인스턴스 멤버가 필요하면 객체를 직접 만들어 사용한다. (`new TestClass().iv`)

## 핵심 정리

- 클래스 = 설계도, 인스턴스 = 클래스로 만든 실제 객체. 객체의 멤버 = 변수(속성) + 메서드(기능).
- `new` 로 만든 인스턴스는 **참조 변수**를 통해서만 다룬다. 멤버 변수는 타입별 기본값으로 초기화된다.
- 객체 배열은 **참조 변수의 배열**. 배열 생성 후 각 요소에 객체를 따로 넣어야 한다.
- 클래스 변수(static)는 **모든 인스턴스가 공유**, 인스턴스 변수는 **인스턴스마다 따로**, 지역 변수는 **메서드가 끝나면 소멸**.
- 기본형 매개변수는 **값 복사**(원본 변경 X), 참조형 매개변수는 **주소 복사**(원본 변경 O).
- void 가 아닌 메서드는 **모든 경로에 return** 이 필요하다.
- static 메서드에서는 인스턴스 변수·인스턴스 메서드를 **바로 쓸 수 없다**.
- 다음으로 볼 것: 오버로딩, 가변인자, 생성자, `this`, 변수의 초기화
