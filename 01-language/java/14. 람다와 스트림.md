## 개요

Java 8 에서 추가된 **람다식**과 **스트림**은 자바에 **함수형 프로그래밍** 스타일을 가져왔다. "어떻게(how) 반복할지" 대신 "**무엇을(what) 할지**"를 코드로 쓴다.

"20살 이상 회원의 이름을 정렬해서 리스트로" 를 두 방식으로 쓰면:

```java
// 반복문: 어떻게 할지를 하나하나 적는다
List<String> names = new ArrayList<>();
for (Member m : members) {
    if (m.getAge() >= 20) {
        names.add(m.getName());
    }
}
Collections.sort(names);
```

```java
// 스트림 + 람다: 무엇을 할지만 적는다
List<String> names = members.stream()
        .filter(m -> m.getAge() >= 20)     // 20살 이상만
        .map(Member::getName)              // 이름만 뽑아서
        .sorted()                          // 정렬하고
        .toList();                         // 리스트로
```

| 파트 | 절 | 주제 |
| --- | --- | --- |
| **1. 람다** | 1 ~ 2 | 람다식이란, 작성 규칙 |
| | 3 ~ 4 | 함수형 인터페이스, `java.util.function` |
| | 5 ~ 6 | Function 합성 · Predicate 결합, 메서드 참조 |
| **2. 스트림** | 7 ~ 8 | 스트림이란, 스트림 만들기 |
| | 9 ~ 10 | 중간 연산, Optional |
| | 11 ~ 13 | 최종 연산, collect, Collector 구현 |
| | 14 | 스트림 변환 |

### 예제에서 쓰는 클래스

```java
// 람다 · 실무 예제
class Member {
    Long getId();  String getName();  int getAge();
}

// 스트림 그림 예제 (Oracle Java Magazine 기사와 같은 데이터)
class Transaction {
    int getId();  Type getType();  int getValue();  Currency getCurrency();  String getCity();
}
enum Type { GROCERY, ELECTRONICS, ... }
```

# Part 1. 람다식

## 1. 람다식이란?

**메서드를 하나의 식(expression)으로 표현**한 것이다. 이름이 없어서 **익명 함수(anonymous function)** 라고도 한다.

```java
// 메서드
int max(int a, int b) {
    return a > b ? a : b;
}

// 람다식
(a, b) -> a > b ? a : b
```

- 메서드를 **변수처럼** 다룰 수 있게 된다. 메서드의 **매개변수로 넘기거나**, **결과로 반환**할 수 있다.
- 사실 자바에서 메서드는 혼자 존재할 수 없다. 람다식은 **익명 클래스의 객체**와 같은 역할을 한다 (→ 3. 함수형 인터페이스).

```java
// 람다 이전: 익명 클래스
list.sort(new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
});

// 람다
list.sort((a, b) -> a.length() - b.length());
```

## 2. 람다식 작성하기

메서드에서 **이름과 반환 타입을 지우고**, 매개변수와 몸통 사이에 **`->`** 를 넣는다.

```text
반환타입 메서드이름(매개변수) { 문장들 }
                ↓
        (매개변수) -> { 문장들 }
```

### 줄여 쓰는 규칙

| 규칙 | 원래 | 줄인 형태 |
| --- | --- | --- |
| 반환값이 있으면 **식**으로 (`return`, `;` 생략) | `(a, b) -> { return a > b ? a : b; }` | `(a, b) -> a > b ? a : b` |
| 매개변수 **타입**은 추론되면 생략 | `(int a, int b) -> a + b` | `(a, b) -> a + b` |
| 매개변수가 **하나**면 괄호 생략 (타입이 없을 때만) | `(a) -> a * a` | `a -> a * a` |
| 문장이 **하나**면 중괄호 생략 (`;` 도 생략) | `(name) -> { System.out.println(name); }` | `name -> System.out.println(name)` |
| 매개변수가 **없으면** 빈 괄호 | | `() -> Math.random()` |

```java
(a, b) -> { return a + b; }    // OK
(a, b) -> return a + b;        // 에러: return 문은 중괄호 생략 불가
int a -> a * a                 // 에러: 타입을 쓰면 괄호 필수 → (int a) -> a * a
(int a, b) -> a + b            // 에러: 일부만 타입 생략 불가
```

| 메서드 | 람다식 |
| --- | --- |
| `int max(int a, int b) { return a > b ? a : b; }` | `(a, b) -> a > b ? a : b` |
| `void printVal(String name, int i) { System.out.println(name + "=" + i); }` | `(name, i) -> System.out.println(name + "=" + i)` |
| `int square(int x) { return x * x; }` | `x -> x * x` |
| `int roll() { return (int)(Math.random() * 6); }` | `() -> (int)(Math.random() * 6)` |

> 💡 **실무 꿀팁**: 람다는 **한두 줄**일 때 읽기 좋다. 중괄호 안이 길어지면 **private 메서드로 빼고 메서드 참조**로 넘긴다: `.filter(this::isActiveVip)`. 스택 트레이스에도 메서드 이름이 남아서 디버깅이 쉬워진다.

## 3. 함수형 인터페이스

람다식을 담는 **참조 변수의 타입**은 무엇일까? 람다식은 사실 **익명 객체**이므로, 그 객체가 구현할 **인터페이스**가 필요하다.

```java
@FunctionalInterface
interface MyFunction {
    int max(int a, int b);      // 추상 메서드는 딱 하나
}

MyFunction f = (a, b) -> a > b ? a : b;   // 람다식 = MyFunction 을 구현한 익명 객체
int big = f.max(5, 3);                    // 5
```

- **추상 메서드가 딱 하나**인 인터페이스를 **함수형 인터페이스**라고 한다. 람다식과 1:1 로 연결될 수 있다.
- `@FunctionalInterface` 를 붙이면 추상 메서드가 하나인지 **컴파일러가 검사**한다.
- default 메서드, static 메서드는 개수에 포함되지 않는다.

### 매개변수와 반환 타입으로 쓰기

```java
void run(MyFunction f) {          // 매개변수가 함수형 인터페이스 → 람다식을 넘길 수 있다
    System.out.println(f.max(3, 7));
}
run((a, b) -> a > b ? a : b);

MyFunction getMax() {             // 반환 타입이 함수형 인터페이스 → 람다식을 반환할 수 있다
    return (a, b) -> a > b ? a : b;
}
```

> 메서드를 매개변수로 넘기고 반환하는 것처럼 보이지만, 실제로는 **람다식(객체)의 주소**를 주고받는다.

### 외부 변수 참조

```java
int base = 10;
Function<Integer, Integer> add = x -> x + base;   // OK
base = 20;                                         // 에러: 람다에서 쓴 지역 변수는 바꿀 수 없다
```

- 람다식 안에서 쓰는 **지역 변수**는 `final` 이거나 **effectively final**(한 번도 바뀌지 않는) 이어야 한다. (익명 클래스와 같은 규칙, → [[05. 객체지향 II]] 내부 클래스)
- 멤버 변수(인스턴스·static 변수)는 바꿀 수 있다.

### 람다식 안의 this

| 구분 | 익명 클래스 안의 `this` | 람다식 안의 `this` |
| --- | --- | --- |
| 가리키는 것 | **익명 클래스 객체 자신** | 람다를 **감싼 클래스**의 객체 |

## 4. java.util.function 패키지

자주 쓰는 함수형 인터페이스를 **미리 정의**해 둔 패키지. 직접 만들지 말고 이것을 쓴다.

| 인터페이스 | 메서드 | 입력 → 출력 | 용도 |
| --- | --- | --- | --- |
| `Runnable` (java.lang) | `void run()` | 없음 → 없음 | 실행만 |
| **`Supplier<T>`** | `T get()` | 없음 → T | **공급**: 값을 만들어 준다 |
| **`Consumer<T>`** | `void accept(T t)` | T → 없음 | **소비**: 값을 받아 쓰기만 |
| **`Function<T, R>`** | `R apply(T t)` | T → R | **변환** |
| **`Predicate<T>`** | `boolean test(T t)` | T → boolean | **조건** 검사 |
| `UnaryOperator<T>` | `T apply(T t)` | T → T | 같은 타입으로 변환 (Function 의 자손) |
| `BinaryOperator<T>` | `T apply(T a, T b)` | (T, T) → T | 두 값을 하나로 합치기 (BiFunction 의 자손) |
| `BiConsumer<T, U>` | `void accept(T t, U u)` | (T, U) → 없음 | |
| `BiPredicate<T, U>` | `boolean test(T t, U u)` | (T, U) → boolean | |
| `BiFunction<T, U, R>` | `R apply(T t, U u)` | (T, U) → R | |

```java
Supplier<Integer>         dice   = () -> (int)(Math.random() * 6) + 1;
Consumer<String>          print  = s -> System.out.println(s);
Function<String, Integer> length = s -> s.length();
Predicate<String>         empty  = s -> s.isEmpty();
BinaryOperator<Integer>   sum    = (a, b) -> a + b;

dice.get();               // 1 ~ 6
print.accept("hello");
length.apply("java");     // 4
empty.test("");           // true
```

### 기본형 특화 인터페이스

래퍼 클래스를 쓰면 **오토박싱·언박싱 비용**이 생긴다. 기본형 전용 인터페이스를 쓰면 피할 수 있다.

| 인터페이스 | 메서드 | 설명 |
| --- | --- | --- |
| `IntSupplier` | `int getAsInt()` | |
| `IntConsumer` | `void accept(int)` | |
| `IntPredicate` | `boolean test(int)` | |
| `IntFunction<R>` | `R apply(int)` | int → R |
| `ToIntFunction<T>` | `int applyAsInt(T)` | T → int |
| `IntUnaryOperator` | `int applyAsInt(int)` | int → int |
| `IntBinaryOperator` | `int applyAsInt(int, int)` | |
| `IntToLongFunction` 등 | | int → long ... |

- Long, Double 버전도 있다 (`LongSupplier`, `ToDoubleFunction` ...).

### 컬렉션 프레임워크의 함수형 메서드

| 인터페이스 | 메서드 | 설명 |
| --- | --- | --- |
| Collection | `removeIf(Predicate)` | 조건에 맞는 요소 삭제 |
| List | `replaceAll(UnaryOperator)` | 모든 요소 변환 |
| Iterable | `forEach(Consumer)` | 모든 요소에 작업 |
| Map | `forEach(BiConsumer)` | 모든 키-값에 작업 |
| Map | `computeIfAbsent(key, Function)` | 키가 없으면 함수로 값 생성 |
| Map | `merge(key, value, BiFunction)` | 키가 있으면 기존 값과 합침 |

```java
list.removeIf(x -> x % 2 == 0);           // 짝수 삭제
list.replaceAll(x -> x * 10);              // 모두 10배
map.forEach((k, v) -> System.out.println(k + "=" + v));
```

## 5. Function 의 합성과 Predicate 의 결합

### Function 합성

| 메서드 | 의미 | 순서 |
| --- | --- | --- |
| `f.andThen(g)` | f 를 적용하고 **그다음** g | `g(f(x))` |
| `f.compose(g)` | g 를 **먼저** 적용하고 f | `f(g(x))` |
| `Function.identity()` | 받은 값을 그대로 반환 (`x -> x`) | |

```java
Function<String, Integer> parse  = s -> Integer.parseInt(s, 16);   // 16진수 문자열 → 정수
Function<Integer, String> binary = i -> Integer.toBinaryString(i);  // 정수 → 2진수 문자열

Function<String, String> hexToBin = parse.andThen(binary);
hexToBin.apply("FF");      // "11111111"

// 리스트를 Map 으로 바꿀 때 자주 쓴다
Map<Long, Member> byId = members.stream()
        .collect(Collectors.toMap(Member::getId, Function.identity()));
```

### Predicate 결합

| 메서드 | 의미 |
| --- | --- |
| `p.and(q)` | p **그리고** q (`&&`) |
| `p.or(q)` | p **또는** q (`\|\|`) |
| `p.negate()` | p 가 **아닌** (`!`) |
| `Predicate.isEqual(obj)` | obj 와 같은지 |
| `Predicate.not(p)` | p 의 반대 (Java 11+, 메서드 참조와 함께 쓰기 좋다) |

```java
Predicate<Integer> over100  = i -> i > 100;
Predicate<Integer> under200 = i -> i < 200;
Predicate<Integer> even     = i -> i % 2 == 0;

Predicate<Integer> all = over100.and(under200).or(even);   // (100 < i < 200) || 짝수
all.test(150);     // true

// 빈 문자열 제거
list.stream().filter(Predicate.not(String::isBlank)).toList();
```

> 💡 **실무 꿀팁**: 검색 조건처럼 **조건이 조합되는 로직**에서 Predicate 를 변수로 이름 붙여 두면 읽기 쉽다.
> ```java
> Predicate<Order> isPaid     = o -> o.getStatus() == PAID;
> Predicate<Order> isThisWeek = o -> o.getOrderedAt().isAfter(weekStart);
> orders.stream().filter(isPaid.and(isThisWeek))...
> ```

## 6. 메서드 참조

람다식이 **메서드 하나만 호출**할 때, `클래스명::메서드명` 으로 더 짧게 쓴다.

| 종류 | 람다식 | 메서드 참조 |
| --- | --- | --- |
| **static 메서드** | `s -> Integer.parseInt(s)` | `Integer::parseInt` |
| **임의 객체의 인스턴스 메서드** (첫 매개변수가 그 객체) | `s -> s.length()` | `String::length` |
| | `(a, b) -> a.equals(b)` | `String::equals` |
| **특정 객체의 인스턴스 메서드** | `x -> System.out.println(x)` | `System.out::println` |
| | `x -> this.isValid(x)` | `this::isValid` |
| **생성자** | `() -> new ArrayList<>()` | `ArrayList::new` |
| | `name -> new Member(name)` | `Member::new` |
| **배열 생성** | `n -> new int[n]` | `int[]::new` |

```java
Function<String, Integer> f1 = Integer::parseInt;
BiFunction<String, String, Boolean> f2 = String::equals;
Supplier<List<String>> f3 = ArrayList::new;
Function<Integer, int[]> f4 = int[]::new;

// 실무에서 가장 많이 보는 형태: 엔티티 → DTO 변환
List<MemberDto> dtos = members.stream()
        .map(MemberDto::from)          // static 팩토리 메서드 참조
        .toList();
```

# Part 2. 스트림

## 7. 스트림이란?

**데이터 소스(컬렉션, 배열, 파일 ...)를 추상화**해서, 어떤 소스든 **같은 방식으로** 다룰 수 있게 한 것이다.

- 전에는 List 는 Iterator, 배열은 for 문, 정렬은 `Collections.sort()` / `Arrays.sort()` 처럼 소스마다 다루는 방법이 달랐다.

![A stream pipeline: filter, sorted, map, collect](https://www.oracle.com/a/tech/img/streams-f1-2179048.jpg)

*스트림 파이프라인: 데이터 소스(transactions) → **중간 연산**(filter, sorted, map) → **최종 연산**(collect). 각 연산에 Predicate, Comparator, Function 같은 함수형 인터페이스를 넘긴다 (출처: Oracle, Java Magazine, "Processing Data with Java SE 8 Streams, Part 1")*

```java
List<Integer> transactionIds = transactions.stream()                    // 데이터 소스
        .filter(t -> t.getType() == Type.GROCERY)                       // 중간 연산
        .sorted(Comparator.comparing(Transaction::getValue).reversed()) // 중간 연산
        .map(Transaction::getId)                                        // 중간 연산
        .toList();                                                      // 최종 연산
```

### 스트림 연산 한눈에 보기

```text
데이터 소스  ─▶  중간 연산 (0개 이상)  ─▶  최종 연산 (딱 1개)  ─▶  결과
stream()        filter, map, sorted ...    collect, count ...     List, Map, 값
```

| 단계 | 반환 | 대표 연산 | 이 노트 |
| --- | --- | --- | --- |
| **생성** | 스트림 | `stream()`, `Stream.of()`, `Arrays.stream()`, `IntStream.range()` | 8절 |
| **중간 연산** | 스트림 (계속 이어 붙임) | `filter`, `map`, `flatMap`, `sorted`, `distinct`, `limit`, `skip`, `peek` | 9절 |
| **최종 연산** | 값 · 컬렉션 · void | `forEach`, `count`, `max`, `findFirst`, `anyMatch`, `reduce`, `toList`, `collect` | 11 ~ 12절 |

### 스트림의 특징

| 특징 | 설명 |
| --- | --- |
| **원본을 바꾸지 않는다** | 읽기만 하고, 결과는 새 컬렉션·값으로 돌려준다 |
| **일회용** | 최종 연산을 하면 닫힌다. 다시 쓰면 `IllegalStateException: stream has already been operated upon or closed` |
| **내부 반복** | 반복문을 메서드 안으로 숨겼다. `forEach(System.out::println)` |
| **지연 연산** | 중간 연산은 **최종 연산이 호출될 때까지 실행되지 않는다** |
| **병렬 처리** | `parallelStream()` 으로 쉽게 병렬화 (→ [[13. 스레드]] Fork/Join) |
| **기본형 스트림** | `IntStream`, `LongStream`, `DoubleStream`: 오토박싱 없이 `sum()`, `average()` 제공 |

```java
Stream<String> s = list.stream();
s.forEach(System.out::println);
s.count();                       // IllegalStateException: 이미 사용한 스트림
```

## 8. 스트림 만들기

| 소스 | 방법 |
| --- | --- |
| 컬렉션 | `list.stream()`, `set.parallelStream()` |
| 배열 | `Arrays.stream(arr)`, `Arrays.stream(arr, from, to)`, `Stream.of(arr)` |
| 값 나열 | `Stream.of("a", "b", "c")` |
| null 일 수도 있는 값 | `Stream.ofNullable(x)` (Java 9+, null 이면 빈 스트림) |
| 정수 범위 | `IntStream.range(1, 5)` → 1~4, `IntStream.rangeClosed(1, 5)` → 1~5 |
| 난수 | `new Random().ints(5, 1, 46)` → 1~45 사이 5개 |
| 반복 생성 | `Stream.iterate(0, n -> n + 2)` → 0, 2, 4 ... (무한) |
| 조건 있는 반복 | `Stream.iterate(1, n -> n <= 100, n -> n * 2)` (Java 9+, for 문 같은 형태) |
| 공급 함수 | `Stream.generate(() -> "x")` (무한) |
| 파일 | `Files.lines(path)`, `Files.list(dir)` |
| 문자열 | `"hello".chars()` (IntStream), `"a\nb".lines()` (줄 단위, Java 11+) |
| 빈 스트림 | `Stream.empty()` |
| 합치기 | `Stream.concat(s1, s2)` |

```java
Stream.iterate(0, n -> n + 2).limit(5).forEach(System.out::println);   // 0 2 4 6 8 (limit 이 없으면 무한)

try (Stream<String> lines = Files.lines(Path.of("app.log"))) {           // 파일 스트림은 닫아야 한다
    long errors = lines.filter(l -> l.contains("ERROR")).count();
}
```

> 💡 **실무 꿀팁**: `Files.lines()`, `Files.list()` 처럼 **I/O 자원을 여는 스트림**은 `try-with-resources` 로 닫는다. 컬렉션 스트림은 닫지 않아도 된다.

## 9. 스트림의 중간 연산

중간 연산은 **스트림을 반환**하므로 계속 이어 붙일 수 있다.

| 분류 | 연산 | 설명 | 예: `Stream.of(5, 1, 3, 1, 4)` 에 적용 |
| --- | --- | --- | --- |
| **거르기** | `filter(Predicate)` | 조건에 맞는 것만 | `filter(n -> n > 2)` → 5, 3, 4 |
| | `distinct()` | 중복 제거 (`equals` 기준) | → 5, 1, 3, 4 |
| **자르기** | `limit(n)` | 앞에서 n 개만 | `limit(2)` → 5, 1 |
| | `skip(n)` | 앞에서 n 개 건너뛰기 | `skip(2)` → 3, 1, 4 |
| | `takeWhile(p)` / `dropWhile(p)` | 조건이 참인 **동안** 가져오기 / 버리기 (Java 9+) | `takeWhile(n -> n > 2)` → 5 |
| **정렬** | `sorted()` / `sorted(Comparator)` | 정렬 | `sorted()` → 1, 1, 3, 4, 5 |
| **변환** | `map(Function)` | 요소를 **다른 값으로** 바꿈 | `map(n -> n * 10)` → 50, 10, 30, 10, 40 |
| | `mapToInt` / `mapToLong` / `mapToDouble` | 기본형 스트림으로 바꿈 | `mapToInt(Integer::intValue).sum()` → 14 |
| | `flatMap(Function)` | 요소 하나를 **스트림으로 바꾼 뒤 펼쳐서** 하나로 합침 | 아래 그림 참고 |
| **엿보기** | `peek(Consumer)` | 요소를 그대로 흘려보내며 **확인만** (디버깅용) | `peek(System.out::println)` |

### 단계별로 보기

![Step-by-step stream processing](https://www.oracle.com/a/tech/img/streams-f2-2179051.jpg)

*filter 로 GROCERY 만 남기고, sorted 로 금액 내림차순 정렬, map 으로 id 만 꺼내서, collect 로 리스트를 만든다. 각 단계마다 스트림의 타입이 바뀌는 것을 볼 수 있다 (출처: Oracle, Java Magazine, "Processing Data with Java SE 8 Streams, Part 1")*

### sorted 와 Comparator

```java
members.stream()
        .sorted(Comparator.comparing(Member::getAge)          // 나이 오름차순
                          .reversed()                         // → 내림차순
                          .thenComparing(Member::getName))    // 나이가 같으면 이름순
        .toList();
```

### map vs flatMap

![map vs flatMap](https://www.oracle.com/a/tech/img/streams-f2-2228346.jpg)

*단어를 글자로 나눌 때, `map(s -> s.split(""))` 는 `Stream<String[]>`(배열의 스트림)이 되어 원하는 결과가 아니다. **`flatMap(Arrays::stream)`** 은 각 배열을 스트림으로 바꾼 뒤 **하나로 펼쳐** `Stream<String>` 을 만든다 (출처: Oracle, Java Magazine, "Processing Data with Java SE 8 Streams, Part 2")*

```java
List<String> words = List.of("Java", "Magazine");

words.stream()
     .map(w -> w.split(""))             // Stream<String[]>  ← 배열이 요소
     .flatMap(Arrays::stream)           // Stream<String>    ← 펼침
     .distinct()
     .toList();                         // [J, a, v, M, g, z, i, n, e]

// 실무: 주문 목록 → 모든 주문 상품
List<OrderItem> allItems = orders.stream()
        .flatMap(order -> order.getItems().stream())
        .toList();
```

### 지연 연산 (Lazy Evaluation)

```java
Stream.of("a", "bb", "ccc", "dddd")
      .filter(s -> { System.out.println("filter " + s); return s.length() > 1; })
      .map(s -> { System.out.println("map " + s); return s.toUpperCase(); })
      .findFirst();
```

```text
filter a          ← 요소 하나씩 파이프라인 끝까지 흘려보낸다 (단계별로 전부 처리하지 않는다)
filter bb
map bb            ← 첫 결과를 찾았으니 여기서 끝. ccc, dddd 는 처리하지 않는다
```

- 중간 연산은 **최종 연산이 호출되어야** 실행되고, 요소를 **하나씩** 끝까지 보낸다.
- `findFirst()`, `limit()`, `anyMatch()` 처럼 일찍 끝낼 수 있는 연산은 **나머지를 처리하지 않는다** (short-circuit).

> 💡 **실무 꿀팁**: 최종 연산이 없으면 **아무것도 실행되지 않는다.** `list.stream().peek(this::save);` 는 저장하지 않는다. 또 스트림 안에서 외부 변수를 바꾸는 **부작용(side effect)** 은 피한다. 결과는 `collect`, `reduce` 로 받는다.

## 10. `Optional<T>` 와 `OptionalInt`

**값이 있을 수도, 없을 수도 있는** 결과를 감싸는 객체. **null 을 직접 다루지 않게** 해서 NPE 를 줄인다 (Java 8+).

![Optional containing a value vs empty Optional](https://www.oracle.com/a/tech/img/java8-optional-f2.gif)

*Optional 은 상자다. 값이 들어 있거나(왼쪽), 비어 있다(오른쪽) (출처: Oracle, Java Magazine, "Tired of Null Pointer Exceptions? Consider Using Java SE 8's Optional!")*

### 만들기

```java
Optional<String> a = Optional.of("value");      // null 이면 NPE
Optional<String> b = Optional.ofNullable(name); // null 이면 빈 Optional
Optional<String> c = Optional.empty();          // 빈 Optional
```

### 값 꺼내기

| 메서드 | 값이 없을 때 |
| --- | --- |
| `get()` | `NoSuchElementException` (**쓰지 않는다**) |
| `orElse(기본값)` | 기본값 |
| `orElseGet(Supplier)` | Supplier 로 **만든** 값 |
| `orElseThrow()` / `orElseThrow(Supplier)` | 예외 |
| `ifPresent(Consumer)` | 아무것도 안 함 |
| `ifPresentOrElse(Consumer, Runnable)` | Runnable 실행 (Java 9+) |
| `isPresent()` / `isEmpty()` | 있는지 / 없는지 (isEmpty 는 Java 11+) |
| `or(Supplier<Optional>)` | 다른 Optional (Java 9+) |
| `stream()` | 빈 스트림 (Java 9+) |

### 변환: map, flatMap, filter

```java
String city = Optional.ofNullable(member)
        .map(Member::getAddress)        // null 이 나오면 그 뒤는 건너뛰고 빈 Optional
        .map(Address::getCity)
        .orElse("미등록");
```

![Nested Optional](https://www.oracle.com/a/tech/img/java8-optional-f3.gif)

![map vs flatMap on Optional](https://www.oracle.com/a/tech/img/java8-optional-f4.gif)

*메서드가 이미 `Optional` 을 반환하면 `map` 은 **Optional 안에 Optional** 이 생긴다 (위). **`flatMap`** 을 쓰면 한 겹으로 펼쳐진다 (아래) (출처: Oracle, Java Magazine, "Tired of Null Pointer Exceptions? ...")*

```java
Optional<Computer> computer = ...;
computer.map(Computer::getSoundcard);       // Optional<Optional<Soundcard>>  ← getSoundcard() 가 Optional 반환
computer.flatMap(Computer::getSoundcard);   // Optional<Soundcard>
```

### OptionalInt, OptionalLong, OptionalDouble

기본형 스트림의 결과에 쓰인다. 꺼낼 때 `getAsInt()`, `orElse(0)`.

```java
OptionalInt max = IntStream.of(3, 7, 1).max();
max.getAsInt();                           // 7
IntStream.empty().max().orElse(0);        // 0

OptionalDouble avg = IntStream.of(1, 2).average();   // average 는 항상 OptionalDouble
```

> 💡 **실무 꿀팁: Optional 사용 규칙**
> - **반환 타입에만** 쓴다. "결과가 없을 수 있다"를 표현하는 용도다. 필드, 메서드 매개변수, 컬렉션 요소에는 쓰지 않는다 (빈 컬렉션이면 `List.of()` 를 반환).
> - `get()` 대신 **`orElseThrow()`**. 스프링 데이터 JPA 의 `findById()` 가 Optional 을 반환한다 (아래 코드).
> - **`orElse` vs `orElseGet` 함정**: `orElse(createDefault())` 는 값이 **있어도** `createDefault()` 를 **항상 실행**한다 (인자를 먼저 계산하니까). DB 조회나 객체 생성처럼 비싼 기본값은 **`orElseGet(() -> createDefault())`**.

```java
Member member = memberRepository.findById(id)
        .orElseThrow(() -> new MemberNotFoundException(id));
```

## 11. 스트림의 최종 연산

최종 연산은 스트림을 **소모해서 결과를 만든다.** 이후 스트림은 닫힌다.

| 분류 | 연산 | 반환 | 예: `Stream.of(5, 1, 3, 1, 4)` 에 적용 |
| --- | --- | --- | --- |
| **순회** | `forEach(Consumer)` | void | `forEach(System.out::println)` (병렬이면 순서 보장 X, `forEachOrdered` 는 보장) |
| **개수 · 최대 · 최소** | `count()` | long | → 5 |
| | `max(Comparator)` / `min(Comparator)` | Optional | `max(Integer::compare)` → Optional[5] |
| **찾기** | `findFirst()` / `findAny()` | Optional | `findFirst()` → Optional[5] (병렬에서는 findAny 가 빠름) |
| **조건 검사** | `anyMatch` / `allMatch` / `noneMatch` | boolean | `anyMatch(n -> n > 4)` → true, `allMatch(n -> n > 0)` → true |
| **줄이기** | `reduce(...)` | T / Optional | `reduce(0, Integer::sum)` → 14 |
| **모으기** | `toList()` | List | → [5, 1, 3, 1, 4] **변경 불가** (Java 16+) |
| | `toArray()` / `toArray(Integer[]::new)` | 배열 | |
| | `collect(Collector)` | R | 다음 절 |
| **기본형 스트림 전용** | `sum()`, `average()`, `summaryStatistics()` | int, OptionalDouble ... | `mapToInt(i -> i).average()` → OptionalDouble[2.8] |

### reduce

![filter, map, reduce](https://www.oracle.com/a/tech/img/streams-f1-2228345.jpg)

*filter → map → **reduce**: reduce 는 BinaryOperator 로 요소들을 하나의 값으로 합친다 (출처: Oracle, Java Magazine, "Processing Data with Java SE 8 Streams, Part 2")*

```java
int sum = Stream.of(1, 2, 3, 4)
        .reduce(0, (a, b) -> a + b);     // 초기값 0 → 0+1 → 1+2 → 3+3 → 6+4 = 10

Optional<Integer> max = Stream.of(1, 2, 3).reduce(Integer::max);   // 초기값이 없으면 Optional

long total = orders.stream()
        .mapToLong(Order::getPrice)
        .sum();                          // 합계는 reduce 보다 기본형 스트림의 sum() 이 간단
```

### toList() vs collect(Collectors.toList())

| 방법 | 결과 리스트 | null 요소 |
| --- | --- | --- |
| `stream.toList()` (Java 16+) | **변경 불가** | 허용 |
| `collect(Collectors.toList())` | 변경 가능 (보통 ArrayList, 명세상 보장 X) | 허용 |
| `collect(Collectors.toUnmodifiableList())` | 변경 불가 | **불가** |

> 💡 **실무 꿀팁**: 대부분은 `toList()` 로 충분하다. 결과에 `add()` 를 해야 한다면 `collect(Collectors.toCollection(ArrayList::new))` 처럼 **명시적으로** 가변 리스트를 만든다.

## 12. collect()

`collect()` 는 **Collector** 를 받아 요소를 수집한다. 자주 쓰는 Collector 는 **`Collectors`** 클래스에 static 메서드로 있다.

| 분류 | Collectors 메서드 |
| --- | --- |
| 컬렉션으로 | `toList()`, `toSet()`, `toMap()`, `toCollection(Supplier)`, `toUnmodifiableList()` |
| 통계 | `counting()`, `summingInt()`, `averagingInt()`, `summarizingInt()`, `maxBy()`, `minBy()` |
| 문자열 결합 | `joining()`, `joining(", ", "[", "]")` |
| 리듀싱 | `reducing()` |
| **그룹화 · 분할** | **`groupingBy()`**, **`partitioningBy()`** |
| 하위 Collector 와 조합 | `mapping()`, `filtering()` (9+), `flatMapping()` (9+), `collectingAndThen()`, `teeing()` (12+) |

### 컬렉션으로 모으기

```java
Set<String> names = members.stream().map(Member::getName).collect(Collectors.toSet());

Map<Long, String> idToName = members.stream()
        .collect(Collectors.toMap(Member::getId, Member::getName));

TreeSet<String> sorted = names.stream().collect(Collectors.toCollection(TreeSet::new));
```

> 💡 **실무 꿀팁: toMap 의 두 가지 함정**
> ```java
> // 1. 키가 중복되면 IllegalStateException: Duplicate key
> Map<String, Member> byName = members.stream()
>         .collect(Collectors.toMap(Member::getName, Function.identity(),
>                  (oldVal, newVal) -> newVal));           // 세 번째 인자로 충돌 시 처리 방법 지정
>
> // 2. 값이 null 이면 NullPointerException (HashMap.merge 를 쓰기 때문)
> ```

### 통계, 문자열 결합

```java
long count  = members.stream().collect(Collectors.counting());
double avg  = members.stream().collect(Collectors.averagingInt(Member::getAge));
IntSummaryStatistics stat = members.stream().collect(Collectors.summarizingInt(Member::getAge));
stat.getMax(); stat.getMin(); stat.getAverage(); stat.getSum(); stat.getCount();

String csv = members.stream().map(Member::getName).collect(Collectors.joining(", ", "[", "]"));
// [kim, lee, park]
```

![maxBy and minBy collectors](https://www.oracle.com/a/tech/img/streams-f3.jpg)

*`maxBy`, `minBy` 는 Comparator 를 받아 Collector 를 만든다 (출처: Oracle, Java Magazine, "Processing Data with Java SE 8 Streams, Part 2")*

### groupingBy: 그룹으로 묶기

![groupingBy](https://www.oracle.com/a/tech/img/streams-f4.jpg)

*분류 함수 `Transaction::getCurrency` 의 결과(USD, GBP, EUR)를 키로, 해당하는 거래 목록을 값으로 하는 Map 을 만든다 (출처: Oracle, Java Magazine, "Processing Data with Java SE 8 Streams, Part 2")*

```java
Map<Currency, List<Transaction>> byCurrency = transactions.stream()
        .collect(Collectors.groupingBy(Transaction::getCurrency));

// 하위 Collector 로 그룹마다 다른 결과 만들기
Map<Currency, Long> countByCurrency = transactions.stream()
        .collect(Collectors.groupingBy(Transaction::getCurrency, Collectors.counting()));

Map<Currency, Integer> sumByCurrency = transactions.stream()
        .collect(Collectors.groupingBy(Transaction::getCurrency,
                 Collectors.summingInt(Transaction::getValue)));

Map<Currency, List<Integer>> idsByCurrency = transactions.stream()
        .collect(Collectors.groupingBy(Transaction::getCurrency,
                 Collectors.mapping(Transaction::getId, Collectors.toList())));

// Map 종류 지정: 키 정렬이 필요하면 TreeMap
Map<Currency, List<Transaction>> sortedGroup = transactions.stream()
        .collect(Collectors.groupingBy(Transaction::getCurrency, TreeMap::new, Collectors.toList()));
```

### 다단계 그룹화

![Multilevel grouping](https://www.oracle.com/a/tech/img/streams-f5.jpg)

*도시별로 묶은 뒤, 각 도시 안에서 다시 통화별로 묶어 금액을 합친다 (2단계 Map) (출처: Oracle, Java Magazine, "Processing Data with Java SE 8 Streams, Part 2")*

```java
Map<String, Map<Currency, Integer>> cityCurrencySum = transactions.stream()
        .collect(Collectors.groupingBy(Transaction::getCity,
                 Collectors.groupingBy(Transaction::getCurrency,
                          Collectors.summingInt(Transaction::getValue))));
```

### partitioningBy: 둘로 나누기

```java
Map<Boolean, List<Member>> adultOrNot = members.stream()
        .collect(Collectors.partitioningBy(m -> m.getAge() >= 20));

adultOrNot.get(true);    // 성인
adultOrNot.get(false);   // 미성년
```

- `groupingBy` 의 특수한 경우. 결과 Map 에 **true, false 키가 항상 존재**한다 (해당 요소가 없어도 빈 리스트).

### collectingAndThen, teeing

```java
// 수집한 뒤 한 번 더 변환
List<String> unmodifiable = names.stream()
        .collect(Collectors.collectingAndThen(Collectors.toList(), Collections::unmodifiableList));

// 두 Collector 결과를 합치기 (Java 12+): 한 번 순회로 최소·최대 구하기
var range = scores.stream().collect(Collectors.teeing(
        Collectors.minBy(Integer::compare),
        Collectors.maxBy(Integer::compare),
        (min, max) -> new Range(min.orElse(0), max.orElse(0))));
```

## 13. Collector 구현하기

`Collector` 인터페이스를 직접 구현하면 나만의 수집 방법을 만들 수 있다.

```java
public interface Collector<T, A, R> {     // T: 요소, A: 중간 저장소, R: 결과
    Supplier<A>          supplier();       // 1. 중간 결과를 담을 저장소 생성      () -> new StringBuilder()
    BiConsumer<A, T>     accumulator();    // 2. 요소를 저장소에 하나씩 추가       (sb, s) -> sb.append(s)
    BinaryOperator<A>    combiner();       // 3. (병렬) 저장소 두 개를 합치기      (sb1, sb2) -> sb1.append(sb2)
    Function<A, R>       finisher();       // 4. 저장소를 최종 결과로 변환         sb -> sb.toString()
    Set<Characteristics> characteristics();// 5. 특성 (UNORDERED, CONCURRENT, IDENTITY_FINISH)
}
```

```java
class ConcatCollector implements Collector<String, StringBuilder, String> {
    @Override public Supplier<StringBuilder> supplier()        { return StringBuilder::new; }
    @Override public BiConsumer<StringBuilder, String> accumulator() { return StringBuilder::append; }
    @Override public BinaryOperator<StringBuilder> combiner()  { return StringBuilder::append; }
    @Override public Function<StringBuilder, String> finisher(){ return StringBuilder::toString; }
    @Override public Set<Characteristics> characteristics()    { return Collections.emptySet(); }
}

String s = Stream.of("a", "b", "c").collect(new ConcatCollector());   // "abc"

// 클래스를 만들지 않고 Collector.of 로
Collector<String, StringBuilder, String> concat = Collector.of(
        StringBuilder::new, StringBuilder::append, StringBuilder::append, StringBuilder::toString);
```

| 특성 | 의미 |
| --- | --- |
| `UNORDERED` | 순서를 유지할 필요가 없다 |
| `CONCURRENT` | 여러 스레드가 **하나의 저장소**에 동시에 추가해도 안전하다 |
| `IDENTITY_FINISH` | finisher 가 항등 함수 (A 가 곧 R) → finisher 를 생략 |

> 💡 **실무 꿀팁**: Collector 를 직접 구현할 일은 거의 없다. `groupingBy` + 하위 Collector 조합, `collectingAndThen`, `teeing` 으로 대부분 해결된다. 직접 만든다면 `Collector.of(...)` 가 간단하다.

## 14. 스트림의 변환

| from | to | 메서드 |
| --- | --- | --- |
| `Stream<T>` | `IntStream` | `mapToInt(ToIntFunction)` |
| `IntStream` | `Stream<Integer>` | `boxed()` |
| `IntStream` | `Stream<U>` | `mapToObj(IntFunction)` |
| `IntStream` | `LongStream`, `DoubleStream` | `asLongStream()`, `asDoubleStream()` |
| `String` | `IntStream` | `chars()` |
| `Stream<T>` | 배열 | `toArray(String[]::new)` |
| `IntStream` | `int[]` | `toArray()` |
| 배열 | 스트림 | `Arrays.stream(arr)`, `Stream.of(arr)` |
| `Collection` | 스트림 | `stream()`, `parallelStream()` |
| `Map` | 스트림 | `map.entrySet().stream()`, `keySet().stream()`, `values().stream()` |
| `Stream<Stream<T>>` / `Stream<T[]>` | `Stream<T>` | `flatMap(...)` |
| 스트림 | 컬렉션 | `toList()`, `collect(Collectors.toSet())`, `collect(Collectors.toMap(...))` |
| 스트림 | 병렬 / 순차 | `parallel()`, `sequential()` |
| `Optional<T>` | 스트림 | `stream()` (Java 9+) |

```java
// 문자열의 알파벳 개수 세기
long letters = "Hello, Java 21!".chars().filter(Character::isLetter).count();   // 9

// Map 을 값 기준으로 정렬해 상위 3개 키 뽑기
List<String> top3 = wordCount.entrySet().stream()
        .sorted(Map.Entry.<String, Long>comparingByValue().reversed())
        .limit(3)
        .map(Map.Entry::getKey)
        .toList();

// int[] → List<Integer>
List<Integer> list = Arrays.stream(new int[]{1, 2, 3}).boxed().toList();
```

## 람다와 스트림 실무 꿀팁 모음

### 1. 반복문과 스트림, 무엇을 쓸까

| 상황 | 추천 |
| --- | --- |
| 필터·변환·그룹화 (데이터 가공) | **스트림** (의도가 잘 드러난다) |
| 중간에 `break`, `continue`, 여러 변수를 함께 바꾸는 로직 | **for 문** |
| 인덱스가 필요한 로직 | for 문 (또는 `IntStream.range`) |
| 예외를 던지는 작업 (Checked 예외) | for 문이 편하다 (람다 안에서는 Checked 예외를 그대로 던질 수 없다) |

- 성능 차이는 대부분 의미 없다. **읽기 쉬운 쪽**을 고른다.

### 2. 람다 안의 Checked 예외

```java
paths.stream().map(p -> Files.readString(p))   // 컴파일 에러: IOException 처리 필요
```

```java
paths.stream().map(p -> {
    try {
        return Files.readString(p);
    } catch (IOException e) {
        throw new UncheckedIOException(e);       // Unchecked 로 감싸서 던진다 (→ [[06. 예외처리]])
    }
}).toList();
```

### 3. 디버깅

- `peek(x -> log.debug("after filter: {}", x))` 로 중간 값을 확인한다.
- IntelliJ 의 **Stream Trace**(디버거의 스트림 아이콘)로 단계별 값을 볼 수 있다.

### 4. 병렬 스트림은 신중하게

- `parallelStream()` 은 **공용 ForkJoinPool** 을 쓴다. 웹 서버의 요청 처리 코드, DB·API 호출이 섞인 작업에서는 쓰지 않는다 (→ [[13. 스레드]]).

### 5. 엔티티 → DTO 변환 패턴

```java
public record MemberResponse(Long id, String name) {
    public static MemberResponse from(Member m) {
        return new MemberResponse(m.getId(), m.getName());
    }
}

List<MemberResponse> body = memberRepository.findAll().stream()
        .map(MemberResponse::from)
        .toList();
```

# 핵심 정리

### 람다

- 람다식 = 메서드를 식으로 표현한 **익명 함수**. 실제로는 함수형 인터페이스를 구현한 **익명 객체**.
- 작성: 이름·반환 타입 제거, `->`. 식이면 `return`·`{}`·`;` 생략, 매개변수 하나면 `()` 생략.
- **함수형 인터페이스** = 추상 메서드 1개, `@FunctionalInterface`. 람다에서 쓰는 지역 변수는 **effectively final**.
- 표준: **Supplier**(공급), **Consumer**(소비), **Function**(변환), **Predicate**(조건), Operator(같은 타입). 기본형 특화로 박싱 회피.
- 합성: `andThen`, `compose`, `identity` / 결합: `and`, `or`, `negate`, `Predicate.not`.
- 메서드 참조: `Integer::parseInt`, `String::length`, `System.out::println`, `ArrayList::new`.

### 스트림

- 원본 불변, **일회용**, 내부 반복, **지연 연산**(최종 연산이 있어야 실행, 요소를 하나씩 끝까지).
- 중간 연산: `filter`, `map`, **`flatMap`**(펼치기), `sorted`, `distinct`, `limit`, `skip`, `peek`.
- **Optional**: 반환 타입에만, `get()` 대신 `orElseThrow()`, 비싼 기본값은 **`orElseGet`**, Optional 을 반환하는 메서드는 `flatMap`.
- 최종 연산: `forEach`, `count`, `max`, `findFirst`, `anyMatch`, `reduce`, **`toList()`(변경 불가)**, `collect`.
- Collectors: `toMap`(중복 키·null 값 주의), `joining`, `summarizingInt`, **`groupingBy`**(+ 하위 Collector, 다단계), `partitioningBy`, `teeing`.
- Collector = supplier, accumulator, combiner, finisher, characteristics. 보통은 `Collector.of`.
- 변환: `mapToInt`/`boxed`/`mapToObj`, `toArray(String[]::new)`, `chars()`, `entrySet().stream()`.
